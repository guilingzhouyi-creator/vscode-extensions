## 2. 核心执行模式 (Execution Modes)

引擎根据运行环境与调用参数自动选择最佳执行路径：

| 模式 | 触发条件 | 特性与优势 |
| :--- | :--- | :--- |
| **冷扫描 (Cold Scan)** | 首次运行 / 显式禁用缓存 | 扫描全部文件，不依赖历史缓存，输出基准结果。 |
| **热扫描 (Warm Scan)** | `cache: true` (默认) | 结合 L1/L2 缓存，仅解析修改文件，大幅压低重新扫描耗时。 |
| **Diff 增量扫描** | 调用 `scanDiff` / `scanDiffDelta` | 接收 Git Diff 或编辑器变更范围，行级增量复用子树。 |
| **Daemon 守护进程** | `--daemon` 或 IPC 连接 | 驻留内存进程与 Worker 池，避免 Node.js 进程冷启动开销。 |

---

## 3. 并发调度与 Worker 线程池

* **动态 Worker 分配**：默认根据 CPU 核心数分配并发 Worker（`concurrency` 参数，缺省为 `os.cpus().length`）。
* **任务批处理分发**：主进程按文件大小与数量切分 Batch 任务，通过 Node.js `worker_threads` 进行多核并行分析。
* **惰性装载保证**：Worker 线程内部对重型 Native Addons（如 `oxc-parser`、`tree-sitter`）采用**按需懒加载**，避免无效内存占用。

---

## 4. 内存自愈与稳定性保障 (RSS Self-Healing)

在大规模项目全量扫描时，静态分析容易造成 V8 堆内存碎片化膨胀。引擎内置自愈机制：

* **RSS 阈值探测**：主进程周期性检查内存常驻集大小（RSS）。
* **自动回收与驱逐**：当 RSS 超过安全阈值（默认 512MB）时，系统自动释放空闲 Worker 进程池与过期 AST 子树缓存，强制触发垃圾回收，保证长期运行不崩溃。
