# 行级增量子树复用机制 (Line-Level Incremental Analysis)

> **所属模块**：`03-incremental-and-diff`  
> **核心源码**：`src/core/incremental.ts`, `src/core/incrementalState.ts`, `src/core/lineMap.ts`, `src/core/editDiff.ts`  
> **文档状态**：✅ **已落地实施 (Implemented & Verified)**

---

## 1. 为什么需要行级增量？

对于 5,000+ 行以上的超大源文件，即使开发者只修改了其中 1 行代码：
* 全量重新解析与全量规则遍历依然需要花费数十毫秒；
* 绝大部分未修改的顶层函数、类方法的 AST 结构与静态质量分析结果与上一版本**完全一致**。

行级增量技术旨在识别文件内部的具体编辑区间，**仅重新分析被修改的函数子树，完全复用未变子树的分析结果**。

---

## 2. 核心架构与复用决策 (`reuseSubtree`)

```
   旧文件版本 (oldContent)                新文件版本 (newContent)
  ┌───────────────────────┐            ┌───────────────────────┐
  │ function A() { ... }  │ ─────────► │ function A() { ... }  │ ──► [复用旧子树 AST & 结果]
  ├───────────────────────┤            ├───────────────────────┤
  │ function B() { ... }  │ ── (修改) ─► │ function B() { +new } │ ──► [重新物化与深度分析]
  ├───────────────────────┤            ├───────────────────────┤
  │ function C() { ... }  │ ─────────► │ function C() { ... }  │ ──► [复用旧子树 AST & 结果]
  └───────────────────────┘            └───────────────────────┘
```

### 2.1 复用判定三要素
一个 AST 函数子树是否能够安全复用，必须同时满足：
1. **起始位置一致**：函数的 `startLine` 与 `startColumn` 严格相等；
2. **源码字节一致**：截取的源码切片 `sourceText` 与旧版本子树严格逐字节相同；
3. **独立性边界**：该子树不依赖外部被修改作用域的上下文。

---

## 3. 行号映射与偏移平移 (`LineMap`)

当编辑发生在文件上方时，下方函数的物理行号会发生向下平移。`LineMap` 负责维护行号位移映射矩阵：
* 精确计算每处编辑引入的 `lineDelta`；
* 对复用的 `Issue` 位置区间自动施加偏移修正，确保行号始终精确指向新版本的源码位置。
