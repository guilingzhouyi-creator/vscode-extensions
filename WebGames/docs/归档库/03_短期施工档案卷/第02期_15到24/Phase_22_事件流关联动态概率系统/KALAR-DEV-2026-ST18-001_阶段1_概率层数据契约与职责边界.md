## 二、 三位一体分层数据契约

| 层 | 职责（边界） | 禁止（反模式） |
| :--- | :--- | :--- |
| **事件系统（事件层）** | 事件定义/触发条件 AST/生命周期/执行逻辑（优先级仲裁/动作派发/结果记录）——确定性业务能力 | 不得把概率计算内嵌为事件执行的一部分（概率查询走概率层）；不得被概率层反向驱动触发判定 |
| **动态概率系统（概率层）** | 事件在**不同上下文/条件/状态**下的概率**计算**、**调整**（buff/debuff/环境修正）与**关联**（事件间概率联动）——可配置扩展 | **不得取代事件核心执行逻辑**（只返回概率值，不派发动作/不判定触发/不执行生命周期）；不得绕过事件定义读配置 |
| **事件发生描述系统（描述层，Phase 23）** | 根据**实际事件/上下文/结果**生成事件描述——可配置扩展 | **不得直接承担事件判定**（描述生成于事件发生之后，不参与触发决策） |

**概率层输出契约**（与事件层的唯一协作面）：

```
EventProbabilityResolver.resolve(event_id, world_context) -> { probability: float(0~1), modifiers: [...], adjusted_by: [...] }
```

- 事件层**查询**概率（触发决策可选引用），概率层**不调用**事件层执行——无循环依赖；
- 概率参数/条件组合/关联规则 100% 配置驱动（`config/domains/event_probability.json` 或事件域表），核心框架/数据契约由代码层保证；
- 配置**不得成为后门**：概率配置不得包含事件执行逻辑（动作派发/生命周期指令），不得绕过类型约束（概率值类型校验 0~1）。

**跨三位一体协作契约**：事件概率条件上下文可**只读引用**物品侧注册状态（如 `{item_owned}`/`{item_quality}`，经配置表键）——物品侧（Phase 21）与事件侧经名称注册表/配置上下文协作，无直接类依赖环。
