## 一、 实现设计（共享核心 + 域接入）

### 1.1 CopywritingResolver（共享文案解析核心，新类 @ 基础设施层）

```gdscript
class_name CopywritingResolver
extends RefCounted

## 未填充参数告警计数（遥测/审计只读）
static var missing_params_count: int = 0

## 统一文案解析：copy_key（<域>.<条目>.<字段>）→ 配置模板 → {param} 填充
## 三要素统一：conditions（状态条件段拼接）/ branches（结果分支，outcome 参数）/ 纯模板
static func resolve(
	copy_key: String,
	params: Dictionary = {},
	outcome: String = "",
	locale_override: String = ""
) -> Dictionary:
	# copy_key 前两段 = 表名（copywriting.<域>）与条目，末段 = 字段
	var parts := copy_key.split(".")
	if parts.size() < 3:
		return {"success": false, "code": "COPY_KEY_INVALID", "copy_key": copy_key}
	var table_name := "copywriting." + parts[0]
	var domain_entries: Dictionary = GameConfig.get_dict(table_name, parts[1], {})
	if domain_entries.is_empty():
		return {"success": false, "code": "COPY_ENTRY_MISSING", "copy_key": copy_key}

	var entry: Dictionary = domain_entries
	var template := _select_template(entry, params, outcome)
	if template.is_empty():
		return {"success": false, "code": "COPY_TEMPLATE_MISSING", "copy_key": copy_key}

	var missing := _missing_params(template, params)
	if not missing.is_empty():
		missing_params_count += missing.size()
		return {"success": false, "code": "MISSING_PARAMS", "copy_key": copy_key, "missing": missing}

	# 文案键登记名称注册表（跨域唯一；同域幂等）
	LocalizationRegistryCatalog.get_shared().register_name_key(copy_key, parts[0], copy_key)
	return {"success": true, "copy_key": copy_key, "text": _fill(template, params)}
```

- **三要素统一**（S1 契约落地）：
  - `conditions`：`params` 状态匹配 `when` → 拼接 `text` 段（物品描述既有结构统一）；
  - `branches`/按 outcome 键：`outcome` 匹配分支键（success/failure/partial…），缺省 `base` 兜底（事件描述既有结构统一）；
  - 纯模板：无条件/分支时直接填充（公告/概率文案）。
- **热重载**：每次 `GameConfig.get_dict` 实时读取（`GameConfig.reload()` 后最新文案零缓存生效）。

### 1.2 域解析器接入（消除同构重复）

| 解析器 | 接入动作 | 保留（红线/职责） |
| :--- | :--- | :--- |
| `ItemDescriptionResolver`（Phase 21） | 填充管线（`_param_regex`/`_missing_params`/`_fill`）改调 `CopywritingResolver.resolve` | `UNREGISTERED_ITEM` 身份校验 / 描述键登记 / 只读消费注册表 |
| `EventDescriptionResolver`（Phase 23） | 结果分支选择改调 `CopywritingResolver.resolve(outcome=...)` | 零判定时序 / 描述键登记 |
| 事件概率文案（Phase 22 扩展） | 统一出口 `probability.<事件>.result`（本卷提供解析能力） | 概率只算不执行（文案只描述结果，禁判定） |
| 公告/通知文案 | 统一出口 `bulletin.<键>`（本卷提供解析能力） | 纯展示文案（无逻辑键） |

- 旧填充管线（`_param_regex`/`_missing_params`/`_fill`）从两解析器移除，全部收敛至 `CopywritingResolver`（一处实现）。

### 1.3 配置布局（S3 迁移的解析侧对齐）

- 统一表 `copywriting.<域>`：`copywriting.item`（物品）/ `copywriting.narrative`（剧情事件）/ `copywriting.probability`（概率文案）/ `copywriting.bulletin`（公告通知）；
- 既有 `descriptions.items` / `narratives.events` 经**适配层**（S3 迁移）映射到统一表（或直接迁移），`CopywritingResolver` 只认 `copywriting.*` 表。
