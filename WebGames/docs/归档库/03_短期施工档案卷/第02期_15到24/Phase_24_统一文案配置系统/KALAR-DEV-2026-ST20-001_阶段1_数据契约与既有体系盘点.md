## 二、 数据契约定义（统一文案配置系统）

### 2.1 统一文案键（延续名称注册表规范）

```
<域>.<条目>.<字段>
```

- 域（domain）：`item`（物品描述）/ `narrative`（剧情事件描述）/ `probability`（概率文案）/ `bulletin`（公告通知）；
- 条目（entry）：各域 canonical 标识（物品 english_name / 事件 ID / 概率事件 ID / 公告键）；
- 字段（field）：`desc`/`result`/`notice`…（语义自描述）；全键经 Phase 19 名称注册表登记，跨域唯一。

### 2.2 统一模板语法与配置结构

| 要素 | 规范 |
| :--- | :--- |
| 占位符 | **`{param}` 唯一语法**（语义化命名），`%s`/`%d` 存量迁移归零 |
| 模板 | 每文案键一个模板字符串（可含 `{param}`） |
| 条件段 | `conditions[].when` + `.text`（状态条件匹配则拼接——物品/事件描述既有结构统一） |
| 结果分支 | `branches` 或按 outcome 键（base/success/failure/partial——事件描述既有结构统一） |
| 配置表 | `copywriting.<域>`（GameConfig 递归扫描自动发现，零装配） |

### 2.3 域白名单边界（红线保留，不合并职责）

| 域 | 红线（延续） |
| :--- | :--- |
| 物品描述 | 占位符仅限属性白名单（不反向定义属性）；身份字段禁入；只读消费注册系统 |
| 剧情事件描述 | 模板禁判定字段（不承担事件判定）；结果分支白名单 |
| 概率文案 | 文案只描述概率结果（只读上下文），禁含判定/执行逻辑；概率值域 0~1 由代码层保证 |
| 公告通知 | 纯展示文案（无逻辑键；参数仅展示性占位符） |

### 2.4 统一加载/热重载

- `copywriting.<域>` 表经 GameConfig 递归扫描自动加载（零装配）；`GameConfig.reload()` 后共享解析核心实时读取最新文案（热重载契约）。
