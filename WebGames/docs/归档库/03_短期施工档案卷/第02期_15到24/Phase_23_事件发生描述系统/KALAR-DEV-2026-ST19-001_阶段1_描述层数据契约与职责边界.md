## 二、 描述层数据契约（事件侧三位一体）

| 层 | 职责（边界） | 禁止（反模式） |
| :--- | :--- | :--- |
| **事件系统（事件层）** | 定义/触发/生命周期/执行（Phase 20/22 契约不变） | 不承载描述生成 |
| **动态概率系统（概率层，Phase 22）** | 概率计算/调整/关联（只算不执行） | 不承载描述生成；不取代事件执行 |
| **事件发生描述系统（描述层）** | 根据**实际事件/上下文/结果**生成描述（事件发生后，模板 + 结果分支 + `{param}` 填充）——可配置扩展 | **不得直接承担事件判定**（不参与触发决策/不返回概率/不派发动作）；不得反向定义事件核心属性或绕过事件系统读取结果 |

**描述层输出契约**：

```
EventDescriptionResolver.resolve(event_id, context, result, locale) -> { success, event_id, text }
```

- `result` = 事件执行结果（成功/失败/产出/损失）——**由事件层写入**，描述层只读消费（不判定、不写回）；
- 描述键：`narrative.<域>.<事件ID>`（Phase 20 键规范，名称注册表登记）；
- **描述生成时序**：事件触发 → 事件层执行（判定/概率/动作）→ **描述层生成描述**（结果已定，纯展示派生）——时序保证描述层不承担判定。

**跨三位一体协作契约**：事件描述可引用物品侧状态（`{item_name}`/`{item_quality}` 经名称注册表 resolve）与概率结果（`{probability_pct}` 经 Phase 22 输出）——物品侧（Phase 21）与事件侧经配置/名称注册表协作，无直接类依赖环。
