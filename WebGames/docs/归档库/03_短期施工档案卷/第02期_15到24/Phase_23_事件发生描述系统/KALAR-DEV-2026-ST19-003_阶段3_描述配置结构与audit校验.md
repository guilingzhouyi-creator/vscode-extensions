## 一、 描述配置结构

```json
{
  "descriptions": {
    "EVT_BEAST_TIDE": {
      "base": "{town} 爆发了兽潮！{beast_count} 头魔物逼近城墙。",
      "success": "英勇的守卫击退了兽潮，{reward_gold} 金币入库，损失 {loss_soldiers} 名卫士。",
      "failure": "兽潮冲破城门！{town} 陷入火海，伤亡 {loss_soldiers}。",
      "partial": "兽潮被遏制但未肃清，{town} 城墙破损，{reward_gold} 金币作为守城赏金。"
    }
  }
}
```

| 项 | 约定 |
| :--- | :--- |
| 表名 | `narratives.events`（GameConfig 递归扫描自动发现，零装配） |
| 描述键 | `narrative.events.<事件ID>`（名称注册表登记，域所有者 = narrative） |
| 结果分支 | `base`/`success`/`failure`/`partial`…（与事件层 `result.outcome` 对齐；缺省 base 兜底） |
| 占位符 | `{param}` 语义化（复用 Phase 20 管线），`%s` 禁入 |

**契约红线（配置不得成为后门）**：

1. **模板禁判定字段**：描述模板只允许展示性占位符——禁出现触发条件、概率判定、动作派发、结果写入字段（描述层不承担判定的配置层保证）；
2. **事件引用已定义**：`descriptions.<事件ID>` 必须对应既有事件定义（事件域清单），未定义 → 阻断；
3. **配置为源零内联**：事件描述文本 100% 来自配置（代码零内联）；占位符残留 `%s`/`%d` 归零。

## 二、 audit 事件描述校验（新增脚本或并入既有链）

| 校验项 | 规则 | 违规级别 |
| :--- | :--- | :--- |
| 事件引用 | `descriptions.<事件ID>` ∉ 事件定义清单 → 违规 | 阻断 |
| 模板禁判定 | 模板含触发/概率/动作派发/结果写入字段 → 违规 | 阻断 |
| 占位符残留 | 模板含 `%s`/`%d`/空 `{}` → 违规 | 阻断 |
| 零内联 | 后端代码出现事件描述文案字面量 → 违规 | 阻断 |
| 键登记 | 描述键未在名称注册表登记 → 违规 | 阻断 |

- 事实源：`config/narratives/events.json` + 事件定义清单 + 占位符白名单；
- 接线：挂入 `audit_runner.py`（`task_id="event_descriptions"`）；规则声明同步 `audit_docs.py --rules` 或独立规则注释。
