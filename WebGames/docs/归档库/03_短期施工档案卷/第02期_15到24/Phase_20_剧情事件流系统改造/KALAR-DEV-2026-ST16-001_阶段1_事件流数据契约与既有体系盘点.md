## 二、 数据契约定义（剧情事件流）

### 2.1 事件流键（延续名称注册表键规范）

```
narrative.<域>.<事件流ID>
```

- **域（domain）**：narratives 配置文件名（`combat` / `character_creation` / `clock` …），表名 `narratives.<文件>`；
- **事件流ID（flow_id）**：事件流唯一标识（如 `parry_interrupt` / `strike_hit`），小写蛇形，禁中文、禁空格；
- **唯一性**：同域内事件流 ID 唯一；跨域经名称注册表（Phase 19）登记 `narrative.*` 键可查可解析。

### 2.2 占位填充符规范（统一为 {param}）

- **唯一占位符语法**：`{param}` 花括号语义化参数（`{attacker}` / `{target}` / `{skill_name}` / `{damage}` / `{remaining_hp}`…）；
- **取缔 C 风格 `%s`/`%.1f`/`%d`**：全量迁移为 `{param}`，复用 `LocalizationSolver.translate` 的插值管线（零新实现）；
- **未填充校验**：事件流文本生成前校验全部占位符已提供参数（缺失 → 拦截 + 告警计数，不静默输出 `%s` 残留）；
- **参数语义化**：参数名与数值语义绑定（禁位置依赖），文案可重排不破坏语义。

### 2.3 配置为唯一事实源

- 剧情文本 100% 来自 `config/narratives/*.json`（零代码内联剧情文案）；
- 事件流加载经 GameConfig 递归扫描（表名 `narratives.<文件>`）自动发现，新增文件即收录（MOD/DLC 零改动）；
- 事件流解析器每次读取**最新配置**（支持 `GameConfig.reload()` 热重载后重新解析）。

### 2.4 热切换/热重载契约

- **热重载**：`GameConfig.reload()` 后事件流解析器重建事件流表（配置为源，零手工刷新）；
- **热切换（运行中事件流安全迁移）**：进行中的事件流（has_triggered 会话）在重载后按事件流 ID 保持触发状态（`triggered_timestamp` 不变），仅文案/参数模板刷新——**零打断**；
- **显示文本不作逻辑判断依据**：事件流 ID/参数名是逻辑键，文案是展示层（延续既有约定）。
