| # | 既有机制 | 位置 | 能力现状 | 三位一体角色 |

| 2 | **统一物品注册系统** | `item_namespace_registry/`（12 文件：ItemRegistryCatalog/ItemLoaderPipeline/ItemRegistrySolver/ItemQualityResolver…） | canonical_id/numeric_id/english_name/loc_name_key 三元组 + 自动递增 ID + 冲突检测 + 配置自动发现 + 品质解析 | **注册层**：类型/ID/唯一标识/跨系统注册与索引 |

## 二、 三位一体分层数据契约

| 层 | 职责（边界） | 禁止（反模式） |
| :--- | :--- | :--- |
| **物品系统（本体层）** | 物品属性/状态/实例化/品质/数值行为——确定性业务能力 | 不得依赖描述层文本做判定；不得把描述模板混入本体逻辑 |
| **统一物品注册系统（注册层）** | 类型/ID/唯一标识（canonical_id + numeric_id + english_name + loc_name_key）/跨系统注册与索引/冲突检测 | 不得承载显示文本生成；不得被描述层绕过（描述层禁自建物品身份） |
| **物品描述系统（描述层）** | 基于**已注册物品**及其状态生成/组织/维护描述（模板 + 状态条件组合 + `{param}` 填充）——可配置扩展 | **不得反向定义物品核心属性**（模板只引用已注册属性，禁定义新属性/覆盖本体字段）；**不得绕过统一注册系统建立独立物品身份**（描述消费 ItemRegistryCatalog 已注册条目，禁独立 canonical_id 空间） |

**跨三位一体协作契约**：

- 物品描述键：`item.<canonical_id>.desc`（经 Phase 19 名称注册表登记，域所有者 = item，跨域唯一）；
- 描述模板占位符：`{param}` 语义化（复用 Phase 20 插值管线，`{quality_tier}`/`{quantity}`/`{durability}`/`{enchant}`…）；
- **数据契约协作**：物品侧（本体+注册+描述）与事件侧（事件+概率+描述）之间仅经名称注册表（键）+ 配置表（上下文数据）协作——事件概率可**只读引用**物品注册状态作为条件上下文（如 `{item_owned}`/`{item_quality}`），**不产生直接类依赖/循环依赖**。
