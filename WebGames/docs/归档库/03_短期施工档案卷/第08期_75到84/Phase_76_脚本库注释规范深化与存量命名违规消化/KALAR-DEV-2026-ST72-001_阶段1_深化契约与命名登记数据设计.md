## 一、 深化契约数据定义 (Enhanced Contract)

### 1.1 注释风格对齐后端规范（新增 SHOULD 维度）

| 深化点 | 校验规则 | 级别 | 对齐来源 |
| :--- | :--- | :---: | :--- |
| 区块集中分割 | 脚本内逻辑分区（常量/函数/流程）使用 78 字符等宽分割线（`# ===...` 或 `# ---...`） | SHOULD | `后端代码注释规范.md` 二 |
| docstring 规范 | py 引擎模块级 docstring（`"""..."""`）存在且非空、第一行为一句话职责 | SHOULD | Python 惯例 + 后端注释精神 |
| 职责真实性 | `职责:` 字段 ≥ 1 句完整描述（非仅复制文件名） | SHOULD | Phase 75 职责语义细化 |
| 注释与代码对齐 | 头注释不得引用不存在的外部路径/依赖（如 `res://` 路径存在性抽查） | SHOULD | `后端代码注释规范.md` 一 |

> 上述维度 Phase 76 先以 **SHOULD（warn 提示）** 落地，下轮视收敛情况升级 MUST。

### 1.2 NAMING_RULES 登记契约（存量消化）

```json
{ "scope": ".", "dirs": ["后端架构", "前端架构", "归档库", "路线图", "玩法汇总", "模板", "audit"],
  "files": ["卡拉尔世界引擎开发路线图\\.md", "README\\.md", "后端代码注释规范\\.md"] }
```

- **语义**：仅追加真实存在文件 `后端代码注释规范.md` 的命名登记，**不改动既有模式**（不放宽、不删除）；
- **三处同步**：`scripts/py/audit_docs.py`（NAMING_RULES 声明）＋ `scripts/README.md`（audit-docs 描述处）＋ `docs/README.md`（目录职责表）一致声明该文件归属 docs/ 根；
- **验收**：audit-docs `--baseline` 中 NAMING-FILE 违规归零（存量消化，非消音）。
