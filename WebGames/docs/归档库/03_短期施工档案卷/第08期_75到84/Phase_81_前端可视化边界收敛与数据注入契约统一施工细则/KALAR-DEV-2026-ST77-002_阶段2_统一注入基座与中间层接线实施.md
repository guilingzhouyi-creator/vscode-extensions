## 一、 统一注入基座与中间层接线 (Unified Injection & Layer Wiring)

### 1.1 基座契约（BaseScreen / BaseModal 落地）

```gdscript
# 模块路径: res://frontend/presentation/base/base_screen.gd（既有文件落地改造）
class_name BaseScreen extends Control

var _snapshot: Dictionary = {}

func on_screen_enter(params: Dictionary = {}) -> void:
	_apply_params(params)

func apply_snapshot(snapshot: Dictionary) -> void:
	_snapshot = snapshot
	_render_from_snapshot()

func _render_from_snapshot() -> void:
	pass  # 子类实现纯渲染映射

func on_screen_exit() -> void:
	UIIntermediary.clear_view_bindings(self)
```

* 18 视图由 `extends Control` 迁移为 `extends BaseScreen`（模态继承 BaseModal），统一生命周期 `on_screen_enter/on_screen_exit`；
* 基类内置 `apply_snapshot` 唯一入口与 UIStateContainer 五态挂载点，视图子类只实现 `_render_from_snapshot` 渲染映射。

### 1.2 统一快照入口与旧桩兼容

* 以 `apply_snapshot(snapshot: Dictionary)` 取代异构的 `set_*_snapshot`/`update_*` 裸参数桩（约 20 个）；
* 迁移策略：旧桩保留为薄封装（内部组装字典后调用 `apply_snapshot`）并标注弃用期，或在同批次内删除并同步调用方测试；严禁两套入口长期并存；
* 快照字段严格来自阶段1 契约，视图禁止对快照做业务反推。

### 1.3 MockServiceContainer 消费闭环

```gdscript
# 数据流: I*Service（Mock 实现）→ Snapshot 契约 → ViewModel → BaseScreen.apply_snapshot
var service := MockServiceContainer.get_instance().get_service("world") as IWorldService
var snapshot := service.fetch_hud_snapshot(character_id)
view_model.update_from_snapshot(snapshot.to_dictionary())
screen.apply_snapshot(view_model.to_render_snapshot())
```

* `app_bootstrap.gd` 装配后必须存在真实消费者，`get_service` 返回值不再丢弃；
* 四个接口 IAuthService/IWorldService/ICombatService/IVersionService 与 Snapshot 契约字段对齐，保证后端实现可无缝替换。

### 1.4 ViewModel 归并与命名统一

* `HudViewModel` 与 `CharacterHudDecoupled` 二选一保留（建议保留三层完整的 CharacterTransportDTO→CharacterDomainModel→CharacterHUDViewModel），字段命名统一（`hp_max` 与 `hp_maximum` 只留一个）；
* `CombatViewModel` 接线到 combat_view 或删除，杜绝零引用悬空层；
* 所有 ViewModel 输入统一为 Snapshot 契约，不再直吃裸字典。

### 1.5 状态机与五态容器接线

* `AppLifecycleFSM` 由 `AppBootstrap`/`NavManager` 驱动（BOOT→INITIALIZING→AUTHENTICATING→MAIN_MENU/LOBBY 等），状态变更纳入既有导航流程；
* `UIStateContainer` 在数据加载路径挂载 Loading/Success/Empty/Error/Retry 五态，重试回调指向 domain_boundary 服务拉取。
