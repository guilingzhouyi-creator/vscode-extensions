## 一、 阶段目标与配置驱动边界 (对齐 P10.3 / 10.4 / 10.8)

本阶段落实后端剧情 i18n 与新手初始化的纯配置驱动架构：
1. **独立后端剧情文案库 (`config/narratives/prologue_i18n.json`)**：构建独立的文案 Key 空间与模板资源，彻底与前端 UI i18n（按钮、Label、静态提示）隔离；
2. **新手配置架构 (`config/domains/starter_loadout.json`)**：声明不同种族/身世的新手装备组合、金币数量及指派规则；
3. **全域无头事件广播**：通过 `EventBus.emit_domain_event` 广播 `prologue.step_advanced`，向前端暴露包含 `channel + narrative_key + i18n_params + mutations` 的结构化事件。

## 四、 全域事件广播与前后端 i18n 消费契约

```gdscript
class_name PrologueEventBroadcaster
extends RefCounted

static func broadcast_prologue_step(packet: PrologueEventPacketDTO, narrative_key: String, params: Dictionary) -> void:
	var bus := EventBus.get_instance()
	if bus == null:
		return

	# 1. 向结构化通道发送包含文案 Key 与参数的泛化领域事件
	# 前端可通过本事件获取结构化数据，使用前端自己的模板或直接展示 fallback_text
	var payload := packet.to_dto()
	payload["narrative_key"] = narrative_key
	payload["i18n_params"] = params.duplicate(true)

	bus.emit_domain_event("prologue.step_advanced", payload)

	# 2. 同步投递富文本文字战报 (供 MainDashboard 的 %NarrativeLog 实时打印)
	bus.emit_narrative(packet.narrative_text, "narrative", {
		"character_id": packet.character_id,
		"narrative_key": narrative_key
	})
```
