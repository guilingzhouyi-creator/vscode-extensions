## 一、 阶段目标与领域定位 (对齐 P10.1 / 10.3 / 10.4)

本阶段为卡拉尔世界引擎承接 Phase 48 所广播的开局事件流（`OpeningEventStreamDTO`），构建**角色专属序章实例生命周期**、**占位符驱动契约**与**独立后端剧情 i18n 契约**。

严格贯彻 P10 标准规范：
1. **角色序章专属实例化（P10.1）**：序章不是“世界序章”或“固定地图开场”，而是每个角色创建完成后，基于角色属性建立专属独立的序章执行上下文，不硬编码绑定固定世界地点、坐标、NPC 或单一场景；
2. **剧情文案与代码彻底分离（P10.3）**：代码中严禁硬编码任何剧情正文，后端只消费剧情节点 ID、文案 Key、占位符、条件与事件动作；
3. **后端 i18n 与前端 UI i18n 彻底解耦（P10.4）**：后端剧情 i18n 独立管理剧情文本、事件文本与角色对白，向前端仅暴露 `剧情事件 + 文案 Key/资源引用 + 参数`，严禁把后端文案当作前端固定 UI 文本接口返回；
4. **事件与状态解耦（P10.7）**：事件执行产生的是结构化结果（如 `CharacterCreated`、`EquipmentGranted`、`LocationAssigned`、`DialogueReady`），不直接指示前端具体页面。

## 二、 角色序章上下文实体与生命周期模型 (`CharacterPrologueContext`)

```gdscript
class_name CharacterPrologueContext
extends RefCounted

# 角色身份唯一源头
var account_id: String = ""
var character_id: String = ""
var character_name: String = ""
var race_id: String = "HUMAN"
var gender: String = "OTHER"

# 运行时动态上下文 (由配置与创建参数确定，严禁代码硬编码)
var assigned_start_location_id: String = ""
var assigned_opening_quest_id: String = ""
var assigned_starter_kit_id: String = ""

# 序章单向阶段流转
var current_stage: int = 0
var step_index: int = 0
var is_active: bool = false
var is_completed: bool = false
var created_timestamp_utc: int = 0

# 占位符运行时缓存字典 (键 -> 动态解析实值)
var runtime_placeholders: Dictionary = {}

func to_dto() -> Dictionary:
	return {
		"account_id": account_id,
		"character_id": character_id,
		"character_name": character_name,
		"race_id": race_id,
		"gender": gender,
		"assigned_start_location_id": assigned_start_location_id,
		"assigned_opening_quest_id": assigned_opening_quest_id,
		"assigned_starter_kit_id": assigned_starter_kit_id,
		"current_stage": current_stage,
		"step_index": step_index,
		"is_active": is_active,
		"is_completed": is_completed,
		"created_timestamp_utc": created_timestamp_utc,
		"runtime_placeholders": runtime_placeholders.duplicate(true)
	}

static func from_dto(d: Dictionary) -> CharacterPrologueContext:
	var ctx := CharacterPrologueContext.new()
	if d.is_empty():
		return ctx
	ctx.account_id = str(d.get("account_id", ""))
	ctx.character_id = str(d.get("character_id", ""))
	ctx.character_name = str(d.get("character_name", ""))
	ctx.race_id = str(d.get("race_id", "HUMAN"))
	ctx.gender = str(d.get("gender", "OTHER"))
	ctx.assigned_start_location_id = str(d.get("assigned_start_location_id", ""))
	ctx.assigned_opening_quest_id = str(d.get("assigned_opening_quest_id", ""))
	ctx.assigned_starter_kit_id = str(d.get("assigned_starter_kit_id", ""))
	ctx.current_stage = int(d.get("current_stage", 0))
	ctx.step_index = int(d.get("step_index", 0))
	ctx.is_active = bool(d.get("is_active", false))
	ctx.is_completed = bool(d.get("is_completed", false))
	ctx.created_timestamp_utc = int(d.get("created_timestamp_utc", 0))
	ctx.runtime_placeholders = (d.get("runtime_placeholders", {}) as Dictionary).duplicate(true)
	return ctx
```

## 三、 占位符体系与解析契约 (对齐 P10.2)

剧情步骤、文案及事件必须采用统一占位符格式 `{VARIABLE_NAME}`，支持动态从角色、世界、配置及事件执行结果中求解：

| 占位符标识 | 语义解释 | 运行时解析事实来源 | 容错策略 |
| :--- | :--- | :--- | :--- |
| `{PLAYER_NAME}` / `{CHARACTER_NAME}` | 角色展示名 (唯一源头) | `CharacterPrologueContext.character_name` | 缺失时按配置 `defaults/fallback_name` 兜底 |
| `{CHARACTER_ID}` | 角色唯一业务编号 | `CharacterPrologueContext.character_id` | 严禁为空，空则阻断 |
| `{RACE_ID}` | 种族标识代码 | `CharacterPrologueContext.race_id` | 读 `config/domains/character_creation.json` 映射名 |
| `{START_LOCATION}` | 起始地点名称/代码 | 角色上下文绑定地点，查后端 i18n 地理表 | 缺失时读 `defaults/starting_location` |
| `{INITIAL_EQUIPMENT}` | 初始装备/新手武器名称 | 新手配置表根据种族/身世分配的装备名 | 查物品注册表英文/本地化三元组 |
| `{NPC_TARGET}` | 序章接引人身份/名称 | 根据出生地/身世配置指派的接引 NPC 代号 | 查 NPC 配置表 |
| `{EVENT_RESULT}` | 上一步骤动作产生的因果值 | 前序事件执行产出的结构化状态标记 | 默认注入 `"SUCCESS"` |

## 四、 后端独立剧情 i18n 契约 (对齐 P10.4)

建立独立的后端剧情文案解析契约 `NarrativeI18nResolver`，明确其与前端表现层 UI i18n 的职责边界：

```gdscript
# 统一文案 Key 三段式约定:
# narrative.<domain_scope>.<event_node_key>
# 示例: "narrative.prologue.awakening" -> 对应 config/narratives/prologue_i18n.json 中的条目
```

### 前后端 i18n 隔离准则
1. **前端 UI i18n 专职**：仅负责客户端按钮、菜单栏、表单 Label、静态弹窗提示等 UI 表现层字符串；
2. **后端剧情 i18n 专职**：仅负责角色对白、剧情叙事、历史片段、系统因果通告等后端业务资源；
3. **契约输出格式**：后端向 EventBus 广播的事件包中**同时包含结构化数据、文案 Key 与动态参数包**：
   ```json
   {
     "event_channel": "prologue.step_advanced",
     "narrative_key": "narrative.prologue.first_encounter",
     "i18n_params": {
       "PLAYER_NAME": "艾隆",
       "NPC_TARGET": "要塞老兵",
       "INITIAL_EQUIPMENT": "粗铁佩剑"
     },
     "fallback_text": "【相遇】要塞老兵快步走来，将粗铁佩剑递给艾隆……"
   }
   ```
   前端表现宿主既可直接展示后端解析后的 `fallback_text`（富文本日志模式），也可按 `narrative_key` + `i18n_params` 由表现层模板引擎自主渲染（高级对白框模式）。
