## 一、 配置驱动与泛化扩展实现 (Configuration-Driven & Refactoring)

### 1. 补偿通道配置化

新增配置键（落点：既有 `config/domains/cdkey_voucher.json`，如该表已存在同族键则就近扩展，严禁另建文件）：

| 配置键 | 类型 | 默认值 | 语义 |
| :--- | :--- | :---: | :--- |
| `redemption/compensation/ttl_ms` | int | 180000 | DISPATCH_PENDING 驻留超时（3 分钟）触发补偿判定 |
| `redemption/compensation/max_retry` | int | 3 | 重试投递上限，超过则 RELEASED |
| `redemption/compensation/enabled` | bool | true | 补偿通道总开关（运维可临时关闭） |

读取方式一律 `GameConfig.get_int/get_bool("domains.cdkey_voucher", "redemption/compensation/ttl_ms", 180000)` 型——类型化取值器 + 安全兜底，严禁 `get_value`。默认值 180000/3/true 为**兜底默认**，实际以配置表为准；若既有 `config/domains/cdkey_voucher.json` 尚无该段，实现轮先补配置段再引用（配置先行，代码后读，防 TC-ARCH-06 键路径校验误伤）。

### 2. 幂等键维度规范登记（可审计资产）

本卷将「幂等键含所有者维度（Inv-IP-1）」登记为全局约定，登记点为既有 `docs/README.md` 或 `config/README.md` 的共享底座约定清单（实现轮在改文档时同步一行，禁止另起规范文件）：

```
幂等/去重缓存约定（2026-09-04 登记，来源 Phase 52）：
  任何 static 进程级幂等缓存键必须以「状态所有者」为最细粒度前缀；
  跨账户/跨角色共享键视为数据一致性违规（首例修复：mail _claimed_results）。
```

### 3. 错误码与可观测性

- 新增对外错误码 `CODE_RELEASED_AFTER_FAILURE` 登记进调用面文档（返回结构仍为 `success/error_code` 双字段，不破坏既有消费者）；
- 补偿触发/释放动作统一经既有领域事件或日志通道留痕（对齐 ClawbackService 的审计精神，但**不新增** GM 审计强制项——本卷范围不涉权限面）；
- 幂等缓存命中与补偿回滚路径补 `push_warning` 级日志（不刷屏：仅在跨账户错配断言或补偿出口打点）。

### 4. 依赖治理

- `mail_delivery_pipeline` 复合键改造仅依赖 `MailItemAggregate.recipient_account_id`（同域字段，无新依赖）；
- `voucher_dispatch_pipeline` 引用 `UniqueIdGenerator`（infrastructure 公共设施，方向：domain → infrastructure，合规）；
- 补偿通道实现在 `redemption_flow_orchestrator.gd` 内完成，不新开文件。
