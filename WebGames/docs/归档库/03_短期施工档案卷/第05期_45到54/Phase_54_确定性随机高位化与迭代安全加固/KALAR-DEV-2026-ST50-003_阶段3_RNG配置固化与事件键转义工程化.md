## 一、 配置驱动与泛化扩展实现 (Configuration-Driven & Refactoring)

### 1. RNG 派生版本登记与兼容策略

| 契约项 | 落点 |
| :--- | :--- |
| 派生版本 | `DeterministicRNG` 头注释登记：**派生 v2（2026-09-04，Phase 54）——整数/数组派生由低比特取模改 randf 全精度高位缩放**；派生函数变更只影响 `randi_range`/`pick` 输出序列 |
| 兼容策略 | 同种子序列整体变化属预期（确定性契约指「同一版本内可复现」）；历史回放/存档若依赖 v1 序列，由运维评估按版本化回放器承载——**本卷不引入双派生开关**（避免长期双路径维护），如确有兼容需求须另行立项 |
| LCG 常量读取 | 顺带核对阶段1 L8 关联项：`_lcg_multiplier/_lcg_increment/_lcg_mask`（127-134 行）每步实时读配置。本卷范围**仅登记风险**（运行中 reload_config 会静默改序列、破坏整局复现契约），固化方案（set_seed 时快照常量）归 Phase 56 防御面统一实施，避免本卷扩散 |

### 2. 组合键编码单点化

```gdscript
# 模块路径: res://backend/domains/event_extractor/composite_event_extractor.gd
# 新增唯一静态入口（Inv-ENG-1 的键编码类比）：
## 长度前缀编码组合键——对任意字段内容无碰撞；仅用于等值分组（不解析）
static func _encode_composite_key(parts: Array) -> String:
    var key := ""
    for part in parts:
        var s := str(part)
        key += "%d:%s" % [s.length(), s]
    return key
# 使用点收敛：98 行唯一构造点改经本函数；KEY_SEP 若失去全部使用点即删除
#（以 grep 实况为准——不留死常量，对齐死配置门禁）
```

### 3. 零硬编码与依赖核对

- 阶段2 新增 `maxi(1, …)` 下限钳制属边界保护（对齐全库既有惯例），非业务阈值硬编码；
- `mini(hi, lo + scaled)` / `mini(arr.size()-1, idx)` 为派生边界钳制，不新增配置键；
- 时间轴 interval 配置继续走 `domains.combat` 既有键族（`tertiary_timeline/*`），**不改默认值**；
- 无新跨域依赖：`_encode_composite_key` 纯静态函数；RNG 改造限于 infrastructure 单文件。

### 4. 文档登记

- `config/README.md` 或 `docs/README.md` 底座约定（改文档时同步一行，禁另起文件）：RNG 派生 v2 生效说明 + 「组合键一律长度前缀编码」约定；
- `tertiary_timeline` 头注释登记「两阶段排期 + 新事件严格未来」语义。
