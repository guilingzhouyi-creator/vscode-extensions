## 一、 核心业务细类与算法实现 (Business Implementation & Solver)

### 1. M2 修复：RNG 高位缩放派生（randi_range / pick）

```gdscript
# 模块路径: res://backend/infrastructure/deterministic_rng.gd
# 派生基准：randf() 已为全精度状态缩放（float(state)/(mask+1)），作为高位信源
# 关键点：int 派生不再触碰 state % small_range 的低比特路径

## [lo, hi] 闭区间整数（含两端）—— Inv-RG-1：由 randf 全精度缩放，禁用 % 低比特
func randi_range(lo: int, hi: int) -> int:
    if hi <= lo:
        return lo
    var span := hi - lo + 1
    var scaled := int(randf() * float(span))      # 消费 1 次 next_state（经 randf）
    return mini(hi, lo + scaled)                  # float 舍入边界钳回 hi

## 从数组等概率取一个元素；空数组返回 null（不产生模零崩溃）
func pick(arr: Array) -> Variant:
    if arr.is_empty():
        return null
    var idx := int(randf() * float(arr.size()))   # 禁用 % 低比特
    return arr[mini(arr.size() - 1, idx)]
```

**序列节奏**：两方法均恰好消费 1 次 `next_state()`（`randf` 内部一次），与旧实现消费节奏一致，仅派生函数不同 → 同种子**新算法序列确定且可复现**（Inv：确定性不破），但与旧算法序列整体不同（派生 v2，阶段3 登记兼容策略）。

### 2. M8 修复：时间轴两阶段分离排期

```gdscript
# 模块路径: res://backend/domains/physics_thermodynamics/tertiary_timeline_engine.gd
func advance_time(delta_ms: int) -> Array[TimelineEventPointDTO]:
    if delta_ms <= 0:
        return []

    current_timeline_ms += delta_ms
    var fired_events: Array[TimelineEventPointDTO] = []
    var pending_events: Array[TimelineEventPointDTO] = []

    # 阶段 A：触发收集（遍历 scheduled_events 自身不修改——Inv-TL-2）
    for evt in scheduled_events:
        if evt.trigger_time_ms <= current_timeline_ms:
            evt.is_processed = true
            fired_events.append(evt)
        else:
            pending_events.append(evt)

    # 阶段 B：分离重排期（新事件严格 > now——Inv-TL-1），追加进 pending
    for evt in fired_events:
        if evt.event_type == TimelineEventType.RANDOM_DISPATCH:
            pending_events.append(_build_next_dispatch_event())
        elif evt.event_type == TimelineEventType.TENSION_PULSE:
            pending_events.append(_build_next_tension_event())

    scheduled_events = pending_events
    return fired_events

# 重排期生成器（原 _schedule_next_* 原地 append 改为返回新事件；trigger 统一 + maxi(1, delta)）
func _build_next_dispatch_event() -> TimelineEventPointDTO:
    var min_int := maxi(1, GameConfig.get_int("domains.combat", "tertiary_timeline/dispatch_interval_min_ms", 1200))
    var max_int := maxi(min_int, GameConfig.get_int("domains.combat", "tertiary_timeline/dispatch_interval_max_ms", 2800))
    var delta := rng.randi_range(min_int, max_int) if rng else min_int
    event_counter += 1
    var evt := TimelineEventPointDTO.new()
    evt.event_id = "EVT_DISPATCH_%d" % event_counter
    evt.event_type = TimelineEventType.RANDOM_DISPATCH
    evt.trigger_time_ms = current_timeline_ms + delta        # 严格 > now（delta ≥ 1）
    return evt
# _build_next_tension_event() 同构：tension_types 空守卫保留（原 90-91 行），interval 下限 maxi(1, …)
```

**语义对照**：interval 配置为 0 时旧实现可能同趟再触发/死循环，新实现钳为 ≥1ms 严格未来，单次 advance 至多推进有限事件数；其余（event_counter 前缀、事件 id、payload）与原实现一致。

### 3. L10 修复：组合键长度前缀编码

```gdscript
# 模块路径: res://backend/domains/event_extractor/composite_event_extractor.gd
# 替换 98 行的 "%s%s%s%s%s" % [..., KEY_SEP, ..., KEY_SEP, ...] 拼接

## 长度前缀编码：对任意字段内容无碰撞（Inv-EC-1）；仅用于等值分组，无需解析
static func _encode_composite_key(parts: Array) -> String:
    var key := ""
    for part in parts:
        var s := str(part)
        key += "%d:%s" % [s.length(), s]
    return key

# 使用点（原 98 行）：var key := _encode_composite_key([rule_id, prim["account_id"], prim["transaction_id"]])
```

**KEY_SEP 处置**：若 `KEY_SEP` 常量已无其他使用点则随改造移除；若有保留使用点则维持定义但组合键路径不再引用（实现轮以 grep 实况为准，禁留死常量——对齐死配置门禁）。
