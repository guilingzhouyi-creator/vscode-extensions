## 一、 快照面清单契约 (Snapshot Surface Manifest)

### 1. 事务快照面类型枚举

以本卷三处修复为基座，先固化三类快照面，后续卷同类事务强制复用：

| 快照面类型 | 覆盖状态 | 获取 | 恢复 | 现有载体 |
| :--- | :--- | :--- | :--- | :--- |
| `SURFACE_WALLET` | 铜/银/金/白金/魔单晶五币余额 | `CharacterWalletEntity.to_dictionary()` | `from_dictionary()` | ✅ 已有 |
| `SURFACE_INVENTORY` | 背包 storage + 穿戴槽 + 物品实例（序列化级） | `WearableInventoryAggregate.snapshot()` | `restore()` | ✅ 已有（反序列化重建） |
| `SURFACE_LOADOUT` | 装备槽位引用（loadout 侧独立簿记） | **本卷新增** `EquipmentLoadoutAggregate.snapshot_slots()` | **本卷新增** `restore_slots()` | ❌ 缺失（M5 根因） |
| `SURFACE_COUNTER` | 计数/保底/状态位类（banner 三字段、击败锁存等） | **本卷新增** banner 侧 `GachaBannerAggregate.snapshot_progress()` / `restore_progress()` | 同左 | ❌ 缺失（M1 根因） |
| `SURFACE_ENGINE_STATE` | 潜能引擎双计数（lifetime/unassigned） | `PotentialGrowthEngine.serialize()` | 收敛式恢复（见 §2.3） | ⚠️ 缺收敛 |

### 2. 事务快照面归属矩阵（本卷范围）

| 事务入口 | 涉及快照面 | 现状缺口 |
| :--- | :--- | :--- |
| `GachaExecutionService` 十连 | WALLET + INVENTORY + **COUNTER(banner)** | COUNTER 未入快照（M1） |
| `DisposalPipeline` 穿戴销毁 | INVENTORY + **LOADOUT** +（账本库台账） | LOADOUT 未入快照（M5） |
| `AttributeRespecPipeline.execute_heart_core_respec` | WALLET + ENGINE_STATE(+ L1 等级/进度) | 成本公式无 ≥0 钳制；ENGINE_STATE 反序列化无收敛（M9） |

### 3. 恢复语义分级

- **原地恢复（原实例可变字段回写）**：WALLET / COUNTER / ENGINE_STATE —— 引用连续性不变。
- **重建式恢复（反序列化新实例）**：INVENTORY（既有 `restore()` 语义，保留）——恢复后必须**重新建立与外部簿记（loadout/事件台账）的引用一致性**（M5 的 111 行清槽动作发生在 restore 之前，故恢复顺序必须为：先 restore INVENTORY → 再按槽位回挂 LOADOUT，或反之保证两侧同源）。

## 二、 三处缺陷的契约级根因定论

### M1（COUNTER 未入快照）：事务边界定论

```
现有时序：扣费(SINK) → 逐抽 roll_single_draw【推进 banner 计数+歪率锁存】→ 发放
          → grant_failed > 0 时【仅回滚 WALLET/INVENTORY】→ 返回 REWARD_COMMIT_FAILED
契约修正：banner 计数推进属于事务提交面，不得先于发放成功提交；
         失败路径必须等量回滚 total_lifetime_pulls / current_pity_count /
         is_next_guaranteed_up 三字段（回滚后与未抽状态严格等价）。
```

### M5（LOADOUT 未入快照）：回滚顺序与引用一致性定论

```
现状：inventory.restore() 为重建式恢复 → 原 DESTROYED 实例被新实例替换，
      loadout 槽仍持旧实例引用且槽位已被清空 → equipped_slots(新实例) 与 loadout(空) 脱节。
契约修正：销毁事务的快照面 = INVENTORY ∪ LOADOUT；
     回滚顺序固定为：restore(LOADOUT 槽位原引用) → restore(INVENTORY 重建)，
     并以 item_uid 为主键校验两侧槽位最终指向同一实例（防双簿记）。
```

### M9（负成本 + 无收敛）：值域与序关系定论

```
不变量 Inv-TX-2/3 落点：
 ① PotentialGrowthEngine.deserialize：读入后强制 unassigned = min(unassigned, lifetime)（先收敛再返回）；
 ② AttributeRespecPipeline.calculate_respec_cost：分子取 maxi(0, lifetime - unassigned)（双保险，防御直接构造 engine 的调用路径）；
 ③ 结果 crystal_cost 再经 maxi(0, …) 兜底——三处任一处独立生效即不可能出现负扣减。
```
