### 1. M1 修复：GachaBannerAggregate 进度快照与十连事务整面回滚

```gdscript
# 模块路径: res://backend/domains/gacha_wish/gacha_banner_entity.gd（新增方法）
class_name GachaBannerAggregate
# 新增快照/恢复对（SURFACE_COUNTER）——仅覆盖事务可变的三字段：
func snapshot_progress() -> Dictionary:
    return {
        "total_lifetime_pulls": total_lifetime_pulls,
        "current_pity_count": current_pity_count,
        "is_next_guaranteed_up": is_next_guaranteed_up,
    }

func restore_progress(snap: Dictionary) -> void:
    total_lifetime_pulls = int(snap.get("total_lifetime_pulls", total_lifetime_pulls))
    current_pity_count = int(snap.get("current_pity_count", current_pity_count))
    is_next_guaranteed_up = bool(snap.get("is_next_guaranteed_up", is_next_guaranteed_up))
```

```gdscript
# 模块路径: res://backend/domains/gacha_wish/gacha_execution_service.gd（改造 execute_multi_pull 失败分支）
var banner_snapshot := banner.snapshot_progress()          # 与 wallet/inventory 快照同点采集
# ...原有逐抽与发放逻辑不变...

    banner.restore_progress(banner_snapshot)               # 关键新增：计数随事务回滚
```

**语义要点**：快照采集点必须与 `wallet_snapshot`/`inventory_snapshot` 同一行（扣费成功后、逐抽循环前），保证「成功提交则三面一致前滚、失败则三面一致回滚」。`grant_failed_count > 0` 的既有判定语义不变（不静默发放部分奖励）。

### 2. M5 修复：销毁事务 loadout 槽位对称回滚

```gdscript
# 模块路径: res://backend/domains/equipment_loadout/equipment_loadout_entity.gd（新增方法）
# 槽位引用快照：仅记录 槽位名 → item_uid（引用以 uid 为准，不持有实例，防重建式恢复失效）
func snapshot_slots() -> Dictionary:
    var snap := {}
    for slot in equipped_slot_ids():            # 依现有槽位枚举（如 weapon/armor/...）
        var it := get_equipped_item_ref(slot)
        if it != null:
            snap[slot] = it.item_uid
    return snap

func restore_slots(snap: Dictionary, inventory: WearableInventoryAggregate) -> void:
    # 依 uid 从背包反查重建实例回挂；背包侧由调用方先完成 restore
    for slot in equipped_slot_ids():
        unequip_item_ref_by_slot(slot)          # 清空当前槽（幂等，空槽安全）
    for slot in snap.keys():
        var uid: String = str(snap[slot])
        var item = inventory.find_item_by_uid(uid)
        if item != null and equip_item_ref_by_slot(slot, item):
            pass                                 # 回挂成功
```

```gdscript
# 模块路径: res://backend/domains/matter_disposal/disposal_pipeline.gd（改造回滚分支）
# 快照面：INVENTORY ∪ LOADOUT（装备槽原引用以 uid 采集，见上）
var inventory_snapshot := inventory.snapshot()
var loadout_snapshot := {}                        # 当 _remove_owned_item 命中穿戴槽前采集
# 命中穿戴槽路径（原 107-113 行）拆除时同步记录被清槽位 → 进入 products 回流循环
for product in products:
    if not inventory.add_item(product):
        inventory.restore(inventory_snapshot)     # 先重建背包（含原装备实例）
        loadout.restore_slots(loadout_snapshot, inventory)   # 再按 uid 回挂装备槽

```

**时序铁律**（阶段1 §二 M5 契约）：先 `restore(INVENTORY)` 重建 → 后 `restore_slots(LOADOUT, inventory)` 以 item_uid 反查回挂；禁止反序（loadout 回挂依赖背包已有重建实例）。成功路径保持「先清槽再销毁」原时序不变。

### 3. M9 修复：反序列化收敛 + 成本非负双层防线

```gdscript
# 模块路径: res://backend/domains/potential_growth/potential_growth_engine.gd（改造 deserialize）
static func deserialize(d: Dictionary) -> PotentialGrowthEngine:
    var eng := PotentialGrowthEngine.new()
    var lifetime := int(d.get("lifetime_potential_earned", 0))
    var unassigned := int(d.get("unassigned_potential_points", 0))
    eng.lifetime_potential_earned = maxi(0, lifetime)                 # 防线 0：lifetime 非负
    eng.unassigned_potential_points = clampi(unassigned, 0, eng.lifetime_potential_earned)  # 防线 1：收敛序关系 Inv-TX-3
    eng.allocated_points_history = d.get("allocated_points_history", {})
    return eng
```

```gdscript
# 模块路径: res://backend/domains/potential_growth/respec_pipeline.gd（改造成本公式）
var crystal_cost = int(floor(float(maxi(0, engine.lifetime_potential_earned - engine.unassigned_potential_points)) / divisor))
# 防线 2：即使调用方绕过 deserialize 直接构造 engine，分子钳 0 亦不可能负成本（Inv-TX-2）
```

**防御纵深说明**：`deserialize` 收敛（防线 1）保护所有存档加载路径；`maxi(0, …)`（防线 2）保护直接构造/遗留内存路径；两条防线互相独立、各自可单独验证（阶段1 DoD `TC-RO-S1-04/05`）。
