## 一、 核心数据模型与 Schema 契约设计

### 1.1 `.kmod` 扩展包元数据 Schema (`bundle_manifest.schema.json`)

定义 `.kmod` 归档包内唯一权威元数据 `manifest.json` 强类型规约：
- **Schema ID**: `kalar.mod_sdk.bundle_manifest.v1`
- **必需字段**: `bundle_id`, `bundle_name`, `version`, `engine_api_version`, `tier`, `files_manifest`, `created_timestamp_utc`
- **文件指纹清单 (`files_manifest`)**: 字典映射 `relative_path -> { "sha256": String, "size_bytes": int }`
- **分级约束**: `tier` 必须处于枚举 `["TIER_1_LOGIC", "TIER_2_AUDIOVISUAL", "TIER_3_OVERHAUL"]`

### 1.2 开发者工作台运行配置 Schema (`workbench_config.schema.json`)

定义工作台环境描述：
- **Schema ID**: `kalar.mod_sdk.workbench_config.v1`
- **字段规范**:
  * `workspace_root`: MOD 工程根目录路径；
  * `watch_mode`: 是否激活文件变动自动热重载检查；
  * `target_engine_mode`: `HEADLESS_PYTHON` 或 `HEADLESS_GODOT`；
  * `default_playthrough_seed`: 确定性无头推演伪随机种子。

### 1.3 序章至大地图状态交接 DTO (`PrologueHandoffDTO`)

文件路径: `res://backend/domains/character_creation/dto/prologue_handoff_dto.gd`
```gdscript

```
