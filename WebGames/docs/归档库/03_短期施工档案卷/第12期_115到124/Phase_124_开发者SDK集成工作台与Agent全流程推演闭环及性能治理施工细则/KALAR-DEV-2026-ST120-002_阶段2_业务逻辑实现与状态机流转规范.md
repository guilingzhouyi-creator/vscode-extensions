## 一、 核心组件与业务逻辑实现

### 1.1 开发者集成单一工作台实现 (`kalar_workbench.py`)

在 `WebGames/mod_sdk/tools/kalar_workbench.py` 实现集成控制台：
- **`build_kmod_package(mod_dir: Path, output_file: Path) -> tuple[bool, str]`**:
  * 遍历 MOD 目录，计算全量文件的相对路径、大小与 SHA-256 哈希；
  * 组装合规 `manifest.json`；
  * 将所有资产打包为标准压缩格式并命名为 `.kmod`；
- **`run_interactive_workbench(workspace: Path)`**:
  * 聚合脚手架初始化、离线静态门禁审查、自动化全流程 Agent 推演与构建打包；
  * 提供面向 AI Agent 的流式 STDIO 命令接口。

### 1.2 序章至大地图探索状态机流转接线 (`WorldGatewayFSM`)

在 [`WorldGatewayFSM`](../../../../../backend/domains/world_gateway/world_gateway_fsm.gd) 增加核心流转方法：
```gdscript
func handoff_prologue_to_world_exploration(handoff: PrologueHandoffDTO) -> Dictionary:
    if handoff == null or handoff.character_id.is_empty():
        return {"success": false, "error_code": "ERR_INVALID_HANDOFF"}
    # 1. 挂载活动模组与界域亲和
    active_mods = handoff.active_mods.duplicate()
    # 2. 推进主循环状态机
    var fsm := GameLoopStateStack.new()
    fsm.switch_to(GameLoopStateStack.EngineState.WORLD_EXPLORATION, {
        "character_id": handoff.character_id,
        "character_name": handoff.character_name,
        "location_id": handoff.assigned_start_location_id,
        "gold": handoff.initial_gold
    })
    # 3. 触发权威 HUD 初始同步
    var hud_ctx: Dictionary = {
        "character_id": handoff.character_id,
        "character_name": handoff.character_name,
        "gold": handoff.initial_gold,
        "location_id": handoff.assigned_start_location_id
    }
    var snap := AuthoritativeHudSyncService.trigger_initial_sync(hud_ctx)
    return {"success": true, "snapshot": snap, "state": fsm.current_state}
```

### 1.3 性能热点优化与循环零瞬态堆分配 (`composite_event_extractor.gd`)

针对 `composite_event_extractor.gd` 的循环分配优化：
- 在对象中维持预分配私有缓冲数组 `_event_scratch_buffer: Array[Dictionary]`；
- 在每趟提取循环前调用 `_event_scratch_buffer.clear()`，原位填充事件数据，严禁在循环内重复调用 `[]` 瞬态初始化。
