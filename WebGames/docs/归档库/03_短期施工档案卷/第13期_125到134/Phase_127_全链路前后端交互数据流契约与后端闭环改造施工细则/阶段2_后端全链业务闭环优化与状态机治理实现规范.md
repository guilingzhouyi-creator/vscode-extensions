### 1.2 核心不变量约束断言

- **对象池化与热路径零堆分配不变量 (Inv-ADV-PRF-002)**：高频信封、HUD 快照刷新及事件分发必须复用 `UnifiedProtocolFactory` / 池化实例与 `reset_state()` 复位方法，严禁在循环与心跳同步内执行无边界 `.new()` 堆分配；所有随机演算必须经 `DeterministicRNG` 或配置驱动确定性种子。
- **状态机互斥迁移与防越权不变量 (Inv-FSM-MUTEX-2)**：活跃世界未退出前严禁切换网关 `GameMode`；注销账号或进入停机流必须显式吊销会话令牌与人类控制租约，且清理全部活跃 `EventBusCore` 订阅令牌。
- **零残缺存盘与诚实停机不变量 (Inv-HONEST-SHUTDOWN-3)**：`SaveDataAccessLayer` 仅在多域提供者完成组装且通过 `SaveReadinessGuard` 校验后才允许写入存档；若 `save_before_quit = true` 且 `force_quit = false` 时落盘失败，停机流程必须显式失败终止（不得推进至 `STOPPED` 或返回 `success = true`）。
- **构造-销毁对称守恒不变量 (Inv-SYMMETRIC-TEARDOWN-4)**：`GameBootstrap.teardown()` 必须对称清理其在运行时装配及联动的所有领域会话态、网关缓存、控制租约、协议对象池与存档提供者表，保障连续多轮启动-退出周期状态零污染。

### 1.3 业务实现最高指示

禁止通过"注释掉校验、兜底回填假数值、写入最小桩代码空壳文件"来掩盖链路断裂；所有跨环断点（如 `EscMenuBackendService` 三字段伪存档覆盖、`UnifiedProtocolDispatcher` 硬编码测试数值、`AuthoritativeHudSyncService` 单信道重复订阅、`GameLifecycleService` 假成功停机）必须在本阶段从状态真源层面彻底根治。

## 一、 七大后端闭环改造核心架构设计

### 1.1 运行时全链会话托管与常驻 HUD 同步中枢（链路 5 核心新增）

新建后端服务 `backend/domains/world_state/services/world_session_runtime_service.gd`（类名 `WorldSessionRuntimeService`，`extends RefCounted`，配完整 6 字段 JSDoc 头注释与 `reset_state()`）：

- **职责边界**：作为后端全链唯一状态持有中枢，集中托管：
  - 当前登录态：`account_id`、`session_token_hash`、`gateway_fsm`（原始令牌经 `AuthService` 内的 `ClientSecretVault` 掩码托管，保持领域与基础设施分层隔离）；
  - 当前网关与档案态：`gateway_fsm`（`WorldGatewayFSM`）、`world_instance`（`WorldInstance`）、`slot_id`、`character_profile`（`CharacterProfile`）、`physiology_sheet`、`wallet_entity`、`world_clock`（`WorldClockMaster`）；
  - 脏标记与节流游标：`_hud_dirty`、`_world_dirty`、`_last_hud_push_ms`、可配置最小推送间隔 `_hud_sync_min_interval_ms`。
- **常驻 HUD 双轨闭环**：
  - 主动拉取路径 `pull_hud_snapshot()`：直接从真实聚合根组装 `HudStatusSnapshotDTO` 与 `AuthoritativeHudSnapshotDTO`（绝不使用硬编码兜底数值）；
  - 事件推送路径 `flush_hud_sync_if_dirty(now_ms: int)`：仅在 `_hud_dirty == true` 且满足间隔节流条件时，经 `AuthoritativeHudSyncService` 向专用子信道分发快照或增量突变；
  - 进入探索态 `activate_world_session(...)` 时自动向 `SaveDataAccessLayer` 注册真实域存盘提供者；退出世界 `deactivate_world_session()` 时对称注销提供者、清理脏标并释放瞬态持有。

### 1.2 账号鉴权、令牌脱敏与首页视图模型闭环（链路 1、9、10）

改造 [`AuthService`](../../../../backend/domains/account/auth_service.gd) 与 `AccountLifecyclePipeline`：

1. **注册即落时间戳与可选签发令牌**：修复 `register_account()` 中 `last_login_timestamp_utc = 0` 的缺口；当请求包含 `auto_login = true`（配置默认可控）时同步建立受保护会话，否则保持严格独立登录。
2. **接入 `ClientSecretVault` 内存脱敏**：会话存储不再明文留存原始令牌，统一使用 `ClientSecretVault.mask_in_memory_token(...)` 生成脱敏索引句柄并校验令牌摘要与 TTL 过期时间。
3. **显式注销与账号首页真源查询**：
   - 新增 `logout_session(session_token: String, account_id: String)`：吊销服务端会话条目、清理绑定租约、广播 `AUTH_SESSION_REVOKED`；
   - 新增 `build_account_home_view_model(session_token: String, repo: AccountRepository)`：为链路 10 返回零敏感字段的账号首页数据视图模型（当前活跃账号摘要、本地可选择档案元数据列表、版本与公告状态）。

### 1.3 世界网关档案目录、探针刷新与模式防越权闭环（链路 2、7、8）

改造 [`WorldGatewayFSM`](../../../../backend/domains/world_gateway/world_gateway_fsm.gd) 与 [`WorldArchiveRepository`](../../../../backend/domains/world_state/world_archive_repository.gd)：

1. **模式探针刷新与持久化门槛对齐**：
   - `exit_to_gateway()` 在重置 `selected_mode = GameMode.UNSELECTED` 与清理上一局会话级 MOD 清单后，必须同步调用 `RuntimeModeGate.set_mode(...)` 清空运行时模式，并立即重新执行 `ModeReadinessProbe.probe_all_modes(context.account_id)` 刷新 `_last_probe_reports`，保证退出世界后网关界面拿到最新可用模式态；
   - 新增 `switch_gateway_mode(target_mode: int)`：严格校验当前处于 `GATEWAY_ENTERED` 且无活跃世界（`StateMutationIsolationGuard` + `AntiBridgeGuard`），禁止探索态热切换模式（命中则抛出 `ERR_HOT_SWAP_BLOCKED_IN_ACTIVE_WORLD`），切换成功同步刷新 `RuntimeModeGate` 与 `WorldGatewayContextDTO`。
2. **序章交接上下文修复**：修正 `handoff_prologue_to_world_exploration(handoff)` 中向 `AuthoritativeHudSyncService.trigger_initial_sync(hud_ctx)` 传入的键名，`allocated_attributes` ➔ `"attribute_values"`（及派生 `"attribute_levels"`），`assigned_start_location_id` ➔ `"current_location_id"`。

### 1.4 权威创角与序章-过场CG-世界探索单轨收口（链路 3、4）

1. **创角双入口收敛**：保留现有底层解算器兼容性的同时，在 `WorldCharacterCreationOrchestrator` / 新增协调器提供唯一权威门面方法 `execute_authoritative_creation_flow(...)`：统一零信任白名单过滤（丢弃客户端伪造属性）、L3 `CharacterPhysiologySheet` 派生、`SaveSlotCharacterBinder` 与 `AccountSlotBindingSolver` 绑定、`WorldArchiveRepository` 存档装配及 `OpeningEventStreamDTO` 广播。
2. **序章与非阻塞 CG 协同闭环**：经领域依赖倒置端口 `PrologueCutscenePort`（由 `GameBootstrap.assemble()` 注入 `CutsceneOrchestrator` 适配器）执行序章 CG；序章完结后自动产出自洽的 `PrologueHandoffDTO`，触发 `WorldGatewayFSM.handoff_prologue_to_world_exploration`，完成世界激活态写入与 HUD 首帧同步推送。

### 1.5 统一协议调度拓展与 ESC 安全双分流根治（链路 5、6、7、11）

1. **扩展 `UnifiedProtocolDispatcher` 路由表与令牌守卫**：
   - 路由覆盖扩展至全 7 个域：`"account"`、`"world_gateway"`、`"character_creation"`、`"prologue"`、`"world_state"`、`"lifecycle"`、`"game_settings"`；
   - 接入 `AuthService.validate_session(request.session_token)` 守卫（除配置允许匿名端点如 `REGISTER_ACCOUNT`、`LOGIN_LOCAL`、`LOGIN_COMPOSITE`、`GET_ACCOUNT_HOME_VIEW_MODEL`、`REQUEST_GRACEFUL_SHUTDOWN` 外，全部请求校验会话合法性）；
   - 替换 `_dispatch_agent_action_compat` 中含硬编码数值的未解耦 `AuthoritativeHudSnapshotDTO`，统一改为读取 `WorldSessionRuntimeService` 实时状态并返回真实 `causal_delta`。
2. **彻底清除 `EscMenuBackendService` 三字段伪存档覆盖漏洞**：
   - 删除 `"ESC_EXIT_TO_GATEWAY"` 分支中构造 `{"slot_id", "account_id", "saved_at"}` 覆盖 `.kalar_save` 的高危逻辑；
   - 统一通过 `SaveReadinessGuard` + `SaveDataAccessLayer.build_save_payload()` 聚合多域真实数据再调用 `SaveDataAccessLayer.save_game(...)`；若当前不存在合法绑定 `slot_id` 或存档提供者未就绪且请求 `auto_save = true`，显式返回失败信封与 `ERR_INCOMPLETE_SAVE_BLOCKED`（不再硬编码回退 `"SLOT_01"` 覆盖无关档位）；
   - 新增 `"ESC_GET_MENU_STATE"` 查询入口，返回当前可存档状态、脏数据标记、当前网关模式与可用菜单动作集。

### 1.6 EventBus 载荷标准化与生命周期对称停机闭环（全链横切 + 链路 11）

1. **修复 `AuthoritativeHudSyncService` 信道绑定与载荷封装**：
   - 将 `subscribe_hud_channels` 中重复绑定的双 `DOMAIN_EVENT_GENERIC` 拆分为精准专用信道订阅（`HUD_STATUS_SNAPSHOT`、`HUD_STAT_MUTATED`、`HUD_WALLET_MUTATED`、`WORLD_CLOCK_ADVANCED` 与生命周期通用信道）；
   - 通过 `EventPacket` 统一填充 `payload_dto` 与 `payload_data`，保证 `HudEventBridge` 及所有事件监听端收到规范数据；
   - 在 `EventPool` / `UnifiedProtocolFactory` 确保借出与归还平衡，增加 `unbind_all()` 显式句柄回收。
2. **修复 `GameLifecycleService._flush_domain_saves()` 假成功漏洞**：
   - 当 `SaveDataAccessLayer.save_game()` 返回 `success == false`（含 `EMPTY_SAVE_BLOCKED`）时，若 `request.force_quit == false`，必须调用 `_record_shutdown_failure(...)` 并终止进入 `STOPPED` 态，返回 `success = false, is_save_completed = false`；仅当 `force_quit == true` 时记录 `degraded_resources` 并允许降级继续停机。
3. **补全 `GameBootstrap.teardown()` 全域对称注销**：
   - 扩展 `teardown()`：按拓扑逆序注销 `WorldSessionRuntimeService`、`AuthService` 会话池、`WorldGatewayFSM` 模式与 `RuntimeModeGate`、`HumanControlLeaseManager`、`UnifiedProtocolFactory` 缓存、以及 `SaveDataAccessLayer` 域提供者与脏标志，保证二次装配前零历史残留。
