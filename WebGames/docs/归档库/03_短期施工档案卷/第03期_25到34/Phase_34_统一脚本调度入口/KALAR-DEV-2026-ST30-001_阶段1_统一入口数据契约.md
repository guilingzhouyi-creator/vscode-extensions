## 一、 现状盘点与覆盖缺口（S1 检索结论）

| 现状 | 能力 | 缺口 |
| :--- | :--- | :--- |
| `audit_runner.py` | 16 audit 任务表（AuditTask dataclass）+ `-j` 异步并行（ThreadPoolExecutor，0=自动 CPU 核心）+ `--diff/--slice/--json/--baseline` 参数 + 流式聚合看板 | 仅覆盖 audit 组 |
| `archive_volume.py` | 归档系统独立入口（volumes/--detect/--cycle/--all） | 无统一调度、无并行 |
| `report_aggregate.py` | 性能门禁报告（--out/--compare/--gate/--base） | 无统一调度、无并行 |
| `report_sweep.py` | bench 报告合并（reports/--out/--md） | 无统一调度、无并行 |
| sh 门禁链 | audit-all.sh 遍历 audit_runner 任务表；bench-sweep.sh/audit-perf.sh 直接调 py | **双入口分散**（sh 层 + py 层各自主导） |

**统一入口覆盖缺口清单**：① bench 组（report_aggregate/report_sweep）② archive 组（archive_volume）③ 跨组异步并行（现仅 audit 组内并行）④ 参数化任务选择（--task/--group）。

## 二、 统一入口数据契约（tool runner 协议）

### 2.1 入口形态（决策）

- **扩展 `audit_runner.py` 本身**为全库统一调度入口（保留文件名/引用面/既有参数语义，零破坏）；
- 任务表扩展为**三组**：`audit`（16 现状）/ `bench`（report_aggregate/report_sweep）/ `archive`（archive_volume）；
- 文档声明其新职责：**全脚本库统一调度入口（tool runner）**。

### 2.2 参数协议（扩展）

| 参数 | 语义 | 现状 |
| :--- | :--- | :--- |
| （无参） | audit 组全量 | 保持 |
| `--group audit\|bench\|archive` | 指定组全量 | 新增 |
| `--task a,b,c` | 指定任务组合（跨组任意组合） | 新增 |
| `-j/--jobs N` | 并发 Worker 数（0=自动） | 保持（扩展覆盖全组） |
| `--serial` | 强制串行 | 保持 |
| `--json` | JSON 聚合报告 | 保持 |
| `--diff` / `--slice` | 增量/领域切片 | 保持（audit 组专属语义） |
| `--baseline` | docs 基线 | 保持 |

### 2.3 异步并行契约

- **组内并行**：audit 组 16 任务 + bench 组内部（report_sweep 合并后 report_aggregate）可并行（`-j` 复用 ThreadPoolExecutor）；
- **组间互斥**：`archive` 组**独享串行**（归档含 git rm/移动文件写操作——与 audit/bench 并发存在写冲突风险）——`--task` 含 archive 任务时自动退化为「archive 先串行 → 其余并行」或整体串行（由 `--serial` 语义决定）；
- 任务级声明：AuditTask 增加 `exclusive: bool` 字段（archive 任务 = True），调度器依此规避写冲突。

### 2.4 边界不变量

1. 既有调用面零破坏：`audit-all.sh`/CI 的无参与 `--json` 调用行为不变；
2. bench/archive 任务入表**不改其既有 CLI 语义**（子进程透传各自参数）；
3. 并行正确性：无共享可变状态（子进程隔离）；archive 串行防写冲突；
4. 共享底座复用：audit_common.py（resolve_repo_root/ensure_utf8_stdout/load_json）接入调度器自身。
