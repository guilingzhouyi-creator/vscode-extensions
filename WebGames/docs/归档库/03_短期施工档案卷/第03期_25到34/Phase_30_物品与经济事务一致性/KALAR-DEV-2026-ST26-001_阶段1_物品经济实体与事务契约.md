## 一、数据契约与边界

| 对象 | 必须成立 | 非法输入 |
| :--- | :--- | :--- |
| ItemEntity | UID、canonical_id、质量、体积、重量非负且来自原型 | 空物品、负属性、未注册模板 |
| Inventory/Equipment | 一个实例只能处于一个容器或装备槽 | 重复挂载、跨账户引用、槽位未知 |
| RewardTransaction | 扣款、发奖、容量检查同一事务 | pull_count/buy_count/count 非正或溢出 |
| MailAttachment | 货币字段完整，物品附件可逐项重试 | 空 mail、重复 mail_id、领取状态与附件不一致 |

品质快照、强化等级、处置价值必须使用同一字段命名和序列化版本；物品数量和经济金额均禁止隐式符号翻转。

## 二、业务实现与状态机

- 物品状态为 `UNOWNED -> INVENTORY <-> EQUIPPED -> CONSUMED/DESTROYED`，状态转移必须验证当前容器归属。
- 发奖采用预检 → 预留 → 提交 → 失败回滚；容量不足、模板未注册或扣款失败均不得改变其他聚合。
- 分解、强化、购买、领取邮件和任务奖励均以事务 ID 幂等；重复请求返回原结果，不重复退款或发放。
- 所有变更返回受控 Result DTO，并传递实际数量、失败项和回滚状态。

## 三、配置驱动与工程化

- 物品质量、默认质量/体积、邮箱容量、商店数量上限、强化费用和产物 canonical ID 从对应 `config/domains` 表读取。
- 所有物品实例通过 `ItemRegistryCatalog` 与 `ItemInstanceFactory` 创建；业务不得自造 canonical ID 或 UID。
- 共享 `InventoryTransaction` 组件负责快照、预留、提交和回滚，避免各领域重复实现。
