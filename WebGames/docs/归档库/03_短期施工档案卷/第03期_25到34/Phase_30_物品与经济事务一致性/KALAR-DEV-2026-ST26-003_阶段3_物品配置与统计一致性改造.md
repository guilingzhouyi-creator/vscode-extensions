## 一、数据契约与边界

- `ItemPrototypeTemplate` 的 canonical/numeric/英文名/loc key、质量、体积、品质字段必须同时通过注册表校验。
- 统计树挂载接口返回 `mounted`、`actual_quantity` 和失败码；库为空或未注册模板不得返回成功。
- 热重载以 canonical ID 为主键更新原型属性，并生成版本号；删除项先阻止新发放，再按迁移策略处理存量实例。

## 二、业务实现与状态机

- 加载流程采用构建新快照 → 全量校验 → 原子替换，禁止在旧注册表上逐条半更新。
- 统计求解器只有在 `mount_item/apply_item_delta` 成功后才计数；负减量触底钳制但不能吞掉失败。
- 处置价值统一读取强化字段；产物 canonical ID 只来自配置，产物未注册则整个处置事务失败。
- 邮箱容量从配置加载，重复 mail_id 和空邮件在入箱前拒绝。

## 三、配置驱动与工程化

- 批量装配前缓存配置表和共享品质解析器，禁止循环内重复 `GameConfig` 读取或每个实例 reload registry。
- 新增 `audit_item_transactions.py` 校验 ID 三元组、字段类型、产物注册、容量上限和事务键唯一性。
- 热重载完成后广播 `items.registry_reloaded`，统计、商店、邮件和发奖服务必须刷新只读引用。
