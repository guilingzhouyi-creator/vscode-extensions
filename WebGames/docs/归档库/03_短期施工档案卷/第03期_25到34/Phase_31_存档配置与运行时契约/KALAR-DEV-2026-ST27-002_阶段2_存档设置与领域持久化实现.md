## 一、数据契约与边界

- 保存 API 返回 `SaveResult`，包含阶段、错误码、正档存在性、备份存在性和恢复建议。
- 设置 DTO 严格限定 `audio/ui_visual/render/version`，未知字段和类型错误不得写入聚合。
- provider/consumer 注册表以领域 ID 和版本为键，缺 consumer、版本不兼容或重复注册均失败。

## 二、业务实现与状态机

1. 写临时文件并 flush/close 后重新读取校验 checksum；校验通过才复制备份。
2. 备份失败按配置策略中止替换；替换使用平台支持的原子交换，并保留旧正档直到新正档可读。
3. `restore_backup` 先验证备份、写恢复临时文件，再完成交换，不执行“先删除正档”。
4. 设置应用成功后落盘；15 秒确认超时调用同一恢复事务，禁止负时间推进。
5. 生产启动由 `SaveAssembler` 自动收集注册领域，序列化和反序列化按版本顺序执行。

## 三、配置驱动与工程化

- 文件路径、备份后缀、最大版本和设置回滚时长使用 `GameConfig` 类型化读取。
- 迁移器按 `from_version -> to_version` 链执行，失败保留原数据并输出结构化日志。
- 不在领域类中直接调用 `DisplayServer`/`AudioServer` 以外的副作用；设置驱动通过适配器注入真实应用接口。
