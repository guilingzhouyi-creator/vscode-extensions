## 一、数据契约与边界

| 契约对象 | 必须字段 | 不变量 |
| :--- | :--- | :--- |
| SaveTransaction | save_name、data_json、checksum、tmp_path、backup_path | 正档始终可恢复；校验和消费同一字节串 |
| ConfigSnapshot | table_name、schema_version、required、payload | 必需表缺失或类型错误阻止装配 |
| SettingsSnapshot | audio、ui_visual、render、version | 只接受白名单字段和合法类型 |
| WorldInstance | world_id、tick、day、month、year、state | 时间单调，旧档缺字段可归一化 |
| DomainPersistence | provider、consumer、version | 每个注册领域可序列化且可反序列化 |

核心不变量：写入失败不破坏正档；配置失败不静默回退生产默认；序列化往返保持语义等价；运行时错误不得由缺省字典索引触发。

## 二、业务实现与状态机

- 存档流程为 `PREPARE -> WRITE_TMP -> VERIFY_TMP -> BACKUP -> ATOMIC_REPLACE -> COMMIT`，每一步都有可恢复失败态。
- 回滚流程先验证备份完整性，再交换到临时目标，确认成功后才移除旧正档。
- 设置流程为 `LOAD -> VALIDATE -> APPLY -> CONFIRM/ROLLBACK`，回滚计时器只接受非负 delta。
- 世界时间和生理复制使用显式归一化函数，不直接信任旧存档字典结构。

## 三、配置驱动与工程化

- `infrastructure.persistence` 声明 tmp/backup 后缀、备份失败策略、校验算法和最大存档版本。
- `domains.game_settings` 声明设置白名单、数值上下界、回滚秒数及默认值；真实持久化路径固定为 `user://settings.kalar_cfg`。
- `GameConfig.ensure_loaded()` 返回结构化加载结果；`GameBootstrap.assemble()` 负责注册所有 provider/consumer 并检查差集。
- 保存与配置热重载均广播版本事件，消费者按版本原子刷新。
