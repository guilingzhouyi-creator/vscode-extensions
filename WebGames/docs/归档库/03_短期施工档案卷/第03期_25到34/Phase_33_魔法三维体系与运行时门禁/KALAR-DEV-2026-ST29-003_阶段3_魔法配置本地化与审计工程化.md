## 一、配置落地和命名统一

| 配置域 | 收口要求 | 兼容策略 |
| :--- | :--- | :--- |
| `rank_gradient` | 11 个键 `rank_1` 至 `rank_11`，entry 的 `rank/level/name_key` 一致 | 旧键只读兼容，新增键不得带能力或档次前缀 |
| `ability_tiers` | 5 个键与 `AbilityTier` 值 1~5 一致；reference_interval 可重叠；reference_label 必须存在 | 候选集合字段名固定为 `ability_tier_candidates` |
| `rank_bands` | 4 个键与 `MagicRankBand` 值 1~4 一致；区间严格按 cursor 无缝覆盖 1~11 | 重叠配置直接拒绝，不自动排序修复 |
| `mana_aptitudes` | 4 个键与枚举一致、backfire_threshold 递增 | `man_adaptor` 作为旧别名登记；新配置规范键为 `mana_adaptor`，迁移期禁止双写不同值 |
| `magic_forms` / `profession_ranks` | 数量、值域、name_key、能损及 magic_domain 单调性完整 | 缺项阻断 registry，不使用类字段默认值替代 |
| `config/i18n` | en_US/zh_CN 对所有 magic name_key 成对覆盖；`magic.rank.*`、`magic.ability_tier.*`、`magic.rank_band.*`、`magic.aptitude.*`、`magic.form.*`、`magic.profession_rank.*` 前缀一致 | 删除或改名须由域所有者 API 清理旧键，并在迁移表登记 |

## 二、审计脚本扩展

`audit_magic_dimensions.py` 在既有六项基础上增加并明确以下检查，输出规则 ID、文件、键和值：

1. `MAGIC_REGISTRY_WIRING`：`GameBootstrap.assemble()` 存在 registry 装配与 ready 检查。
2. `MAGIC_CARDINALITY`：六类表数量分别为 11、5、4、4、4、13，且枚举、配置键、entry 数值三方一致。
3. `MAGIC_BAND_DISJOINT_COVERAGE`：档次区间严格无重叠、无空隙、全覆盖 1~11。
4. `MAGIC_DTO_FIELD_SHAPE`：`ability_tier` 标量、`ability_tier_candidates` 数组、`rank_band` 标量语义不冲突。
5. `MAGIC_I18N_PAIR`：中英文键集合与配置 name_key 集合一致；旧别名只能出现在迁移白名单。
6. `MAGIC_PRIVATE_ACCESS`：魔法注册流程不得访问 `LocalizationRegistryCatalog` 私有字段。
7. `MAGIC_FALLBACK_DIAGNOSTIC`：非法 rank 不得通过静默一阶兜底；安全兜底必须伴随错误码。

脚本通过只证明静态契约；运行时 registry 接线、热重载和 DTO 行为由阶段4 测试确认。

## 三、热重载与版本工程化

- `magic_tiers` 或魔法 i18n 表变更时，`GameConfig` 发布同一 `config_version`；registry、resolver、名称注册表按版本原子替换。
- 旧快照仍被活动事务引用时保留其 registry 只读视图；新事务使用新版本，禁止原地修改共享字典。
- i18n 缺失只允许显示层回退英文键本体；规则判定所需 name_key 缺失必须使 registry 不可用。
- 审计报告写入配置版本、脚本版本和发现数量，供 `audit-all.sh` 和归档验收复核。
