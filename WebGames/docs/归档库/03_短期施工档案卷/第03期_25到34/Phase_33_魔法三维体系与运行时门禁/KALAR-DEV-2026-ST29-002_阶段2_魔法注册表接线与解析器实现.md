## 一、实现任务与职责边界

| 组件 | 必须实现 | 禁止行为 |
| :--- | :--- | :--- |
| `GameBootstrap` | 持有唯一 registry 实例；装配失败返回 `success=false` 与诊断；重复 assemble 幂等 | 消费方自行 `MagicTierRegistry.new()` 或在领域节点中静默重载 |
| `MagicTierRegistry` | 校验六类表数量、键值一致性、区间、阈值、形态能损和 profession 单调性；生成稳定索引 | 只检查 `_ranks`/`_profession_ranks` 后宣称 ready |
| `MagicAbilityTierResolver` | 接收 registry/快照；返回候选数组 `ability_tier_candidates`；保留重叠和越级白名单 | 直接从 `GameConfig` 读取未校验数据，或把候选压成单枚举 |
| `MagicRankBandResolver` | 接收 registry/快照；按互斥区间返回单一 band；越界返回 `UNREGISTERED_BAND` | 逐阶复制映射表、容忍重叠或使用默认 LOW 掩盖坏 rank |
| `MagicBaselineResolver` | 只通过 registry 和两个 resolver 查询；输出标量字段与候选字段分离；保持失败码 | 解析器间重复实现区间逻辑或在失败时拼装部分基线 |
| `MagicTierSnapshot` | 提供 checked DTO 解析；校验枚举范围、rank/form 配对、phase loss 和 rank_band 一致性 | `from_dto` 直接强制转换任意整数并继续运行 |
| `LocalizationRegistryCatalog` | 提供公开 `get_translation`/域清理接口，支持同域幂等重载 | 通过下划线字段跨类访问内部字典 |

## 二、解析和失败流程

1. `GameBootstrap.assemble()` 加载配置后装配 registry，registry 未 ready 时停止后续物品/魔法消费方注册。
2. `MagicBaselineResolver.resolve()` 先检查 registry ready，再校验 rank、form、aptitude、profession 和三维从属关系；任一失败返回单一错误码。
3. rank 合法后由 registry 提供强度和档次，ability resolver 只返回候选集合；输出同时包含 `ability_tier`（输入主体标量或明确空值）与 `ability_tier_candidates`。
4. `MagicTierSnapshot.from_dto()` 采用 `validate_dto -> migrate_version -> construct` 顺序；失败不返回可消费对象，迁移必须记录源版本。
5. 名称键登记在 registry 成功后执行；跨域冲突使 registry 进入不可用状态，热重载先撤销本域旧键再登记新键，整个过程原子完成。

## 三、兼容和性能约束

- 旧调用方读取 `ability_tier` 数组的迁移窗口内提供明确兼容字段，但新代码只使用 `ability_tier_candidates`；窗口结束由配置版本门禁阻断旧字段。
- `get_strength_weight(99)` 等便捷查询可以返回配置化安全值，但必须同时提供 `UNREGISTERED_RANK` 诊断；不得把安全值用于写入快照。
- registry 在装配期建立 rank、tier、band、aptitude、form、profession 的整型索引；运行时解析不遍历原始字典、不重复读盘。
- 任何缓存携带 `config_version`，热重载后旧缓存失效；同一事务不可混用两份 registry 快照。
