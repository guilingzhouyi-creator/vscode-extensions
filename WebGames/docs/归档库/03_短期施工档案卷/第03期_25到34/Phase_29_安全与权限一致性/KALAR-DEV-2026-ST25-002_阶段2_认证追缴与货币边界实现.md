## 一、数据契约与边界

- `AuthSessionDTO` 必须携带服务端生成的 token hash、账户、设备指纹、签发和过期时间、撤销状态。
- `AdminPermissionEntity` 只接收已校验的密封摘要；`target_level` 采用明确枚举，权限集合去重并按稳定顺序保存。
- `ClawbackResult` 返回 `success`、`currency_delta`、`item_delta`、`audit_id` 和失败码；任何子操作失败都标记事务失败。
- 所有货币数量以整数铜币计量，转换和欠账边界由货币实体单点实现。

## 二、业务实现与状态机

1. 登录成功时生成随机 token，写入会话仓；校验时按 token 查仓并验证 TTL、设备和撤销标记。
2. 授权时先验证密封摘要，再检查等级和具体权限；不满足任一条件立即返回，不执行 handler。
3. 追缴使用事务快照：先计算货币欠账与物品钳制，再提交钱包、背包、装备槽位，最后写不可变审计记录。
4. 货币 API 对所有负支出/负债务增量返回失败；允许负余额只通过明确的欠账入口产生。

失败状态不得回写成功标记；重复 `audit_id` 或同一追缴请求必须幂等拒绝。

## 三、配置驱动与工程化

- 认证 TTL、设备绑定开关、等级枚举、追缴可用模式和负余额上限全部来自配置表。
- 审计载荷禁止写入口明文 passkey、原始 token 和完整设备指纹，只写摘要及截断标识。
- 服务依赖通过构造函数注入，禁止在领域类中创建全局会话仓或读取调用者提供的 mode。
- 货币提交提供单一 `apply_transaction` 边界，供追缴与普通交易复用，避免重复实现余额方向逻辑。
