# 施工细则：安全与权限一致性 —— 阶段3：安全配置与密封热重载改造

## 一、数据契约与边界

- 配置表必须声明 `session/ttl_seconds`、`session/allow_future_clock_skew`、`admin/max_level`、`currency/max_debt_copper` 和 `security/seal_key_id`。
- 密封算法契约为带服务端密钥的 HMAC；密钥只从受信运行环境读取，存档不保存密钥本体。
- 热重载事件携带表名、版本和生效时间；安全服务在版本不一致时拒绝新请求而不清空现有有效会话。

## 二、业务实现与状态机

- `GameConfig.reload()` 完成后广播 `config.security_reloaded`，认证、权限和货币服务按版本原子替换快照。
- entitlement 校验使用规范化排序后的权限集合和 HMAC，篡改或密钥版本不符返回无权限。
- 任何缺失必需安全配置都使装配返回失败，不允许回退到生产默认密钥或无限 TTL。

## 三、配置驱动与工程化

- 扩展 `audit_config.py` 校验安全表存在、TTL 为正、等级在枚举内、债务上限非负、密钥引用存在。
- 增加配置版本与迁移编号；旧版本密封只允许一次性迁移，迁移失败保留原数据并记录审计。
- 禁止在 `backend/domains` 使用 token、passkey、密钥及生产等级魔法数字字面量。

## 四、验收测试与门禁

| 检验项 ID | 验证输入 | 预期输出 |
| :--- | :--- | :--- |
| `TC-SEC-S3-01` | 缺失安全表、TTL=0、债务上限为负 | audit 与装配均失败 |
| `TC-SEC-S3-02` | 修改权限集合、切换密钥版本 | HMAC 校验失败或进入受控迁移 |
| `TC-SEC-S3-03` | 热重载前后并发校验 | 请求只使用完整旧/新快照，不出现混合状态 |
| `TC-SEC-S3-04` | 代码字面量扫描 | 安全阈值和密钥无未登记硬编码 |

门禁结果必须记录配置审计 JSON、热重载测试日志和 `audit-docs --baseline` 增量为零。
