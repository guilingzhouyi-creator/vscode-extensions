## 一、数据契约与边界

| 契约对象 | 必填字段 | 合法范围 | 拒绝条件 |
| :--- | :--- | :--- | :--- |
| 会话 token | token、account_id、issued_at、expires_at、device_fingerprint | 服务端签发，TTL 由配置提供 | 空 token、未知 token、过期、未来时间、设备不匹配 |
| 管理员口令 | passkey、target_level、granted_permissions | 口令只存不可逆密封；等级为已登记枚举 | 明文比较、等级越界、权限集合未授权 |
| 追缴上下文 | mode、admin、inventory、wallet、audit_id | mode 只能由受信运行上下文提供；联机限定 | 调用者伪造 online、缺少 GM 权限、目标为空 |
| 货币增量 | currency_delta、debt_delta | 所有业务输入为非负支出/非负债务增量；余额可低于零 | 负 cost、负 debt、未知币种、溢出 |

核心不变量：任何授权结果必须由服务端状态和签名上下文共同决定；负数金额不得改变余额方向；追缴必须覆盖背包和装备槽位并写审计。

## 二、业务实现与状态机

- 会话状态固定为 `ISSUED -> ACTIVE -> EXPIRED/REVOKED`，校验接口只接受服务端 token 存储中的记录。
- 口令校验采用统一密封比较，`target_level` 与 `granted_permissions` 必须同时满足调用权限矩阵。
- 追缴执行顺序为：校验在线上下文 → 校验 GM 权限 → 计算钳制量 → 原子更新货币/物品 → 写入审计；任一步失败不得部分提交。
- 货币服务将 `try_spend`、`incur_debt` 和 `apply_delta` 的负输入统一返回受控错误码，不再静默修正。

## 三、配置驱动与工程化

- 在 `config/infrastructure/admin.json` 增加会话 TTL、权限等级上限、追缴模式和审计字段白名单。
- 在 `config/domains/currency.json` 集中声明可欠账币种与最大负余额；代码只能通过 `GameConfig.get_int/get_bool/get_array` 读取。
- 会话、授权和追缴服务由 `GameBootstrap.assemble()` 注入共享依赖；禁止业务层从调用参数推断联机模式。
- 统一错误码：`TOKEN_UNKNOWN`、`TOKEN_EXPIRED`、`AUTH_CONTEXT_INVALID`、`PERMISSION_DENIED`、`NEGATIVE_AMOUNT`、`CLAWBACK_NOT_ATOMIC`。
