## 一、配置映射契约

| 配置表 | 新增或收口字段 | 约束 |
| :--- | :--- | :--- |
| `domains.quest` | prerequisite 校验开关、路径最大长度、未知节点策略 | 路径最大长度为正；未知节点策略只能是拒绝或显式跳过，默认拒绝 |
| `domains.world` | `astar` 边界、阻抗上下界、行军距离上限、空队伍策略 | infinity、距离和阻抗必须为有限正数；负值配置使表加载失败 |
| `domains.ground_loot` | delta 上限、保护期/寿命下限、衰变回收策略 | 时间参数不允许负值；永不腐朽使用明确的 `-1` 语义并由校验器识别 |
| `domains.npc` | legacy 幂等保留窗口、失败重试次数、替代继承人文案键 | 重试次数和窗口非负；替代继承人不得成为可写账户 ID |
| `domains.event_extractor` | 批大小、失败隔离、processed key 版本、投影提交顺序 | `batch_size` 为正；规则 ID、组合事件名和 projection 唯一 |
| `domains.deterministic` | 输入上下界、算法版本、指纹 schema、配置快照版本 | 指纹格式和 LCG 参数变更必须递增版本并触发回放兼容检查 |
| `infrastructure.event_categories` / `log` | 多段 channel 路由、未知分类和日志级别策略 | 分类键、级别键采用小写机器键；显示名只来自 i18n/配置 |

## 二、热重载与快照流程

1. `GameConfig` 完成单表解析和类型校验后，发布带 `table_name`、`schema_version`、`config_version` 的快照事件。
2. 任务、世界、掉落、NPC、事件提取和回放消费者在事务开始时锁定快照；热重载只影响下一事务。
3. 任一表校验失败时保留上一份有效快照并发布失败诊断；生产模式不得静默使用代码默认值。
4. EventBus 路由表与叙事表必须成对校验；多段 channel 的完整事件名映射不到模板时只广播结构化事件并记录一次受控告警。

## 三、异步、持久化和监控

- 事件提取批次和遥测写入允许异步执行，但事务提交、processed key 写入和存档快照顺序不可交叉；使用明确的完成信号或 `await` 边界。
- 失败组、回放拒绝、坏图、非法掉落和 NPC 重复提交均写入结构化日志，日志载荷不得包含完整账号隐私字段。
- 监控指标至少包括 `quest_graph_reject_count`、`path_invalid_edge_count`、`event_retry_count`、`processed_key_conflict_count`、`replay_reject_count` 和事件消费者异常数；指标名采用 `snake_case`。
- 任何优化（优先队列、批量并发、索引压缩）必须先有基准报告和确定性回放对比，不得以提高吞吐为由放宽校验。
