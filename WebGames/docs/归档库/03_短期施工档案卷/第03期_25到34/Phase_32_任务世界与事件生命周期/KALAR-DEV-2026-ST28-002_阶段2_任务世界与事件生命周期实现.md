## 一、实现边界与错误隔离

| 领域 | 实现要求 | 禁止行为 |
| :--- | :--- | :--- |
| 任务因果 | 在 `evaluate_quest_completion` 前运行节点/前置依赖校验；使用 DFS 或 Kahn 检测环路；忽略不存在的路径不得被视为成功 | 通过空路径或残留 `is_completed` 直接完成任务 |
| 世界行军 | `execute_marching_step` 先校验 party、目的地、有限非负距离和正阻抗；计算结果经 Result 返回后一次性提交状态 | 失败时已扣口粮或已移动 current_node_id |
| 地图寻路 | 过滤未知节点、负边和非有限阻抗；维持确定性 tie-break（成本相同按 node_id 稳定排序）；不可达返回空路径 | 把负边交给 Dijkstra/A*，或用隐式默认值掩盖坏图 |
| 地面掉落 | `tick_ground_loot` 对负 delta 直接返回错误；已衰变、空物品和重复 tick 幂等；释放引用与状态提交同一边界 | 负 delta 回拨寿命/保护期，或衰变后重新挂载旧实例 |
| NPC 传承 | 先校验来源/继承人引用和可继承关系，再以 `idempotency_key` 建立提交记录；著书、金币转移、事件广播按事务顺序执行；替代继承人只用于叙事，不对空对象写入 | 依赖 `successor_npc != null` 的单次判断实现幂等 |
| 组合事件 | 每组独立执行校验、物化、投影和遥测；`processed_keys[group_key] = true` 只能位于全部成功之后；失败组返回原因并可重试 | DTO 校验失败或 `library == null` 时提前吞掉组键 |
| 确定性回放 | 预扫描 tick/seed/action；动作通过 `PhysicalVerbRegistry` 解析；RNG、指纹和配置版本固定 | 对非法动作使用 `get(..., -2)` 静默继续，或在循环中读取变化配置 |
| EventBus | 将 channel 按 `.` 解析为域和完整事件名；完整事件名用于叙事查表；结构化广播与叙事广播顺序固定 | 只取第二段导致 `world.clock.advanced` 被截断 |

## 二、状态机与提交顺序

```text
输入校验 -> 领域求解 -> 事务快照 -> 领域提交 -> domain_event -> 叙事/遥测消费者
              |失败                         |消费者失败
              +-> FAILED，不写领域状态       +-> 记录错误，不回滚领域提交
```

- 任务和地图求解器保持无状态静态接口；配置快照由调用方注入或在单次调用开始时取得。
- 行军、NPC 传承和掉落更新使用显式 Result 字典，至少包含 `success`、`code` 和受影响字段；调用方必须检查 `success`。
- EventBus 的 `emit_domain_event` 只接受已提交 payload；异步监听器使用 `Callable` 连接并在回调边界捕获错误，不能抛回领域调用栈。
- 组合事件批处理按 `batch_size` 分段，单组失败不阻断其它组；重试使用原始事务键和配置版本，禁止生成新的随机键。

## 三、算法与性能约束

- 保持当前 A* 求解结果语义，先用稳定 tie-break 和边界过滤修复正确性；只有基准显示节点规模达到配置阈值时，才替换为优先队列实现。
- 事件批次物化使用一次注册表查询和按组复用 `AccountItemLibraryAggregate`，不得在每条事件中重复装配 `GameBootstrap`。
- 回放循环不分配临时字典以外的大对象；输入预扫描与执行分离，确保非法批次不会产生部分指纹。
- NPC 幂等索引和 `processed_keys` 的生命周期与存档一致，超过配置保留窗口后通过压缩而非无界增长。
