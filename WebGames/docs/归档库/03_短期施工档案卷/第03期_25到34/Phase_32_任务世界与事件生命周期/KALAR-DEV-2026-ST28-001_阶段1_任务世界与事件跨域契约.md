## 一、审查问题分级与处理边界

| 类型 | 已识别问题 | 本阶段处理原则 |
| :--- | :--- | :--- |
| 规范违规 | 任务路径、事件通道和输入字段缺少统一非空、格式及命名契约 | 固化字段、枚举、错误码和键格式，后续门禁检查 |
| 设计缺陷 | 任务环路、空路径、空队伍、非法目的地、掉落空物件可能进入业务状态机 | 将非法输入定义为拒绝态，禁止部分状态写入 |

| 性能问题 | 地图开放集线性扫描；批量事件失败隔离边界不明确 | 先定义可测复杂度与批次隔离指标，不预设无收益重构 |
| 可维护性问题 | EventBus 多段事件名解析只消费固定段；各域自行解释默认值 | 由配置表和共享 Result 契约统一解释 |
| 可选优化 | 未来可引入优先队列、事件重放索引和异步批处理 | 仅在基准证明收益且不破坏确定性后立项 |

## 二、跨域数据契约

| 契约对象 | 必须字段 | 不变量与失败码 |
| :--- | :--- | :--- |
| QuestCausalityAggregate | quest_id、objective_nodes、solution_paths、prerequisites | 节点 ID 唯一；前置节点存在；路径非空且无重复节点；依赖图无自环和环路；失败返回 `QUEST_GRAPH_INVALID` |
| MarchingParty | party_id、party_size、current_node_id、ration_units | `party_id` 非空；`party_size` 大于 0；口粮不小于 0；目的地必须存在；失败返回 `EMPTY_PARTY`、`DESTINATION_NOT_FOUND` 或 `NEGATIVE_DISTANCE` |
| WorldMapGraphNode/edge | node_id、terrain_type、target_node_id、distance | 节点和边引用已登记；距离为有限正数；地形阻抗为有限正数；不可达返回 `PATH_NOT_FOUND` |
| GroundDroppedItemAggregate | drop_id、item_entity、local_coordinates、protection_remain_seconds、total_lifespan_seconds | `drop_id` 和物品实例非空；时间增量非负；衰变后不可拾取；失败返回 `DROP_INVALID` 或 `NEGATIVE_DELTA` |
| NPCLegacyTransaction | source_npc_id、successor_npc_id、legacy_id、idempotency_key、state | 来源与继承人引用必须存在且关系可继承；来源 NPC 仅能成功提交一次；继承人为空使用配置化替代名但不转移给空对象；状态 `PREPARED/COMMITTED/FAILED` 单向跃迁 |
| CompositeEventBatch | account_id、transaction_id、event_type、canonical_id、quantity、processed_key | 数量为正；空 transaction_id 只能逐条落账；processed key 由规则、账号、事务三元组规范化；只有完整物化/投影后才可标记已处理 |
| DeterministicInputSnapshot | tick、rng_seed、action_command | tick 严格递增且非负；seed 在配置范围内；动作必须在 `PhysicalVerbRegistry` 登记；非法输入返回 `REPLAY_INPUT_INVALID` |
| DomainEvent | channel、payload、category_key | channel 至少含域和事件名，事件名各段非空；payload 为字典；未知分类受控回退；事件广播顺序确定 |

## 三、生命周期和数据流

1. 任务提交先完成前置依赖校验，再评估事实；任一路径完成才进入 `COMPLETED`，环路或空路径不得改变任务完成标记。
2. 行军请求依次执行输入校验、路径/阻抗求解、时间与口粮计算、队伍状态提交、到达事件广播；前四步任一失败都不修改队伍。
3. 掉落生命周期为 `SPAWNED -> PROTECTED -> AVAILABLE -> DECAYED`，物品引用在进入 `DECAYED` 后释放且不可重新拾取。
4. NPC 传承和组合事件均采用 `PREPARED -> APPLIED -> COMMITTED` 事务语义；失败只能进入 `FAILED` 并保留重试依据。
5. 回放先验证全部输入和配置版本，再执行固定顺序 RNG；EventBus 只消费已提交事件，异步消费者失败不反向修改领域状态。

## 四、配置和版本契约

- `domains/quest.json`、`domains/world.json`、`domains/ground_loot.json`、`domains/npc.json`、`domains/event_extractor.json`、`domains/deterministic.json` 负责阈值、默认值、错误隔离策略和算法版本；代码不得新增同义默认常量。
- `infrastructure/event_categories.json` 与 `infrastructure/log.json` 是分类和日志级别唯一来源；`channel` 的多段解析规则写入配置版本并向后兼容已有两段通道。
- 所有领域输入和输出附带 `schema_version` 或 `config_version`；热重载期间同一事务固定使用一个快照，禁止半批次混用新旧配置。
