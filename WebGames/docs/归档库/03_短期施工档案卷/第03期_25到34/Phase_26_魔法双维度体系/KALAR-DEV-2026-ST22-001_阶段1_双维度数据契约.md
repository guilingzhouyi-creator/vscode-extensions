## 二、 双维度数据契约

### 2.1 维度一：阶位梯度（Rank Gradient）

- 连续整数阶位 **rank 1~11**，严格递增（strength_weight 单调），量化魔法强度/规模/技术层级；
- **无能力分级前缀**：键 `rank_1`…`rank_11`（禁 mortal_/heroic_/divine_/god_ 嵌入）；
- 独立配置段 `magic_tiers.json → rank_gradient`；单调性由 audit/不变量保证（禁跨级倒置）。

### 2.2 维度二：能力分级（Ability Tier）

- 独立四等：**异能（ESP）/ 英雄（HEROIC）/ 神圣（DIVINE）/ 真神（GOD）**——描述施法主体/存在总体能力层次、身份与力量范畴；
- 独立配置段 `ability_tiers`：每等含 `name_key`（`magic.ability_tier.*`）+ **参考区间**（weak interval：覆盖的阶位区间，允许重叠）+ 权重 + 参考标签；
- **超位（SUPERTIER）**：保留为能力分级维度的**高级位阶**（真神之上/超越位阶上限的特殊存在），独立条目（S2 落地）。

### 2.3 弱映射关系（两维度间）

| 机制 | 规则 |
| :--- | :--- |
| 参考区间 | 每能力等级声明「大致覆盖的阶位区间」（如 异能 1~3、英雄 3~6、神圣 6~9、真神 9~11——**允许区间重叠**）——经验性判断依据 |
| 参考标签 | 配置化标签（如 `typical_rank_label`）供展示/提示用，非判定逻辑 |
| 经验判定 | 从阶位推断能力等级 = 查参考区间（命中即"大致对应"），**仅经验性**，非数学映射 |
| 越级 | 特殊个体/特殊魔法/装备/环境/状态可突破通常区间（配置 `allow_break` 标志或仅提示），系统不强制 |
| **禁止** | 不得使用固定 `Tier↔Rank` 一对一枚举映射作为**核心判定逻辑** |

### 2.4 边界声明

- **需求表2 历史封存真源「四等十一阶」2 处不修改**（历史真源，仅活跃体系演进——与 Phase 18 先例一致）；
- 两维度独立性为不变量：新增等级/能力分类/特殊规则**不得破坏双体系独立**；
- 显示文本（i18n）仅承载称谓，不作逻辑判断依据（Phase 19 红线延续）。
