## 二、 改造边界与数据契约

### 2.1 默认分类配置化

- 新配置键：`domains.items`（或既有表）`defaults/category_minor`，fallback 值仍为 `"WEAPON_BLADE"`（零行为变化）；
- 消费点：`item_loader_pipeline` / `item_registry_catalog` / `physical_verb_registry` 的 `"WEAPON_BLADE"` 字面量 → `GameConfig.get_string(...)` 引用（fallback 不变）。

### 2.2 代码物品 ID 引用一致性

- 不删常量（引用语义合法），audit 校验：代码内 `KALAR:...` canonical ID 字面量 ⊆ `config/items/*.json` 已注册集合（防注册表改名/删除后代码引用漂移）。

### 2.3 AST kind 白名单单一真源

- **真源 = 代码**（`NarrativeCausalityOrchestrator.evaluate_ast_condition` 的 match kind 分支）；
- `audit_event_probability.py` 删除 Python `KIND_WHITELIST` 副本，改为**解析代码 match kind 生成白名单**（单一真源，新增 kind 只改代码一处）。

### 2.4 gacha 概率值域审计补强

- `audit_gacha_rates.py`（或并入 audit_config）：`domains.gacha` 表 `rates.*` 0~1、`pity.*` 正整数且 soft < hard——配置驱动补强（不改行为）。

**边界声明**：本卷不动文案（GM/公告/中文 fallback 归 Phase 24）、不动概率行为（gacha 值不变，仅加校验）、不建新域（默认分类归既有 items 表）。
