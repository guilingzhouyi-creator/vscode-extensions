## 一、 停机数据与状态转换契约

### 1.1 阶段顺序和资源策略

- `shutdown_hooks/stage_order` 必须恰好包含 `freeze_inputs`、`flush_saves`、`execute_resource_descriptors`、`revoke_session`、`teardown_bootstrap` 各一次；缺失、未知或重复项在任何停机副作用前拒绝。
- `shutdown_hooks/resource_policies` 按资源 ID 提供 `priority`、`timeout_ms`、`is_critical`。资源注册及停机预检拒绝缺失策略、重复 ID、非法数值和无效 `Callable`。
- 用户裁定资源优先级**降序**，高优先级先释放。配置重载后，停机预检重新取策略并按降序稳定重排。
- 生命周期配置中的 `unwired_slot_sentinel` 是 `UNBOUND` 唯一真源；Guard 与 Account 路径均使用 `GameConfig.get_string` 读取。

### 1.2 失败、超时与重入

| 场景 | 响应约束 |
| :--- | :--- |
| 非关键清理失败 | 标记降级/剩余/保留资源，按既定管线继续 |
| 关键清理失败 | 整体失败，停止后续非关键清理并记录未执行资源 |
| 资源或阶段超时 | 记录超时和对应阶段/资源；同步回调返回后才可检测 |
| 正在停机时重入 | 拒绝第二条资源清理流程，不重复触发副作用 |
| 已停机再次请求 | 保持稳定幂等结果，不重复释放资源 |

`GameShutdownDTO.Response` 通过字段表达失败阶段、剩余/保留/超时/未执行/降级资源和阶段结果；不得以单一 `success` 丢弃诊断信息。
