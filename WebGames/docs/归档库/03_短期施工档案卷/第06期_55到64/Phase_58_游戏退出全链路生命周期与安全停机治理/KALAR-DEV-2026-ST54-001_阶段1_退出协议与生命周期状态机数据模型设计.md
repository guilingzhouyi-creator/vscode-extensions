  - `backend/infrastructure/game_loop_fsm.gd:10-18`：引擎主循环状态栈仅支持到 `PAUSED_MODAL`，缺少停机与注销状态；
  - `config/infrastructure/contracts.json`：Phase 57 契约注册表中零退出/停机命令端点。

* **核心不变量约束断言**：
  - `Inv-EX-1`（状态写权限唯一性）：生命周期状态（`LifecyclePhase`）的写权限**严格且唯一**归属于 `GameLifecycleFSM` 状态机内部，其余所有模块（UI、API、Service、Resource）仅具备只读订阅与查询权限，禁止外部直接覆写状态；
  - `Inv-EX-2`（合法单向状态跃迁）：生命周期严格遵循 `RUNNING → STOPPING → STOPPED` 标准流转，或在异常时进入 `STOP_FAILED → FORCE_STOPPING → STOPPED`，禁止从 `STOPPED` 或 `STOPPING` 非法逆跳回 `RUNNING`；
  - `Inv-EX-3`（请求幂等性）：任一带有相同 `idempotency_key` 的停机请求在同一生命周期内多次下发，必须严格返回相同的停机进展快照，杜绝重复触发清理与并发写冲突；
  - `Inv-EX-4`（资源清理拓扑 DAG 无环性）：停机资源注册表中的依赖关系必须构成有向无环图（DAG），释放顺序严格按拓扑逆序执行，循环依赖在注册期直接报错阻断；
  - `Inv-EX-5`（持久化完整性守卫）：若退出上下文标记 `auto_save: true`，必须在进入 `STOPPED` 前确认 `SaveManager` 原子写与 SHA-256 计算完毕，未完成前不得强制释放存储资源。

* **防漂移最高指示**：
  - 本阶段**仅**设计生命周期数据结构、协议 DTO 与状态枚举模型，严禁私自编写业务功能代码；
  - 严禁生搬硬套占位符，所有 DTO 字段必须具备严格类型标注与确定性默认值；
  - 协议字段语义必须收敛于业务意图（退出原因、槽位、会话），严禁把内部 Worker、线程句柄等底层细节暴露到 DTO 中。

## 一、 数据结构设计与代码契约 (Data Structures & Code Contracts)

### 1. 生命周期阶段枚举与状态模型 (LifecyclePhase)

```gdscript
# 模块路径: res://backend/domains/lifecycle/lifecycle_model.gd
class_name GameLifecycleModel
extends RefCounted

## 引擎全生命周期阶段枚举（结构性强类型，零魔法字符串）
enum LifecyclePhase {
	UNINITIALIZED = 0,    ## 0. 未初始化
	BOOT_INITIALIZING = 1,## 1. 启动装配中（配置加载/注册表填充）
	RUNNING = 2,          ## 2. 正常运行中（主循环活跃）
	PAUSED = 3,           ## 3. 游戏暂停中（模态阻断）
	STOPPING = 4,         ## 4. 正在安全停机（停输入/刷存档/断网络）
	STOP_FAILED = 5,      ## 5. 安全停机异常受阻（I/O超时或资源死锁）
	FORCE_STOPPING = 6,   ## 6. 强制终止清理（降级强杀孤儿任务）
	STOPPED = 7           ## 7. 停机完成（资源归零，可安全关闭进程）
}

## 退出触发原因分类
enum ExitReason {
	USER_LOGOUT_TO_MENU = 1,  ## 用户主动退回主菜单/选服页
	USER_DESKTOP_QUIT = 2,    ## 用户主动退出到操作系统桌面
	WINDOW_CLOSE_REQUEST = 3, ## OS 窗口右上角 "X" 关闭请求
	FATAL_EXCEPTION = 4,      ## 核心系统崩溃导致的不可恢复停机
	REMOTE_KICK_OUT = 5       ## 远端服务端踢出或会话顶替
}
```

### 2. 退出协议请求与响应 DTO (Shutdown DTOs)

```gdscript
# 模块路径: res://backend/domains/lifecycle/dto/game_shutdown_dto.gd
class_name GameShutdownRequestDTO
extends RefCounted

var session_token: String = ""             # 发起退出的客户端会话凭据
var account_id: String = ""                # 目标账号 ID
var exit_reason: int = GameLifecycleModel.ExitReason.USER_DESKTOP_QUIT
var target_save_slot: String = ""          # 退出前需强制持久化的槽位（为空则取当前活跃槽位）
var idempotency_key: String = ""           # 客户端生成的 UUID 防重标识
var force_timeout_seconds: float = 5.0     # 客户端要求的超时放弃阈值（由配置驱动注入）
var timestamp_utc: int = 0                 # 客户端发起时间戳

func to_dto() -> Dictionary:
	return {
		"session_token": session_token,
		"account_id": account_id,
		"exit_reason": exit_reason,
		"target_save_slot": target_save_slot,
		"idempotency_key": idempotency_key,
		"force_timeout_seconds": force_timeout_seconds,
		"timestamp_utc": timestamp_utc
	}

static func from_dto(data: Dictionary) -> GameShutdownRequestDTO:
	var req := GameShutdownRequestDTO.new()
	req.session_token = String(data.get("session_token", ""))
	req.account_id = String(data.get("account_id", ""))
	req.exit_reason = int(data.get("exit_reason", GameLifecycleModel.ExitReason.USER_DESKTOP_QUIT))
	req.target_save_slot = String(data.get("target_save_slot", ""))
	req.idempotency_key = String(data.get("idempotency_key", ""))
	req.force_timeout_seconds = float(data.get("force_timeout_seconds", 5.0))
	req.timestamp_utc = int(data.get("timestamp_utc", 0))
	return req
```

```gdscript
# 模块路径: res://backend/domains/lifecycle/dto/game_shutdown_dto.gd
class_name GameShutdownResponseDTO
extends RefCounted

var success: bool = false
var error_code: String = "OK"              # 错误码（OK, ALREADY_STOPPING, SAVE_FAILED, TIMEOUT）
var current_phase: int = GameLifecycleModel.LifecyclePhase.STOPPED
var is_save_completed: bool = false        # 是否已成功完成原子存档落盘
var save_sha256: String = ""               # 退出存档生成的校验散列
var remaining_resources: Array[String] = []# 尚未完全释放的孤儿资源名称
var elapsed_milliseconds: int = 0          # 停机整个过程耗时（毫秒）

func to_dto() -> Dictionary:
	return {
		"success": success,
		"error_code": error_code,
		"current_phase": current_phase,
		"is_save_completed": is_save_completed,
		"save_sha256": save_sha256,
		"remaining_resources": remaining_resources.duplicate(),
		"elapsed_milliseconds": elapsed_milliseconds
	}

static func from_dto(data: Dictionary) -> GameShutdownResponseDTO:
	var resp := GameShutdownResponseDTO.new()
	resp.success = bool(data.get("success", false))
	resp.error_code = String(data.get("error_code", "OK"))
	resp.current_phase = int(data.get("current_phase", GameLifecycleModel.LifecyclePhase.STOPPED))
	resp.is_save_completed = bool(data.get("is_save_completed", false))
	resp.save_sha256 = String(data.get("save_sha256", ""))
	var raw_res: Array = data.get("remaining_resources", [])
	resp.remaining_resources = []
	for r in raw_res:
		resp.remaining_resources.append(String(r))
	resp.elapsed_milliseconds = int(data.get("elapsed_milliseconds", 0))
	return resp
```

### 3. 停机资源描述符与清理任务 (ShutdownResourceDescriptor)

```gdscript
# 模块路径: res://backend/domains/lifecycle/shutdown_resource_descriptor.gd
class_name ShutdownResourceDescriptor
extends RefCounted

var resource_id: String = ""               # 资源唯一标识（如 "persistence_flush", "event_bus_clear"）
var priority: int = 100                    # 清理优先级（数值越大越先执行）
var timeout_ms: int = 2000                 # 单项资源清理超时时间（毫秒）
var is_critical: bool = true               # 是否为关键资源（关键资源失败会促发 STOP_FAILED）
var cleanup_action: Callable = Callable()  # 清理具体回调函数

func _init(id: String, prio: int, critical: bool, action: Callable, timeout: int = 2000) -> void:
	resource_id = id
	priority = prio
	is_critical = critical
	cleanup_action = action
	timeout_ms = timeout
```
