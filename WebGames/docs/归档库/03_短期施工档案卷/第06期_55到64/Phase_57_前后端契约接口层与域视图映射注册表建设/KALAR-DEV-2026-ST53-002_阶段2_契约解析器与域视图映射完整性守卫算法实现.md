## 📌 第一性原理溯源指针

* **精准上游证据指针**：
  - `docs/audit/AUDIT_REPORT_UI缺失.md:165-167`：三份审计共同指向「契约层缺失」需从"定义契约"进一步到"落地契约解析"；
  - `backend/domains/character_creation/`（16 文件 / 43 静态方法）：PARTIAL 域最严重案例，说明"契约完整性守卫"能实时暴露"骨架 vs 能力"的偏差；
  - `backend/domains/contract_registry/`（Phase 57 S1 建立的域目录）：本阶段直接消费其数据契约；
  - Phase 47 S2 `GameModeRoutingSolver` 的**模式路由求解器**范式：本阶段事件路由与命令分发复用该单点路由范式。

* **核心不变量约束断言**：
  - `Inv-CP-1`（字段映射类型安全）：任一 DTO 字段映射在应用 `transform_kind` 前**必须**校验后端字段类型与契约声明一致，类型不匹配返回 `CT_ERR_SCHEMA_INVALID` 而非崩溃；
  - `Inv-CP-2`（事件路由幂等）：任一 EventBus 事件在同一次 dispatch 中**必须**只被处理一次，重复订阅同一事件不产生重复 signal 广播；
  - `Inv-CP-3`（命令分发前置校验）：任一 UI Command 在调用后端 Service 前**必须**通过 `params_schema`（Phase 55 S1 VD_* 值域范式复用）校验，非法参数被拒绝且返回可展示的错误码；
  - `Inv-CP-4`（完整性守卫单向可见）：契约完整性守卫**只读**、**不修改**注册表条目，其输出（缺失清单）以独立快照 DTO 形式暴露；
  - `Inv-CP-5`（缓存有界与副本返回）：索引缓存**必须**有界（LRU 上限 = 128 条），查询结果**必须**返回副本而非内部引用（Phase 56 S3 已建立的容器返回副本范式）；
  - `Inv-CP-6`（契约解析器单点路由）：字段映射 / 事件订阅 / 命令分发**必须**经唯一 `ContractRegistryIndex` 路由，禁止绕过注册表直接访问后端 Service（防伪造）。

* **防漂移最高指示**：
  - 本阶段**只**实现解析器与守卫算法，**不**修改任何实际视图 `.gd`/`.tscn` 的接线逻辑；接线层留给 Phase 58/59/60；
  - 解析器不实现任何真实的字段转换规则（`transform_kind` 除 `identity` 外其他值暂返回未决标记 `UNSUPPORTED`，由后续 Phase 消费时扩展）；
  - 严禁将本阶段扩展为"契约层端到端接线"——那是 Phase 58 起的核心任务。
