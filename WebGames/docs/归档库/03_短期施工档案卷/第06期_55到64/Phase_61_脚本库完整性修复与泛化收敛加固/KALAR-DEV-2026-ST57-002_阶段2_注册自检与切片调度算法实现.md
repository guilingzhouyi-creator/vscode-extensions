### R2 `--slice` 实现（`audit_runner.py:395-430`，减法过滤）

```python
# 伪契约（特化，非占位）：slice_norm = args.slice.strip().lower()
# 命中谓词：slice_norm in t.task_id.lower() or slice_norm in t.script_name.lower() or slice_norm in {s.lower() for s in t.scopes}
# 生效点：仅当无 --task/--group/--diff 时；命中空集 → 打印可选 task_id 列表并 return 2
```

`--diff` 三要素（`changed_scopes/engine_hits/scripts_need_full`）语义保持原样；`--baseline` 覆盖仅改 `docs` 任务且复制列表后赋值（避 `default_args` 共享突变）。

### R3 并发保序（维持 `ProcessPoolExecutor`，不迁 `ThreadPool`）

实证：任务体为 `python -X utf8 <engine>` 重进程，`ProcessPool` 规避 GIL 且与现有 `--jobs` 语义兼容；`ThreadPool` 省 fork 但受 GIL 限且改动面大。收敛为文档化决策 + `workers = min(cpu, len(tasks))` 保持。`exclusive` 先行串行逻辑不变。

### R4 样板收敛（仅常量，不抽执行流）

`audit_common.py` 增三常量：`GD_LOOP_HEAD_RE`、`GD_GAMECONFIG_GETTER_RE`、`KALAR_DEV_PREFIX` 已有复用；`audit_perf_hotspots.py:31`、`audit_gd.py:42` 改引用常量，正则语义逐字符一致。`Finding` 不强制统一（各脚本 `severity` 谱系不同，强统属过度设计）。

### R5 桥接增强（`audit_refactor_metrics.py`）

* 新增 `--analyzers complexity,large-file,constants,governance` 透传（缺省全量），`subprocess` 命令追加 `--config WebGames/auto-refactor.config.json`（S3 产出）；
* 输出增 `governance` 分组 Top3（`GOV-PRF/LOG/STD`），`byAnalyzer.governance` 缺席即提示“引擎未启用治理层”；
* JSON 解析容错：`json.loads` 失败时尝试 `raw[raw.find("{"):raw.rfind("}")+1]` 二次解析，仍失败则打印前 800 字符并降级 `return 0`（上游 `reporters.ts` 转义 bug 由 auto-refactor 侧另修，本脚本不吞错）。
