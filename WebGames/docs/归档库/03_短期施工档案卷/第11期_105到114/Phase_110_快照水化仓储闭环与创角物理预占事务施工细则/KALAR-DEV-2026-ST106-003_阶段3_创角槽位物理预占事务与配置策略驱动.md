## 一、 创角物理预占事务与配置驱动设计 (Slot Provisioning & Config-Driven Design)

### 1. 配置策略扩展 (`config/domains/account/core.json`)

在 `save_slot` 节流配置节点扩展物理预占策略与初始档案模板参数：

```json
  "save_slot": {
    "max_slots": 3,
    "id_prefix": "SLOT_",
    "auto_provision_disk": false,
    "provision_template": {
      "level": 1,
      "gold": 0
    },
    "unwired_policy": {
      "require_explicit_character_name": false,
      "require_explicit_world_ref": false
    }
  }
```

* `auto_provision_disk` (bool): 全局创角物理预占开关，缺省为 false，由业务场景按需显式指定或由特定配置驱动开启；
* `provision_template` (Dictionary): 预占角色初始数值基础模板，声明初始等级与金币等不可或缺的核心数据结构。

### 2. 解算器领域门面预加载与解耦

为了确保解算器符合架构护栏（`TC-ARCH-08A` 严禁直接引用 `res://backend/infrastructure/`），所有持久化与仓储交互均经由领域层门面与仓储单例完成：

```gdscript
const AccountRepository = preload("res://backend/domains/account/account_repository.gd")
const SaveDataAccessLayer = preload("res://backend/domains/persistence_protocol/save_data_access_layer.gd")
```

### 3. 创角物理预占事务执行链路 (`create_character_in_slot`)

```text
                     create_character_in_slot(account, slot_id, name, ..., provision_disk)
                                                      │
                                           账号与槽位合法性前置卫语句
                                                      │
                                           构建 SaveSlotSummaryDTO
                                                      │
                                           account.bind_character_to_slot(...)
                                                      │
                                         是否触发磁盘预占？
                                    (provision_disk or auto_provision_disk)
                                   ┌──────────────────┴──────────────────┐
                                   ▼                                     ▼
                                [是: 物理预占]                     [否: 跳过预占]
                                   │                                     │
                     构建 init_payload (含等级/金币)                       │
                                   │                                     │
                     SaveDataAccessLayer.save_game(slot_id, payload)     │
                                   │                                     │
                     绑定 save_file_sha256 签名                           │
                                   └──────────────────┬──────────────────┘
                                                      │
                                           AccountRepository 同步
                                  (若 repo.has_account 则 repo.save_account)
                                                      │
                                           ensure_account_world_ref
                                                      │
                                           返回成功与预占执行摘要
```

* **磁盘物理落盘**：调用 `SaveDataAccessLayer.save_game(slot_id, init_payload)`，底层自动完成运行模式校验、非空载荷审查、SHA-256 计算与原子替换（tmp->bak->rename）；
* **签名回灌**：若预占成功，将返回的摘要哈希注入 `dto.save_file_sha256`；
* **账号仓储同步**：若底层 `AccountRepository.get_instance().has_account(account.account_id)`，调用 `repo.save_account(account)` 将新绑定的槽位摘要同步刷盘与更新内存双层索引；
* **快捷创建与解绑联动**：`quick_create_in_next_slot` 透传 `provision_disk` 参数；`clear_slot` 解绑后同样触发 `repo.save_account(account)` 保证注销状态磁盘同步。
