## 二、核心数据契约

### GAP-02 修复契约

| 契约对象 | 修复前 | 修复后（不变量） |
| :--- | :--- | :--- |
| `GroundLootPickupSolver.attempt_pickup` | 调用 `inventory.add_item_to_backpack(drop.item_entity)` | 调用 `inventory.add_item(drop.item_entity)` |
| 接口语义 | `add_item_to_backpack` 隐含"只加入背包格"语义 | `add_item` 遵循 `WearableInventoryAggregate` 统一入口，负重/容量同路径检定 |
| 修复范围 | 仅修改调用接口名 | 不改变地面拾取的四步检定逻辑（衰变/距离/归属/容量）；不新增背包逻辑 |

### GAP-01 修复契约

| 契约对象 | 必须字段 | 边界不变量 |
| :--- | :--- | :--- |
| `ItemStatisticsSolver.record_item_event` 调用位置 | `library`（可空）、`EVENT_ITEM_GRANTED`、`canonical_id`（来自 `drop.item_entity.template_id`）、`quantity=1` | 仅在 `attempt_pickup` 成功路径（返回 `success:true` 且 `picked_item != null`）后调用；`library` 为 null 时跳过，不阻塞拾取主流程 |
| 对称性保证 | mail/gacha/quest/shop 已有接入点 | 地面拾取补入后，全部六条获取路径统计台账完整对称 |

### GAP-04 修复契约

| 契约对象 | 必须接口 | 边界不变量 |
| :--- | :--- | :--- |
| `GenericAffixSolver.roll_random_affixes` | `(monster_tier: int, count: int, rng: DeterministicRNG) -> Array[String]` | 词缀池与权重由 `config/domains/elite.json` 的 `affix_pool` 段驱动；零硬编码；无词缀池时返回空数组，不崩溃 |
| 权重分布 | 各 `aff_id` 在 `affix_pool` 中含 `weight` 字段 | 按权重加权随机选取，使用 `DeterministicRNG.pick_weighted` 复用确定性PRNG体系；`apply_elite_affixes` 仍保留（外部精确覆盖场景） |
| 算法主权 | 后端控制概率分布 | 调用方只传 `monster_tier` 和 `count`，不传 `affix_ids` 列表 |

### GAP-03 修复契约

| 契约对象 | 必须字段 | 边界不变量 |
| :--- | :--- | :--- |
| `CommissionFSM.accept_commission` | 新增 `transaction_id: String = ""` 参数 | `_completed_transactions` 静态字典检查（与 workshop/gacha 同模式）；重复提交直接返回缓存结果 |
| `CommissionFSM.settle_successful_commission` | 新增 `transaction_id: String = ""` 参数 | 同上 |
| `CommissionFSM.handle_commission_breach` | 新增 `transaction_id: String = ""` 参数 | 同上；保证金没收幂等 |
| 键格式 | `"COMMISSION_{action}_{commission_id}_{Time.get_ticks_usec()}"` | 与 workshop/gacha 键格式对齐 |

### GAP-05 修复契约

| 契约对象 | 接口设计 | 边界不变量 |
| :--- | :--- | :--- |
| `EventBus.emit_domain_event("monster.killed", {...})` | payload 含 `drop_declarations: Array[Dictionary]`，每项含 `canonical_id`、`display_name`、`position`、`killer_id`、`decay_cat` | `monster.killed` 事件由战斗结算方发出；`GroundDroppedItemAggregate.create_from_declaration` 在事件监听器内调用 |
| 监听器位置 | `backend/domains/ground_loot/` 新增 `ground_loot_event_listener.gd` | 职责单一：只监听 `monster.killed`，调用 `create_from_declaration` 并组装聚合根；不引入新的跨域依赖 |

### GAP-06 职责边界文档化契约

| 路径 | 定位 | 约束 |
| :--- | :--- | :--- |
| `chat_command/reward_dispatch_pipeline.gd` | **开发/测试通道**（Dev Channel）| 只允许在开发/测试环境下使用；不接入运营CDKey统计/时效/频控；文件头注释显式标注 `# [DEV CHANNEL] 非运营正式通道` |
| `cdkey_voucher/cdkey_redemption_solver.gd` | **运营正式通道**（Production Channel）| 全部运营CDKey兑换必须经此域；含复合门槛/时效/频控/全服上限/邮件发放 |
| 不做代码删除 | 保留 chat 路径代码 | 仅添加注释文档化，不删除也不合并，避免引入不可控回归 |

## 三、依赖与职责边界（修复不变量）

1. **GAP-02**：`GroundLootPickupSolver` 只修改 `add_item_to_backpack` → `add_item` 一处调用，不改变四步检定逻辑。
2. **GAP-01**：`record_item_event` 接入在 `attempt_pickup` 成功路径追加，`library` 参数可空注入（测试确定性），不影响未传 `library` 的现有调用方。
3. **GAP-04**：`roll_random_affixes` 为新增入口；`apply_elite_affixes` 保留，不删改现有接口；`elite.json` 新增 `affix_pool` 段，不修改现有段结构。
4. **GAP-03**：`CommissionFSM` 仅追加幂等检查，不修改业务判定逻辑；保证金扣减/奖励入账/违约逻辑不变。
5. **GAP-05**：新增 `GroundLootEventListener` 为独立文件，通过 `EventBus` 解耦，不在 `MonsterAggregateEntity` 内添加掉落钩子（防止怪物域污染地面拾取域）。
6. **GAP-06**：只加注释，不改代码，不删代码；两套路径不合并。
