## 一、配置映射契约

| 配置段 | 新增或收口字段 | 约束 |
| :--- | :--- | :--- |
| `domains.cdkey_voucher` → `eligibility_rules` | `combinator`（AND/OR）、`rules`（rule_id/metric_key/operator/value）、`scope` 标注 | combinator 只允许 AND/OR；operator 白名单 gte/lte/eq/neq/contains；规则 ID 作用域内唯一 |
| 全局/兑换码级作用域 | `scope_type`（GLOBAL/VOUCHER） | 兑换码级规则经兑换码聚合字段承载，按 key 覆盖全局；默认无配置 = 默认允许 |
| 兼容策略 | `schema_version`（规则段版本） | 规则段结构变更递增版本；旧配置按默认值兜底，不静默丢弃 |

## 二、热重载与快照流程

1. `GameConfig` 完成规则段解析与类型校验后发布带版本号的快照事件（复用 Phase 31 ConfigReloadResult）。
2. 规则段任一字段非法时保留上一份有效快照并输出结构化诊断；生产模式不得静默回退到代码默认值。
3. 向后兼容：旧版配置（缺新字段）按默认值补齐；版本不兼容配置受控拒绝并记录迁移提示。

## 三、异步、持久化和监控

- 规则判定为同步纯函数（无 IO），未达标路径零持久化写入。
- 非法配置拒绝与兼容兜底写入结构化日志：记录表名、版本、违规字段与处理动作，载荷不含隐私。
- 监控指标至少包括 `rule_config_reject_count`、`rule_scope_override_count`、`rule_fallback_count`，指标名 `snake_case`。
- `audit_config.py` 规则段结构校验泛化：未知字段、字段类型、operator 白名单、组合合法性与作用域标注存在性。
