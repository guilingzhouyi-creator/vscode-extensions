## 一、EquipmentFSM 镜像同步算法（N1 核心）

`backend/domains/equipment_loadout/equipment_fsm.gd` 两个入口按阶段1 §2.3 时序重写，骨架（全部为既有 API 组合，零新增基础设施）：

```gdscript
# equip_from_inventory（换装分支，省略前置卫语句）
var inv_snapshot := inventory.snapshot()
var loadout_snapshot := loadout.slots.duplicate()
if not inventory.remove_item(item): return {...ITEM_NOT_IN_INVENTORY}
var inv_old = inventory.unequip_item(slot_name)   # 槽位不在容量键集时返回 null，容忍
if inv_old != null and old_item != null and inv_old != old_item:
    inventory.restore(inv_snapshot); loadout.slots = loadout_snapshot
    return {"success": false, "error_code": "EQUIP_STATE_DIVERGENCE"}
if not inventory.equip_item(slot_name, item):
    inventory.restore(inv_snapshot); loadout.slots = loadout_snapshot
    return {"success": false, "error_code": "EQUIP_SYNC_FAILED"}
if not inventory.can_add_item(old_item):          # 此刻容量已按新穿戴计——真正的守卫点
    inventory.restore(inv_snapshot); loadout.slots = loadout_snapshot
    return {...INVENTORY_CAPACITY_EXCEEDED}
if not inventory.add_item(old_item):              # 双保险，失败同路径回滚
    inventory.restore(inv_snapshot); loadout.slots = loadout_snapshot
    return {...INVENTORY_CAPACITY_EXCEEDED}
loadout.equip(slot_name, item)
if loadout.get_equipped_item(slot_name) != item:  # 提交确认（既有模式保留）
    inventory.restore(inv_snapshot); loadout.slots = loadout_snapshot
    return {"success": false, "error_code": "EQUIP_COMMIT_FAILED"}
```

* 卸下路径 `unequip_to_inventory`：先 `unequip_item(slot)`（释放 UID 与容量贡献）再 `can_add_item/add_item`，`loadout.unequip` 在容量检定**通过后**执行，失败回滚双侧。
* 空槽直穿（old_item == null）分支同样补 `equip_item` 同步，失败码 `EQUIP_SYNC_FAILED`。
* `EquipmentLoadoutAggregate` 新增 `unequip_item_ref(item: ItemEntity) -> String`：按实例引用反查槽位并卸下，返回槽位名（供处置销毁联动），未命中返回空串。

## 二、处置逐件发放与双侧销毁（N3）

`backend/domains/matter_disposal/disposal_pipeline.gd`：

1. 签名追加可选参 `loadout: EquipmentLoadoutAggregate = null`（既有调用方不破坏）。
2. 产物构建：`for i in res.yield_slag_ash_count` 逐件 `ItemInstanceFactory.build_instance(slag_proto, _msg("slag_ash_name"), "DSP_")`（每件独立 UID），逐件覆写历史 `item_id`；dust 同理。
3. 移除输入：`_remove_owned_item` 命中穿戴槽时，除 `container_state="DESTROYED"` 外追加 `loadout.unequip_item_ref(item)` 双侧清槽（loadout 为 null 时仅 inventory 侧，兼容旧调用）。
4. 容量预检改为**逐件顺序模拟**：按 slag→dust 顺序逐件 `add_item`，任一件失败即 `inventory.restore(snapshot)` 整体回滚并返回 `INVENTORY_CAPACITY_INSUFFICIENT`（替代原「先加 slag 再试 dust」的等价但难读写法）。
5. 最终回流逐件 `add_item`（容量已由模拟保证，失败仍按 `PRODUCT_ADD_FAILED` 回滚防御）。
6. 删除 `:42-43` 的 `yield_mass/*` 死读取；`config/domains/matter_disposal.json` 移除 `yield_mass` 段。
