## 一、立项范围与需求溯源

本卷承接需求 P「后端魔法体系升级与细化」，核心目标不是新增若干技能效果，而是建立一套可持续扩展的**统一魔法规则后端**：以既有位阶魔法体系（`MagicTierSnapshot` / `MagicTierRegistry` / `magic_tiers.json`）为位阶真源，在其上新增**魔法属性大类（光/暗）与派生变体（神圣/暗黑）**、**几重化**、**封印与解放**、**升格化**、**延时**五组可配置规则能力，并以统一模型（定义/属性变体/位阶/行动卡/条件/状态/触发器/结算器）承载。

**术语对齐（真源）**：
- 「位阶魔法大类 / 法式魔法 / 变体」层级 → 对应既有 `MagicForm`（始源/咒术/集成/超位）与「咒术魔法 → 术式/法式 → 位阶魔法/元素规范魔法」需求表述；神圣系、暗黑系是**该体系内的进一步变体**，而非与光/暗平行的新顶层架构。
- 「位阶」→ 既有 `MagicRank`（连续 1~11 阶）+ `magic_tiers.json` 的 `rank_gradient`（`strength_weight` 等），为独立数据维度。
- 「行动卡」→ 一次行动行为载体（后端尚无成型实现，本卷给出统一契约），与玩法稿 AP/手牌语义衔接。

**不在本卷范围**：前端表现层行动卡 UI、联机权威仲裁、技能树/自创技能系统、物理动词结算公式本身（仅引用不重写）。

## 二、魔法属性大类与派生变体契约

### 2.1 两套基础魔法体系（顶层属性大类）

| 大类 | 成员属性 | 设计语义 |
| :--- | :--- | :--- |
| 光系（LIGHT_SCHOOL） | 金（GOLD）/ 木（WOOD）/ 水（WATER）/ 火（FIRE）/ 土（EARTH） | 规范元素法式的基础集合之一；成员数量可配置 |
| 暗系（DARK_SCHOOL） | 风（WIND）/ 雷（THUNDER） | 同上，成员数量可配置 |

- 成员清单**配置化**（`attribute_schools` 段），禁止以「恰五/恰二」等固定数量作为代码不变量——数量、组合全部由配置描述。
- 每一属性为独立 `MagicAttribute` 条目（含 canonical 键、名称键、归属大类、排序），用于魔法定义、变体条件与文案。

### 2.2 派生体系（融会贯通 → 变体）

| 派生体系 | 融会贯通来源 | 归属层级 | 说明 |
| :--- | :--- | :--- | :--- |
| 神圣系（HOLY） | 光系相关体系完成融会贯通 | 位阶魔法大类→法式魔法→**变体** 的进一步变体 | 不是与光系平行的顶层 |
| 暗黑系（ABYSSAL） | 暗系相关体系完成融会贯通 | 同上 | 同上 |

- **融会贯通是「可配置的体系演化条件」**：由 `fusion_conditions`（条件组合，复用 Phase 36 规则引擎 AND/OR/NOT 组合语义）描述——满足条件后相关魔法获得对应派生变体标记，**严禁把「固定属性数量/固定属性组合」写死进系统唯一规则**。
- 变体影响位阶的既有不变量：派生变体魔法仍须遵守 `MagicTierSnapshot.is_god_form_pair_valid`（高阶 RANK_10/11 必须配对 SUPERTIER 形态）等从属约束。

### 2.3 法式变体语义

- 「变体」在本模型中是一组**派生标记 + 配置化修正**（威力倍率/能损/文案等），挂在既有属性/位阶维度之上；`MagicForm` 不新增枚举值（避免破坏既有 4 形态不变量），变体通过 `variant_of_form` 关联既有形态表达。
- 未定义明确的变体派生规则 → 登记为**待定义边界**（见 2.4），引擎不创造隐含规则。

### 2.4 待定义边界登记（本阶段明确开放项）

| 边界 ID | 内容 | 处置 |
| :--- | :--- | :--- |
| `BND-41-FUSION-01` | 光系五属性「全部达成」还是「子集达成」即融会贯通，未获业务裁决 | 配置预留 `fusion_mode`（ALL/ANY/自定义条件组），默认 ANY+显式条件，运行时按配置执行；默认示例值不视为唯一规则 |
| `BND-41-VARIANT-02` | 神圣系变体与暗黑系变体之间是否存在互斥/转换关系 | 引擎只做派生标记叠加，关系语义留待后续案卷 |

## 三、统一规则模型 —— 八职责对象契约

| 职责对象 | 建议文件（backend/domains/magic_system/） | 数据契约要点 |
| :--- | :--- | :--- |
| 魔法定义 | `magic_definition.gd` | `canonical_id`、`form`（引用 MagicForm）、`attribute`（引用 MagicAttribute 键）、`base_rank`、`resource_cost`（配置键）、`effect_profile`（结算参数键）、版本号 |
| 属性/变体 | `magic_attribute_school.gd` | 大类成员表 + 派生体系声明（source/派生标记/fusion_conditions） |
| 位阶 | 复用 `MagicTierRegistry` | 独立数据维度：rank 1~11、strength_weight、band、god-form 不变量 |
| 行动卡 | `action_card_definition.gd` | 一次行动行为：`card_id`、`card_type`（NORMAL/SEAL/ASCEND/DELAY/RELEASE）、`magic_ref`、`casts_per_play`（几重化）、`consumes_play`（恒 1） |
| 条件 | `magic_rule_condition.gd` | 组合条件树（AND/OR/NOT/LEAF），用于升格资格/融会贯通/延时释放校验 |
| 状态 | `magic_rule_state.gd` | 持续语义载体：seal_state / delay_state / variant_flags；持有对象、来源 card、时间/步数、清理钩子 |
| 触发器 | `magic_rule_trigger.gd` | 延时到期强制打出等待触发调度，非阻塞式队列（step 单位） |
| 结算器 | `magic_settlement_solver.gd` | 统一最终效果计算：位阶/属性变体/强化/状态叠加求值，纯函数 + 可空注入 RNG/上下文 |

**关键不变量（跨职责）**：
1. 位阶永远作为独立维度参与计算，升格不得产生「复制整卡」的新卡实例；
2. 封印/延时等持续语义必须建模为**状态持续存在**，禁止复制新卡表达；
3. 行动卡消耗次数与实际魔法攻击次数严格分离：任何机制下「一次行动卡打出」恒对应 `consumes_play = 1`；
4. 所有数值、数量、组合、上限一律配置化，禁止硬编码为系统唯一规则；
5. 未定义组合语义 → 显式返回「待定义边界」结果码，禁止引擎自造隐含规则。
