## 三、统一规则注册表：`MagicRuleRegistry`

对标 `MagicTierRegistry`（`item_namespace_registry/magic_tier_registry.gd`）的装配模式：

```gdscript
# backend/domains/magic_system/magic_rule_registry.gd
class_name MagicRuleRegistry extends RefCounted
const CONFIG_TABLE: String = "domains.magic_rules"

var _schools: Dictionary = {}    # school_id -> {members, name_key}
var _attributes: Dictionary = {} # attribute_id -> {school, name_key}
var _variants: Dictionary = {}   # variant_id -> {source_schools, fusion_mode, fusion_conditions, ...}
var _multi_cast: Dictionary = {}
var _seal: Dictionary = {}
var _ascension: Dictionary = {}
var _delay: Dictionary = {}
var _combo_semantics: Dictionary = {}
var _ready: bool = false

func reload_configuration() -> void
func is_ready() -> bool
# 查询入口（全部类型化读取，禁 Variant get_value 直读配置）
func get_school(school_id: String) -> Dictionary
func get_attribute(attribute_id: String) -> Dictionary
func get_variant(variant_id: String) -> Dictionary
func combo_semantic(combo_key: String) -> String   # DEFINED/PARTIAL/BND_NOT_DEFINED
```

**装配接入**：`GameBootstrap.assemble()` 中紧随 `MagicTierRegistry` 之后创建并 `reload_configuration()`；未就绪（结构不变量失败）即阻断装配（与魔法位阶注册表同款「不暴露半成品」策略）。同时提供 `magic_rules()` 静态访问器。

## 四、结构审计与校验（audit_config 扩展）

在 `scripts/py/audit_config.py` 的规则段校验登记 `domains.magic_rules` 结构检查：

| 校验项 | 断言 |
| :--- | :--- |
| 段存在性 | `attribute_schools` / `attributes` / `variants` / `multi_cast` / `seal` / `ascension` / `delay` / `combo_semantics` 全部存在且为对象 |
| 成员引用闭合 | `attributes[].school` 与 `attribute_schools` 键一一对应；`variants[].source_schools[]` 均在 `attribute_schools` 内 |
| 键型约束 | 数值键为 int/float 且取合法域（max_casts 1~10、max_rank 1~11、delay min<=max 等）；布尔键为 bool |
| 条件树 | `fusion_conditions`/`ascension.conditions` 结构合法（op ∈ AND/OR/NOT/LEAF；LEAF 含 kind 与 args） |
| 变体归属 | `variant_of_form` 取值于既有 MagicForm 数值（1~4），禁止新增枚举越界 |
| 组合语义枚举 | `combo_semantics` 取值 ∈ DEFINED/PARTIAL/BND_NOT_DEFINED |

**热重载**：`GameConfig.reload_config()` 原子交换后若 `magic_rules` 变更，注册表快照随重载刷新；坏快照保留旧版本（复用 GameConfig 既有守卫），注册表 `_ready=false` 时查询返回受控失败而非陈旧半成品。

## 五、零硬编码与文案

- 全部规则参数、数量、组合、上限、变体派生标记读取自 `domains.magic_rules`；位阶强度权重等仍读 `domains.magic_tiers`（单一真源，禁止双份拷贝）。
- 文案/名称一律经 i18n `zh_CN.json` 键（`magic.school.*`/`magic.attr.*`/`magic.variant.*`）与 `GameConfig.msg`/`EventBus.render_narrative` 渲染，代码零中文/数值字面量。
- audit_hardcode / audit_gd 门禁对 `backend/domains/magic_system/` 零新增违规。

## 六、可扩展性设计（引擎层扩展点）

| 扩展场景 | 做法 | 改动面 |
| :--- | :--- | :--- |
| 新增魔法 | 配置新 `MagicDefinition` + 效果参数 | 零引擎改动 |
| 新增属性/属性大类 | 配置 `attributes` + `attribute_schools` | 零引擎改动 |
| 新增变体 | 配置 `variants`（源体系 + 融会贯通条件） | 零引擎改动 |
| 新增位阶语义 | 复用 `magic_tiers.json`（引擎不复制阶位表） | 配置改动 |
| 新增行动卡机制 | 新增 `card_type` 枚举值 + 对应求解器子类，注册进调度/结算管线 | 一处注册点 |
| 未定义组合 | 登记 `BND_NOT_DEFINED`；查询返回 `BND_NOT_DEFINED` 结果码 | 配置标注，不造隐含规则 |
