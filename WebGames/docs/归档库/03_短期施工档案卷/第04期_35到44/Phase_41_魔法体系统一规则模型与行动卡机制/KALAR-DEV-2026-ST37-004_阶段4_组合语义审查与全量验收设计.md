## 二、组合语义审查矩阵（需求 P 第 7 节逐项判定）

| 组合键 | 组合 | 语义判定 | 明确语义 / 边界处置 |
| :--- | :--- | :---: | :--- |
| `multi_x_ascend` | 几重化 × 升格化 | ✅ DEFINED | 升格化先于几重化生效（升格改变魔法位阶维度）；几重化打出时按**当前位阶**对全部 N 次攻击统一结算；同一次几重化内不逐击升格。 |
| `ascend_x_delay` | 升格化 × 延时 | ✅ DEFINED | 升格不影响已排程延时；延时释放属性快照取 `attribute_snapshot`——`AT_RELEASE` 时按释放瞬间位阶结算（升格在延时期间发生则生效），`AT_CAST` 按创建快照。 |
| `seal_x_delay` | 封印 × 延时 | ✅ DEFINED | 封印状态中的魔法**不可被选择为延时目标**（封印优先，返回 `SEALED_MAGIC_UNPLAYABLE`）；已排程的延时魔法在释放前被封印 → 按 `seal.release_fail_policy` 等价处置（默认取消延时并清理，不产生双重占用）。 |
| `seal_x_ascend` | 封印 × 升格化 | ✅ DEFINED | 封印中的魔法**不可升格**（封印锁定该魔法当前位阶与可用性，返回 `SEALED_MAGIC_UNPLAYABLE`）；升格化必须先解放后再升格。 |
| `seal_x_multi` | 封印 × 几重化 | ✅ DEFINED | 封印中的魔法不可作为几重化目标（封印锁定打出权）；几重化进行中不可插入封印（一次性事务，无中间态）。 |
| `delay_x_multi` | 延时 × 几重化 | ✅ DEFINED | 延时卡可携带几重化配置（`casts_per_play` 随延时状态持久化）；释放瞬间按当时 `casts_per_play` 触发 N 次攻击，仍只计一次行动消耗；`multi_cast.allow_with_delay` 需为 true。 |
| `fusion_x_rank` | 融会贯通 × 位阶变化 | ⚠️ PARTIAL | 融会贯通产生**派生变体标记**（属性体系维度），位阶为独立维度；已融会贯通的魔法升格不丢失变体标记；升格不影响已达成融会贯通资格。**未定义边界**：融会贯通条件中含「某位阶以上」类型的门槛时，升格后的位阶变化是否即时重算已达成变体——登记 `BND-41-FUSION-RANK-01`，默认引擎只做标记持久化，不自动撤销/追授变体。 |

**审查结论**：六组组合语义明确一致（DEFINED），一组（`fusion_x_rank`）部分明确并显式登记待定义边界。引擎层组合查询统一经 `combo_semantic(combo_key)` 返回 DEFINED/PARTIAL/BND_NOT_DEFINED，不静默猜测。

## 三、待定义边界登记表（引擎可扩展承诺）

| 边界 ID | 组合/场景 | 当前处置 | 后续扩展点 |
| :--- | :--- | :--- | :--- |
| `BND-41-FUSION-01` | 融会贯通达成模式（ALL/ANY/自定义） | 配置 `fusion_mode` 驱动，默认 ANY | 新增条件组合种类无需改引擎 |
| `BND-41-FUSION-RANK-01` | 融会贯通门槛含位阶条件时升格是否即时重算 | 标记持久化，不自动撤销/追授 | 派生变体资格重算器（后续案卷） |
| `BND-41-VARIANT-02` | 神圣/暗黑变体间互斥或叠加 | 派生标记独立叠加，不设互斥 | 变体关系规则配置（后续案卷） |
| `BND-41-SEAL-DUR-01` | 封印默认持续时间跨场景语义 | `default_duration_seconds=0` 场景内常驻 | 跨场景封印持久化（联机案卷） |

> 上述边界全部以「引擎返回受控结果码 + 配置标注」承接，任何一层不得自行创造隐含规则。
