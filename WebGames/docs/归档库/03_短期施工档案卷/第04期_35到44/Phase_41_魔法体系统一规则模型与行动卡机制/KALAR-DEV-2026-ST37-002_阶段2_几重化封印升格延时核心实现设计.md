## 二、魔法几重化（Multi-Cast）实现设计

### 2.1 语义

**一次行动卡打出 → 同一选定魔法同时发动 1~5 次攻击（次数配置上限）**。无论实际发动几次，都只消耗 1 张行动卡（`consumes_play = 1`），**不等价于连续打出多张行动卡**。

核心分离项：

| 维度 | 契约 | 配置来源 |
| :--- | :--- | :--- |
| 行动消耗次数 | 恒 1（一次行动卡打出） | 硬不变量，代码强制 |
| 实际魔法攻击次数 | `casts_per_play`（1~max） | `multi_cast` 段 `max_casts` / 单卡 `casts_per_play` |

### 2.2 求解器接口设计

```gdscript
# backend/domains/magic_system/multi_cast_solver.gd
class_name MultiCastSolver extends RefCounted

## 校验一次几重化打出的合法性（次数上限/资源/目标）
static func validate_play(card: ActionCardDefinition, ctx: MagicCastContext) -> Dictionary
## 执行一次打出：返回 N 次攻击的结构化结算序列
static func execute_play(card: ActionCardDefinition, ctx: MagicCastContext, rng: DeterministicRNG = null) -> Dictionary
```

### 2.3 明确规则（全部纳入统一配置）

1. **目标选择**：单目标（同一目标承受 N 次）或多目标（依次分配，配置 `target_mode: SAME|SEQUENTIAL`）；多目标模式下越界目标跳过，不报错。
2. **伤害计算**：每次攻击独立走统一结算器（`MagicSettlementSolver.resolve_attack`），位阶/属性/状态逐击生效（如第一击触发状态改变，后续击按新状态结算）；支持 `snapshot: bool` 决定整次打出是否按起手状态快照结算（默认 false = 逐击实时）。
3. **资源消耗**：一次打出只扣除一次行动卡资源与一次基础施法消耗；逐击倍率资源（如每击追加魔力）由配置 `cost_per_cast` 显式声明，未声明则 0。
4. **触发次数**：按实际攻击次数计触发（命中/吸血/反噬等事件按击数触发）；`apply_elite_affixes` 类词缀不被重复注入（魔法自身词缀只结算一次）。
5. **上限规则**：`max_casts` 配置上限（需求定为 5），超限请求受控失败（`MULTI_CAST_EXCEEDS_MAX`）；次数 <= 0 非法。
6. 与升格化、延时、封印组合语义见阶段4 组合矩阵。

### 2.4 状态机

单次打出不需要常驻状态机（一次性事务），但**延时几重化**需将「cast_count + 目标集合」随延时状态持久化（见五）。

## 三、魔法封印与魔法解放（Seal / Release）实现设计

### 3.1 语义

**封印**：打出魔法封印行动卡（消耗 1 张行动卡）→ 指定魔法进入封印状态。**解放**：释放处于封印状态的魔法。封印行动卡**转化为魔法解放行动卡**，且在封印期间保持该行动语义——该常驻必须建模为**状态持续存在**（`MagicSealState`），而非简单复制一张新卡。

### 3.2 状态实体契约

| 必明确项 | 契约 |
| :--- | :--- |
| 持有对象 | 施法者（account/character 维度）持有封印状态；绑定 `seal_state.magic_ref`（被封印魔法）+ `seal_state.holder_id` |
| 持续时间 | `seal_seconds` 配置上限；0/缺省 = 战斗/场景生命周期内常驻（由配置 `default_duration_seconds` 决定），超时自动解除并清理 |
| 可封印数量 | `max_seals` 配置（每持有者上限）；超出受控失败 `SEAL_SLOT_FULL` |
| 是否允许重复封印 | `allow_repeat_seal` 配置（默认 false：同一魔法已封印则二次封印返回 `ALREADY_SEALED`；true 时转为「重封印刷新持续时间」语义需显式配置） |
| 解放后的状态清理 | 解放成功 → 从持有者封印清单移除，状态对象销毁；若解放目标非封印态 → `NOT_SEALED` 受控失败 |
| 异常中断与回退 | 封印打出时若目标魔法非法/资源不足 → 整次操作回退，不产生半封印；封印期间持有者死亡/战斗结束 → 状态按 `on_holder_lost` 配置（AUTO_RELEASE 释放并返回魔法 / DISCARD 丢弃 / KEEP 跨场景保留） |
| 与其他强化叠加 | 封印状态内的魔法仍可被升格化影响（封印存的是引用不是快照，见 2.4 不变量 2）；封印期间不可再次打出该魔法（`SEALED_MAGIC_UNPLAYABLE`） |

### 3.3 求解器接口设计

```gdscript
# backend/domains/magic_system/seal_solver.gd
class_name SealSolver extends RefCounted
static func apply_seal(holder_id: String, magic_ref: String, source_card: ActionCardDefinition, ctx) -> Dictionary
static func apply_release(holder_id: String, magic_ref: String, ctx) -> Dictionary
```

### 3.4 状态机

`MagicSealState` 生命周期：`ACTIVE`（封印中）→ 解放成功 `RELEASED`（清理）｜ 超时 `EXPIRED`（清理）｜ 持有者丢失 `HOLDER_LOST`（按配置处置）｜ 非法回退 `ROLLED_BACK`（无副作用）。状态跃迁全部记录于状态实体，供结算器与审计读取。

## 四、魔法升格化（Ascension）实现设计

### 4.1 语义

**打出魔法升格化行动卡 → 选择现有魔法 → 校验升格条件 → 位阶 +1 → 按新位阶计算后续效果**。位阶是独立数据维度（复用 `MagicTierRegistry`），升格不产生独立新技能/新卡。

### 4.2 明确规则

| 必明确项 | 契约 |
| :--- | :--- |
| 可升格的最大位阶 | `max_rank`（<= 既有 RANK_11；默认读 `magic_tiers.json` 阶位梯度上限）；已达最高位阶 → `RANK_ALREADY_MAX` 受控失败 |
| 升格条件 | `ascension_conditions` 条件组（资源/位阶资质/进度门槛，配置化，可组合） |
| 是否允许连续升格 | `allow_consecutive` 配置（默认 false：一次行动卡只 +1；true 表示单次打出可多次校验+1，由 `max_steps_per_play` 上限约束） |
| 升格是否永久 | `permanent: bool`（默认 true）；false 时升格为临时态（`duration_steps`），到期回落 |
| 升格后的资源与威力变化 | 不再复制技能——结算时经 `MagicSettlementSolver` 按新位阶读取 `rank_gradient.strength_weight` 等参数动态计算 |
| 已处于最高位阶时的处理 | 返回受控失败码，行动卡不消耗或按配置 `consume_on_max: bool` 决定是否退卡 |
| 与几重化/封印/延时组合 | 升格后引用同一魔法实例（引用非快照）；封印中可升格（升格不解除封印）；延时魔法在释放瞬间以**当时位阶**结算（见五 5.3） |

### 4.3 求解器接口设计

```gdscript
# backend/domains/magic_system/ascension_solver.gd
class_name AscensionSolver extends RefCounted
static func validate_ascension(magic_ref: String, holder, ctx) -> Dictionary
static func apply_ascension(magic_ref: String, holder, ctx) -> Dictionary  # rank+1 并按新位阶重算基线
```

### 4.4 状态机

永久升格：`PENDING_VALIDATE → RANK_UP → COMMITTED`（单事务，失败整单回退）。临时升格：`RANK_UP → TEMP_BOOSTED → EXPIRED`（到期回落原阶并记录）。与位阶形态不变量（god-form 高阶须 SUPERTIER 形态）冲突时，`RANK_UP` 返回 `GOD_FORM_PAIR_VIOLATION`。

## 五、魔法延时（Delayed Cast）实现设计

### 5.1 语义

**打出延时行动卡 → 选择魔法 → 进入延时释放状态 → 指定未来释放时间（步数为主要单位）→ 经过 N 步后强制打出该魔法**。延时魔法触发时**不得阻碍玩家正常行动卡继续打出** → 必须设计为独立的**待触发行动/调度状态**（非阻塞），不能阻塞当前行动流程。

### 5.2 明确规则

| 必明确项 | 契约 |
| :--- | :--- |
| 延时时间合法范围 | `delay_min_steps` / `delay_max_steps` 配置；越界受控失败 `DELAY_OUT_OF_RANGE` |
| 同一魔法能否重复延时 | `allow_repeat_delay` 配置（默认 false：同一魔法已处于延时态 → `ALREADY_DELAYED`） |
| 延时期间目标变化如何处理 | `target_policy`: `LOCKED`（锁定原目标，目标失效则释放失败）\| `RETARGET`（释放时按规则重选）\| `FAIL_ON_MISSING`（默认，缺失则受控失败） |
| 释放时实时属性 vs 创建时属性 | `attribute_snapshot`: `AT_CAST`（创建时快照，升格/属性变化不影响释放结算）\| `AT_RELEASE`（默认，释放时实时结算，含期间升格效果） |
| 与封印/升格/几重化组合 | 封印中的魔法不可设置延时（`SEALED`）；升格不中断已排程延时（按 `AT_RELEASE` 则释放时用新位阶）；延时卡可与几重化组合（释放时按当时 `casts_per_play` 触发，配置 `delay_multi_ok` 默认 true） |
| 玩家死亡/战斗结束/回合结束 | 调度器监听边界事件：死亡 → 按 `on_owner_death`（默认 CANCEL，可配置 FAIL_DROP）；战斗结束 → `on_battle_end`（默认 CANCEL）；回合结束 → 步数制跨回合继续（步数按战斗 tick 累计） |
| 强制释放失败的处理 | `release_fail_policy`: `KEEP_PENDING`（保留状态下轮重试）\| `CANCEL_AND_REFUND`（取消并回退资源）\| `CANCEL`（默认，取消不退款） |

### 5.3 调度器设计（非阻塞）

```gdscript
# backend/domains/magic_system/delay_scheduler.gd
class_name DelayScheduler extends RefCounted
# 每战斗 tick 步进：只推进到期判定，不抢占玩家行动槽
func advance_steps(clock: WorldClockMaster) -> void
func schedule(delay_state: MagicDelayState) -> Dictionary
func pending_count(holder_id: String) -> int
# 到期强制打出：插入「待执行队列」，由行动系统空闲槽消费（不阻塞玩家主动出牌）
func drain_due(holder_id: String) -> Array[Dictionary]
```

**非阻塞不变量**：调度器只维护到期队列；到期魔法在行动系统下一个可用时机消费；若行动槽始终被玩家占用，到期项按 `delay_overflow_policy`（默认 ACCUMULATE 累积，可配 DISCARD_OLDEST）处理——**任何情况下不得阻塞玩家正常行动卡打出**。

## 六、统一结算器（MagicSettlementSolver）

所有机制的最终效果收敛到统一结算器：输入 `magic_ref + 当前位阶/属性/变体标记 + 叠加状态(seal/delay/temp_boost) + 上下文`，输出结构化结算结果。结算器为纯函数，随机性经 `DeterministicRNG` 注入。任何新魔法/新机制只需新增配置 + 注册条件/结算参数，不改引擎唯一规则。
