## 一、P2：GameConfig 路径解析缓存与批量读

### 1.1 现状取证

- `game_config.gd:252-266` `get_value` 每次调用 `_split_path(path)`（`path.split("/")` 重建 PackedStringArray）+ 自表根逐段字典遍历，未命中/数组越界才返回 default。
- 类型化取值器（get_string/int/float/bool/dict/array，`:270-306`）全部委托 get_value，故全链每次读都重复解析路径。
- 热路径实例：`thermodynamics_solver.gd:22-24,41-58` 单次受击 3~11 次 `get_float`；`combat_pipeline_fsm` 参与体字段默认值（构造即读）等。
- 热重载：`reload_config()`（`:138-219`）构建新表成功原子交换 `_tables`，版本推进。

### 1.2 设计

1. 新增静态路径分段缓存：
   - `static var _path_cache: Dictionary = {}`：`path → PackedStringArray`（分段结果），`_split_path` 命中即返、未命中解析后写入——**消除每次调用的 split 分配**（读多写少，缓存无界但键域=代码内静态字面量路径，规模有界；reload 时随表缓存一并清空防御性处置）。
   - 失效时机：`reload_config()` 成功交换 `_tables` 后 `_path_cache.clear()`（表键不变但**值可能变**——路径缓存只缓存分段不含值，故值变化无需失效；清空仅为防御键集变化）。
2. 新增批量读 API（供热路径一次取参）：
   - `static func get_many(table_name: String, paths: PackedStringArray) -> Dictionary`：单次 `ensure_loaded()` + 单次取表根，逐路径复用 `_split_path` 缓存解析，返回 `{path: value}`（缺失路径不含键，与 get_value 语义一致：不抛错、调用方自取带默认）。
   - 语义承诺：与逐键 `get_value(table_name, p, null)` 逐位等价（含数组下标路径）。
3. 热路径改造（行为等价，仅替换重复读）：
   - `thermodynamics_solver.calculate_mana_phase_transition_loss` 等单函数 3+ 次同表读取处，改经一次性 `get_many` 取参（若测量确有必要；保守原则：**仅改已取证的重复读函数**，不做全库盲改）。
4. 不变量：get_value/get_* 单键语义、默认回退、宽松类型转换**零变化**（缓存只动 split 分段与批量入口，单键取值器内部逻辑原样保留）。

## 二、P3：AccountItemLibraryAggregate canonical 索引与增量聚合

### 2.1 现状取证

- `account_item_library.gd:66-94`：`apply_item_delta` 每次 `find_item_node(canonical_id)` 双层 for 全树线性扫（root→major→minor→canonical，O(major×minor×items)）；命中后更新叶 stats 再 `_recalc_upwards(root, [major, minor])` 自底向上聚合该主分类子树。
- 树深恒定 3 层（root→category_major→category_minor→item），serialize 直接存 `root_node` 字典（`:115-116`）。

### 2.2 设计

1. 新增实例索引：`var _canonical_index: Dictionary = {}`（canonical_id → `{"major": String, "minor": String}`）。
   - 维护点：`_mount_item`（新建叶/挂载路径，`:48-61` 附近）写入；序列化重建：`deserialize`/restore 路径（如存在）或首次查询懒重建（`_ensure_index()` 在 `find_item_node`/`apply_item_delta` 前置检查，空索引即全树遍历一次重建）。
   - `find_item_node` 改为：`_ensure_index()` → 索引命中 O(1) 直取节点 + 组装 `{"node", "path"}`（返回结构与既有调用方兼容，`path` 供 `_recalc_upwards`）。
   - 卸载/删除路径（如有 erase）同步移除索引项。
2. 增量聚合：`_recalc_upwards(root, [major, minor])` 保持（树深 3 聚合代价小、语义为分类统计必须），本卷**不改聚合算法本身**——仅消除「定位叶节点」的线性扫（P3 收益主体是 O(1) 定位 + 避免每次事件全树 find）。
3. 行为等价：`find_item_node`/`apply_item_delta`/`query_subtree`/`serialize` 返回结构与既有断言零漂移；索引为运行时加速结构，不入 serialize（serialize 仍存 root_node，deserialize 后索引懒重建）。

### 3.2 设计（保守分级：不改变回滚能力）

2. unequip_to_inventory 同理：`item 不在 loadout` 等前置失败先行。
3. 快照本身（深 duplicate）保留——回滚语义（含深快照重建新实例的行为）与既有断言/Phase 43 C2 记录一致，**不改快照深浅**（改浅快照属行为变更，超本卷范围）。
4. 收益：高频「非法请求/无变更请求」不再付深快照成本；成功路径快照次数不变（保持事务原子性）。
