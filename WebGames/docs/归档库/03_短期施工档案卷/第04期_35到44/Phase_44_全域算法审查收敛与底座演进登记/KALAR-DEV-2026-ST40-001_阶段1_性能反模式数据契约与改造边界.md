## 二、不变量契约（改造红线）

1. **确定性契约**：P 类改造一律不引入全局随机、不改变 LCG 调用次序与数量——凡涉及 RNG 的路径（十连/掉落/强化）行为序列与改造前逐位一致（TC-ARCH-04 门禁兜底）。
2. **配置驱动契约**：新增上限/缓存容量键一律进 `config/`（`infrastructure.admin` 或所属域表），经 `audit_config --strict` 新键结构校验消费闭环；禁止在代码中固化示例数值（C1 教训：键先行须同卷消费）。
3. **语义零漂移契约**：P2 路径缓存必须与 `get_value` 现有语义等价（类型宽松转换/默认回退/数组下标/热重载失效）；P3 索引必须与 `find_item_node` 返回等价（含 serialize/restore 后索引重建）；P4 裁剪语义统一「最旧先出」（与 Phase 43 会话/审计一致）；P5 回滚能力等价（失败路径仍须完整恢复）。
4. **热重载契约**：GameConfig 路径缓存须在 `reload_config()` 成功交换后清空（新旧表值可能不同）；QualityTierRegistry 单例仍暴露 `reload_configuration()`（GM 热重载入口不变）。
5. **行为等价契约**：非反模式路径（含 379/379 既有断言触及的）零改动；改造文件仅触及取证定位的具体行。

## 三、P1~P7 数据契约要点

- **P1**：`GameBootstrap` 新增 `_quality_registry` 单例（`QualityTierRegistry`）+ 访问器 `quality_tier_registry()`；`ItemInstanceFactory.build_instance` 增可选参 `quality_registry: QualityTierRegistry = null`（null 时经 `GameBootstrap.quality_tier_registry()` 兜底取装配单例，保证既有调用签名零破坏）；`ItemQualityResolver` 构造注入 registry 实例（不再内部 new+reload）。
- **P2**：`GameConfig` 增内部静态路径缓存（`table:path → 值引用` 或已解析分段），`reload_config()` 成功交换后清缓存；新增 `get_many(table_name, paths: PackedStringArray) -> Dictionary` 批量读（单次表查找 + 逐路径解析，供热路径调用方一次性取参）。
- **P3**：`AccountItemLibraryAggregate` 增 `_canonical_index: Dictionary`（canonical_id → [major_key, minor_key]），`apply_item_delta`/`find_item_node` 走索引 O(1)；`_mount_item`/`serialize`/`restore`（如有）维护或重建索引；`_recalc_upwards` 保留（树深恒定 3 层，子树聚合为分类节点必要），但改为仅重算受影响主分类单链（不遍历无关分支）。
- **P4**：基础设施抽 `FifoBudget`（或域内静态助手）：`trim_oldest(container: Dictionary, max: int)` 单次计算溢出量后按插入序擦除（keys 排序一次，非 while 循环重建）；6 处调用点统一接入，上限键优先读所属域配置（缺省保持既有 1000/500 等值）。
- **P5**：`EquipmentFSM` 穿/脱预检先行（can_add 判定在快照前即可完成的部分前置），仅当提交路径可能变更 inventory 时才 `snapshot()`；失败路径恢复语义不变（快照仍完整）。
- **P6**：三处无界容器补上限：`server_grant_registry`（上限键 `domains.item_namespace_registry server_grant/max_entries` 或复用 admin，缺省 10000）、`npc_legacy_fsm._committed_npc_ids`（上限键 `domains.npc committed/max_entries`，缺省 5000）、`reward_dispatch_pipeline.redeemed_keys`（上限键 `domains.chat_command redeemed/max_entries`，缺省 2000），皆最旧先出。
- **P7**：`multi_cast_solver.execute_play` 拆分 `_build_hit_ctx`：SAME 目标且无 per-hit 变异时共享同一 ctx（零拷贝，snapshot_mode 冻结仍成立）；`magic_rule_registry` 查询段改为内部只读引用 + 变更时重建（`reload_configuration` 后重建引用，查询零拷贝）；`ground_loot_event_listener.cleanup_decayed` 单遍过滤（`filter` 一次分配）。
