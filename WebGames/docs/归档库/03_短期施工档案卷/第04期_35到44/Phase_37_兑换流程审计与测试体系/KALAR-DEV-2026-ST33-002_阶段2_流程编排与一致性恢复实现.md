## 一、实现边界与错误隔离

| 领域 | 实现要求 | 禁止行为 |
| :--- | :--- | :--- |
| 流程编排 | 统一入口编排：判定 → 核销 → 记录 → 投递；每步返回结构化 Result | 调用方自行拼装步骤产生旁路路径 |
| 一致性 | 投递失败标记 `DISPATCH_PENDING`，恢复后按回执重发；成功记录以 transaction_id 唯一 | 投递失败仍保持已消耗状态造成奖励丢失 |
| 去重 | 重复请求按 transaction_id 去重；重复投递按 mail_id 回执去重 | 重复提交产生双倍奖励或重复记录 |
| 审计 | 判定原因、状态跃迁、核销/记录/投递操作结构化留痕 | 内部诊断信息泄露到客户端提示 |

## 二、状态机与提交顺序

```text
SUBMITTED -> ELIGIBILITY_CHECK -> REDEEMED -> RECORDED -> DISPATCHED
     |失败(可重试)                |投递失败
     +-> FAILED(重试依据保留)      +-> DISPATCH_PENDING(恢复重发)
```

- 资格判定失败（含门槛未达标）进入可重试失败态，零核销写入（复用 Phase 35 语义）。
- 核销成功即写兑换记录（transaction_id 唯一）；投递失败时记录标记 `DISPATCH_PENDING`，恢复后按回执重发，不重复核销。
- 编排层保持无状态静态接口，事务键与回执由调用方/会话注入，不依赖全局可变状态。

## 三、算法与性能约束

- 流程每步单次线性操作；去重查找用事务键哈希索引，O(1) 判定。
- 重试受配置上限约束（超限进入人工审计队列），避免无限重试。
