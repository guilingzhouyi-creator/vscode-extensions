## 一、数据契约与边界

| 契约对象 | 必须字段 | 不变量 |
| :--- | :--- | :--- |
| MarketState | goods_id、supply、demand、inventory、price、trade_volume、last_updated_tick | 状态随交易与时间演化；任何时刻可快照可重放 |
| TimeInput | world_tick、day、month、year | 统一世界时间源（world_clock_master 权威）；时间只作输入不作唯一价格来源 |
| EconomyConfig | base_price、price_bounds、elasticity、weight、initial_state | 提供基础参数/规则/上下限/权重；最终结果不得直接读固定值 |
| TradeAction | account_id、goods_id、side（BUY/SELL）、quantity、tick | 交易行为反向影响市场状态（供需/库存/成交量反馈） |

核心不变量：

1. **静态配置 ≠ 静态结果**：配置文件提供基础参数与初始状态，但最终交易价格、供需、收益与市场状态由运行时状态与世界时间共同计算，不得直接读取永久固定数值。
2. **世界时间是输入而非等价**：时间驱动市场演化，但不得把时间直接等同于价格变化（价格由公式/状态共同决定）。
3. **反馈闭环**：玩家/市场交易行为影响市场状态（库存/供需/成交量），形成持续反馈的闭环系统，不是单向读取数值。
4. **可追踪可重放**：所有经济变化（价格/供需/状态跃迁）具备可追踪、可重放、可审计能力——同输入同状态必得同结果。

## 二、业务实现与状态机

- 动态计算范式：`世界时间 + 基础配置 + 当前经济状态 + 玩家/市场行为 → 动态经济计算 → 新市场状态 → 下一轮计算`（替代 `配置文件 → 固定价格 → 永久不变`）。
- 市场状态演化：交易发生时更新供需/库存/成交量 → 时间推进时按配置公式与权重重算价格与供需 → 状态快照入可重放日志。

## 三、配置驱动与工程化

- 经济参数（基础价/上下限/弹性/权重/初始状态/公式选择）由新配置段（如 `config/domains/economy.json`）驱动，代码零硬编码；最终结果不写死。
- 世界时间源统一走 `world_clock_master`/`world_instance` 权威时间；时间跳变处理见阶段3。
