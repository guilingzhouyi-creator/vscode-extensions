## 一、配置驱动范围

本阶段只把已识别的事实参数移出源码，不把业务规则泛化成无边界脚本。新增配置表必须先建立 JSON 文件，再登记到 `GameConfig._required_tables`，并由加载器完成类型、键集合和值域校验。

| 参数族 | 配置事实源 | 约束 |
| :--- | :--- | :--- |
| 安全密封与审计策略 | 现有基础设施/管理员配置和环境密钥提供器 | JSON 只保存算法、版本、密钥 ID、失败策略等非秘密元数据；秘密不落库；缺失密钥拒绝操作 |
| 物品保护、锁定与分解产物 | 物品注册表及物品/分解域配置 | 通过 `canonical_id` 或已注册键解析；未知 ID 在装配或操作前拒绝，不以源码 fallback 补齐 |
| 交易边界与经济参数 | 现有商店、货币和经济域配置 | 数量、价格、库存和波动边界统一声明；配置值只作为输入，运行时状态不写回配置快照 |
| 幂等保留与容量 | 基础设施配置 | 明确最大记录数、TTL、淘汰策略和重启行为；容量为非负整数，TTL 不得溢出时间类型 |
| 错误码与外部提示 | 现有 i18n/narratives 配置 | 对外只读稳定分类，内部原因与字段脱敏后进入审计；缺失文案有受控失败而非拼接源码字符串 |

## 二、GameConfig 与生命周期

1. `GameConfig.reload_config()` 先在临时快照中加载、校验和构建版本；全部通过后以单次替换发布，失败保留上一份可用快照及版本号。
2. 运行中的服务只持有不可变配置快照引用；热重载通过 `EventBus` 广播版本变化，禁止在消费者遍历期间修改共享字典。
3. 密钥提供器、幂等存储、统计投递器和时间源通过 `GameBootstrap.assemble()` 注入；服务退出时释放连接、定时器和订阅，避免静态回调持有已销毁节点。
4. 门禁脚本必须把 Godot 路径转换和进程退出码作为显式结果传递；失败日志在验收完成前保留，不能在失败分支先删除或用 `if ! command` 覆盖真实状态。

## 三、工程化约束

- 统一使用严格类型 DTO、窄接口和无状态求解器；只有确有生命周期需求的对象才持有状态。
- 统计和遥测采用提交后批处理，记录 `transaction_id`、耗时和失败类别；敏感字段按既有脱敏规则处理。
- 任何缓存、队列或订阅都必须声明所有权、容量、清理触发点和关闭行为；未声明者不得新增。
- 配置校验、运行时校验和审计规则三者保持同一字段命名与大小写，禁止通过别名掩盖迁移错误。
