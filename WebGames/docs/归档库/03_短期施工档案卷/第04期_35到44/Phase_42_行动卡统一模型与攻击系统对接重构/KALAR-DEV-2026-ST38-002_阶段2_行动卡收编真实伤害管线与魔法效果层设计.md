## 一、修复/实现范围

依据阶段1 数据契约，将 Phase 41 自建的魔法行动卡/结算模型收编进既有攻击系统：
1. **收编行动卡**：`magic_system/action_card_definition.gd` 退役为兼容别名（deprecated 包装），权威行动卡 = `PhysicalVerbRegistry.CombatActionCardEntity`；
2. **伤害走真实管线**：删除 `MagicSettlementSolver` 的虚拟 `base_power × rank_weight` 结算，物理/魔法伤害全部经既有管线入口（`PhysicsAndThermodynamicsSolver` / `CombatPipelineFSM`）；
3. **魔法机制降级为效果层**：封印/升格/延时/几重化/解放作为行动卡效果（effect layer）挂接，不再自成一类卡。

| 现文件 | 处置 | 理由 |

| `magic_system/magic_rule_registry.gd` | 不变（规则配置真源） | 与攻击卡正交 |

### 2.2 行动卡扩展（魔法卡类别）

`CombatActionCardEntity` 扩展（**新增可选字段，不破坏既有 8 动词卡**）：
- `card_category`: String = "ATTACK"（ATTACK/BUFF/DEBUFF/RECOVER/ITEM/ULTIMATE——对齐玩法稿 4.3 卡池分类）；
- `magic_ref`: String = ""（可选，关联 `MagicDefinition.canonical_id`；非魔法卡为空）；
- `effects`: Array = []（可选，效果层声明，见四）；
- `card_pool`: String = "random"（random/skill/ultimate，出牌来源池标记）。

所有新字段读 `combat.json::card_pool_defaults` 兜底默认值，代码零硬编码。

## 三、真实伤害管线接入（D2 修复）

### 3.1 物理伤害

魔法/物理行动卡命中后不再由 magic_system 自算——统一走既有入口：

```gdscript
# CombatPipelineFSM.execute_action_round(attacker, attacker_verb, defender, defender_verb)
#   → PhysicsAndThermodynamicsSolver.calculate_penetration_damage(m, v, verb, edge, armor)
```

魔法侧将 `verb_type` 映射为既有动词或注册魔法动词域后复用同一函数族；**禁止另起伤害公式**。

### 3.2 魔法伤害

魔法行动卡按需求表1 §5.2 魔法公式接入（能量密度 × 抗性 × 技能路径权重），由既有 `combat.json::phase_transition`（始源/咒术两步相变能损）驱动：
- 始源直驱 / 超位：极效直驱（能损 3% 级别，读 `primordial_min_loss_floor`）；
- 咒术有咏唱：两步相变能损（`incantation_step1_*` + `step2_*` 参数）。

Phase 41 `MagicDefinition` 的 `rank_weight` 不再独立当伤害系数，仅作为**结算适配输入**（等级/位阶上下文）传入管线。

### 3.3 结算适配层

`MagicSettlementSolver` 重构为**纯适配层**（不改变名，避免大范围引用改动）：
- `resolve_attack()` 改为构造 `CombatPipelineFSM.CombatParticipant` 输入并调用 `execute_action_round`/伤害入口，返回其结构化结果；
- 保留确定性：RNG 经 `DeterministicRNG` 注入，供暴击/反击等概率判定使用。

## 四、魔法机制效果层设计（D3/D4 语义挂接）

| 机制 | 挂接形态 | 语义 |
| :--- | :--- | :--- |
| 几重化 | 行动卡 `effects[]` 内 `{ "kind": "multi_cast", "casts_per_play": N }` | 一张卡一次出牌 → 事务内 N 次命中结算（仍只占一张手牌/一次行动） |
| 封印/解放 | 效果触发 `SealSolver`（封印卡效果）或 `RELEASE` 型行动卡 | 状态仍由 `MagicRuleState` 承载，行动卡只是触发入口 |
| 升格化 | 效果触发 `AscensionSolver` | 位阶维度在 magic_system 内更新，出牌本身走既有行动语义 |
| 延时 | 效果创建 `MagicRuleTrigger` 入 `DelayScheduler` | 释放时经行动队列在可用时机消费，不阻塞玩家出牌 |

## 五、AP 轴出牌合法域校验（D3 修复）

新增统一出牌校验（独立求解器或并入 CombatPipelineFSM 调用链前），断言：

```
出牌合法 = card in hand(手牌持有) AND 满足 AP 语义
AP > 0: 可消耗 ap_cost 出牌（ap_cost 为负语义另行处理，随 verb base_ap 对齐）
AP < 0: 硬直禁主动出牌（只可被动招架 → 仅允许 PARRY/BLOCK/INTER 类防御卡）
AP = 0: 均势先手判定
```

受控失败码：`HAND_NOT_CONTAIN` / `AP_INSUFFICIENT_OR_STAGGERED` / `CARD_POOL_MISMATCH`。
