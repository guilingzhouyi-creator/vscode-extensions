## 一、 配置契约 (config/domains/event_extractor.json)

```jsonc
{
  "enabled": true,
  "batch_size": 200,
  "grouping_rules": [
    { "rule_id": "rule_cdkey_redeem", "source_event": "item.granted", "group_key": "transaction_id",
      "composite_event": "transaction.cdkey_redeemed", "projection": "account_summary" },
    { "rule_id": "rule_gacha_pull", "source_event": "item.granted", "group_key": "transaction_id",
      "composite_event": "transaction.gacha_pull", "projection": "account_summary" },
    { "rule_id": "rule_disposal", "source_event": "item.destroyed", "group_key": "transaction_id",
      "composite_event": "transaction.disposal", "projection": "account_summary" }
  ],
  "projections": {
    "account_summary": { "scope": "account", "include": ["current_quantity", "total_gained", "total_destroyed"] }
  }
}
```

* 配置表在 `game_config.gd` `_required_tables` 登记 `domains.event_extractor`，并同步域清单 `config/infrastructure/domains.json`（TC-ARCH-01/03 护栏要求）；
* 类型化取值：`get_bool` / `get_int` / `get_array` / `get_dict`，禁止 `get_value`（警告即错误）。

## 二、 链路事务键接入点清单（transaction_id 注入）

| 链路 | 文件 | 事务键来源 |
| :--- | :--- | :--- |
| CDKey 兑换 | `reward_dispatch_pipeline.redeem_cdkey` | `clean_key`（兑换码即事务键） |
| 礼包直发 | `voucher_dispatch_pipeline.dispatch_rewards_direct` | payload `tx_id`（新增字段，缺省随机） |
| 邮件领取 | `mail_delivery_pipeline.claim_single_mail` | `mail.mail_id` |
| 祈愿抽卡 | `gacha_execution_service.execute_multi_pull` | 本次 pull 批次号（`pull_count` 内共享） |
| GM 发放 | `sandbox_cheat_solver` GIVE_ITEM | 指令执行 id |
| 追缴 | `clawback_service` | 审计流水 id（与 `GMArbitrationAuditService` 对齐） |
| 销毁 | `disposal_pipeline.process_item_disposal` | `item_id` |
| 分解 | `reforge_salvage_pipeline.salvage_equipment` | `item.item_id` |

**改造约束**：全部为**可选尾部参数或 payload 字段**（缺省空串），缺省时 `ItemStatisticsSolver` 保持逐条落账，既有测试与调用方零改动（与 Phase 07 账号加固同风格的向后兼容接入）。

## 三、 热重载与一致性

* 规则表变更经 `GameConfig` 热重载广播后，`CompositeEventExtractor` 下一批次生效；
* `enabled=false` 时提取管线整体旁路，仅保留逐条落账（运营灰度开关）。
