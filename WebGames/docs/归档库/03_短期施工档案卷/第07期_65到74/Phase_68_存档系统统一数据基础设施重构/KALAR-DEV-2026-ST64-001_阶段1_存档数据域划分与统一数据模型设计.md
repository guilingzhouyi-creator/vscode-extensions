  - `Inv-SV-1`（领域划分不变量）：存档数据域划分以**实际业务边界**为准（account/character/inventory/item/lattice/world/progress/economy/quest/lifecycle/settings），禁止按代码文件或历史顺序机械划分；任一核心数据有且仅有一个所有权域，禁止多域共同直接修改同一份核心数据；
  - `Inv-SV-2`（统一数据标准不变量）：所有业务域经 `serialize()/deserialize()` 规范化接口进入统一存档信封（`data_json` 单字段 + 签名），禁止旁路自定义格式；`SaveManager` 信封契约不得被破坏（校验与消费指向同一字节序列）；

  - `Inv-SV-5`（无运行时对象不变量）：存档数据禁止保存运行时对象/场景引用/节点指针，仅可持久化值类型（String/int/float/Dictionary/Array）。

## 一、 存档数据域重新划分（基于实际业务审计）

### 1.1 审计现状 → 目标域映射

基于本次审计（47 域注册表 + serialize 实现 + 数据依赖），**实际业务领域划分**如下（非机械照抄示例）：

| 目标数据域 | 对应实际业务域（domains.json id） | 拥有数据 | 现状 serialize 实现 |
| :--- | :--- | :--- | :--- |
| `account` 玩家基础状态域 | `account` | 账号身份、会话 Token、save_slot_summaries 槽位摘要 | `AccountProfileAggregate.serialize/deserialize` ✅ |
| `character` 角色状态域 | `character_creation` | 角色身份（name/race/gender）、序章执行上下文、创建进度 | `CharacterPrologueContext.to_dto/from_dto` ✅ |
| `inventory` 背包数据域 | `inventory` | 装备槽位、存储物品数组、背包容量/负重缓存、owner_account_id | `WearableInventoryAggregate.serialize`（增量实现） ✅ |
| `item` 物品持有数据域 | `inventory`（item_entity） | 物品实例（canonical_id + instance 判别式 + 数量/属性快照），**不含物品定义** | `ItemEntity.serialize/deserialize` ✅ |
| `lattice` 技能数据域 | `lattice_skill_book` | 技能格栅 AST、签名哈希、自定义技能稿（manuscript） | `SkillSubgraphAST.serialize/deserialize` ✅ |
| `world` 世界状态域 | `world_gateway` | 当前世界状态引用、进入模式、世界实例引用 | `WorldGatewayModel` DTO ✅ |
| `progress` 进度数据域 | `persistence_protocol`/`reconciliation` | 进度对账、服务器广播状态（单机占位） | `ReconciliationSolver` ✅ |
| `economy` 经济数据域 | `currency_economy` | 钱包各货币余额、债务、消费流水摘要 | 钱包实体 serialize（审计确认） ✅ |
| `quest` 任务数据域 | `quest_causality` | 任务因果状态、已完成标记 | 待审计确认（见阶段2 接入清单） 🟡 |
| `lifecycle` 生命周期域 | `lifecycle` | 停机管线状态、玩家会话状态标记 | DTO 序列化 ✅ |
| `settings` 系统配置关联域 | `game_settings` | 玩家本地设置（按键/画质/语言偏好） | `SettingsPersistenceService` ✅ |

### 1.2 每个数据域的契约卡片（统一模板，全部域适用）

以 `inventory`（背包）为例完整示例，其余域在实施时按同模板收敛：

```text
数据域: inventory
├─ 负责数据: equipped_slots（槽位→物品引用）、storage_items（持有实例数组）、
│            owner_account_id、缓存指标（_cached_storage_volume/_cached_total_weight）
├─ 数据结构: { equipped_slots: {slot: item_ref}, storage_items: [item_ref], owner_account_id: str }
├─ 数据所有权: 唯一所有者 = inventory 域；item 实例内容归 item 域，inventory 只持有引用
├─ 生命周期: 与角色/存档槽位同生命周期；创建随角色、销毁随槽位删除
├─ 依赖关系: 依赖 item 域（引用 ItemInstance）；依赖 config/domains/inventory.json（容量/负重默认）
├─ 读写入口: WearableInventoryAggregate.serialize()（写）/ deserialize()（读），经 SaveAssembler 装配
├─ 序列化规则: 仅值类型；物品引用用 canonical_id + instance_discriminator（不存对象）
├─ 校验规则: 引用完整性（引用的 canonical_id 必须在 items 表存在）；容量/负重非负
├─ 默认值来源: config/domains/inventory.json（baseline_capacity/max_carry_weight_kg/capacity_slots）
├─ 数据版本: domain_version = 1（域级，独立演进）
├─ 迁移方式: register_migration("inventory:1" → "inventory:2", callable)；仅结构变化时注册
└─ 跨域引用: 只读引用 item 域定义（canonical_id 键）；禁止写穿物品定义
```

### 1.3 物品-背包-技能联动数据流（配置/运行时分离）

```
配置层（永不入档）                    存档层（只存玩家状态）
ItemDefinition (config/items/*.json)   ItemInstance/PlayerItemState
  canonical_id/english_name/属性模板      canonical_id 引用 + instance 判别式 + 数量/属性快照
        ↓ 引用                               ↓
SkillDefinition (config/domains/lattice) PlayerSkillState (SkillSubgraphAST)
  格栅模板/技能定义                        签名哈希 + 节点/边结构（玩家自创）
        ↓ 引用                               ↓
InventoryState (equipped_slots/storage)  SaveData (SaveManager 信封 data_json)
```

**关键设计决策**：
- **物品定义与持有分离**：`ItemEntity` 存 `canonical_id`（引用 `config/items/*.json` 定义）+ instance 判别式；定义属性**永不写入存档**（缺定义时按 item_defaults 兜底重建，Inv-SV-3）；
- **技能定义与状态分离**：`SkillSubgraphAST` 存结构（nodes/edges）与 `signature_hash`；技能模板属性（skill_name/sentence_count 默认）读配置，不重复存储；
- **禁止重复存储**：可由配置重算的（容量、负重、属性模板）一律不存；
- **禁止循环依赖**：inventory → item（引用定义键）；character → inventory/lattice（聚合）；存档装配层单向依赖业务域，禁止反向。

## 二、 统一数据标准与三级版本模型

### 2.1 统一数据标准（Inv-SV-2）

```gdscript
# 统一域契约（实施阶段落为 SaveDomainContract 注册条目）
# 每个可持久化数据域必须实现：
#   serialize() -> Dictionary      # 纯值类型，无运行时对象（Inv-SV-5）
#   static deserialize(d) -> 聚合   # 缺省字段回退默认值来源
# 注册（config/infrastructure/domains.json 扩展 save 段）：
#   { "id": "inventory", "save": { "enabled": true, "domain_version": 1,
#     "serializer": "WearableInventoryAggregate", "hot_reload": "deny" } }
```

### 2.2 三级版本模型（Inv-SV-4）

| 版本层级 | 载体 | 演进粒度 | 迁移机制 |
| :--- | :--- | :--- | :--- |
| **Domain Version** | 各域 serialize 结果内嵌 `domain_version` | 单域结构变化 | 域级 `register_migration("inventory:1"→"inventory:2")` |
| **Schema Version** | 存档布局 schema 声明（阶段3 配置） | 布局/字段集合整体变化 | 布局迁移链 |
| **Save Version** | 信封 `format_version`（现有，`persistence.json` 驱动） | 整档版本 | 既有 `migrate_save_data` 链 ✅ |

**兼容策略**：旧档（仅含 `data` 无签名）继续 legacy 降级读取（现状语义保留）；新档全量签名；域级迁移**独立于业务运行逻辑**，可测试可追踪（`GameSaveAssembler.register_migration` 已具备）。

## 三、 状态与边界约束 (States & Boundary Constraints)

| 约束 | 说明 | 违反后果 |
| :--- | :--- | :--- |
| Inv-SV-1 | 领域划分以业务边界为准，单一所有权 | 多域共改核心数据 → 评审阻断 |

| Inv-SV-5 | 存档仅值类型，无对象/场景引用 | 运行时对象入档 → 评审阻断 |
