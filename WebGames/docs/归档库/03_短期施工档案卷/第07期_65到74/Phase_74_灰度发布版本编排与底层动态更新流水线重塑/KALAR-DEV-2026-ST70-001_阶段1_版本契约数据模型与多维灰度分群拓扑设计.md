## 📌 第一性原理溯源指针

* **精准上游规范指针**：
  - `backend/infrastructure/event_bus/event_channel_definition.gd`（P72 整型信道常量真源）
  - `backend/infrastructure/event_bus/event_category_mask.gd`（P72 五类正交位掩码）
  - `backend/domains/persistence_protocol/runtime_mode_gate.gd`（单机/联机物理隔离闸门）
  - `backend/infrastructure/game_bootstrap.gd`（全域唯一装配入口）
  - `config/infrastructure/domains.json`（全域领域元数据事实表）
* **核心不变量约束断言**：
  - `Inv-VG1-1 (控制面与数据面绝对解耦)`：所有通过 P72 EventBus 派发的版本控制消息（`0x0500` 段），单包 Variant 序列化体积必须严格 $< 1\text{ KB}$，大体量更新资源（.pck / .zip）绝对禁止穿透 EventBus；
  - `Inv-VG1-2 (分群判定纯数学确定性)`：灰度匹配引擎必须基于输入标量与 MurmurHash3/确定性离散混叠散列，对于相同输入其分群判定结果必须 100% 确定，禁止依赖未初始化的伪随机数或动态字典遍历顺序；
  - `Inv-VG1-3 (授权令牌防篡改完整性)`：`ActivationTokenDTO` 必须包含版本号、生效截止时间戳、目标用户标识与 HMAC/SHA-256 签名校验位，缺少有效令牌的客户端绝对禁止跃迁至目标版本；
  - `Inv-VG1-4 (单机联机版本治理大一统)`：单机模式与联机模式共享完全相同的 `VersionManifestDTO` 与版本判定算法，唯一区别在于单机由本地离线凭证注入，联机由网络会话动态下发；
  - `Inv-VG1-5 (零硬编码与配置驱动)`：所有 Release Ring（如 ALPHA, BETA, STABLE, CANARY）、灰度百分比区间及渠道标识符必须统一由 `release_policy.json` 驱动，代码内禁止存在 `if user_id in [...]` 硬编码。

## 一、 数据结构设计与代码契约 (Data Structures & Contracts)

### 1. 语义化版本清单数据契约 (`VersionManifestDTO`)
* 模块路径: `res://backend/domains/version_governance/version_manifest_dto.gd`
* 职责: 定义卡拉尔引擎任意发行版本（Release）或增量补丁（Patch）的标准元数据模型。

```gdscript
class_name VersionManifestDTO
extends RefCounted

# 补丁发布类型枚举
enum PatchType {
	FULL_RELEASE = 0,    # 完整全量版本 (Base Pack)
	INCREMENTAL_PCK = 1, # 增量 PCK 补丁包 (动态叠加挂载)
	CONFIG_HOTFIX = 2,   # 纯配置/数值热修复 (GameConfig 增量 diff 刷新)
	EMERGENCY_ROLLBACK = 3 # 紧急回滚指令包 (强制版本重置)
}

# 发布环级枚举 (Release Ring)
enum ReleaseRing {
	INTERNAL = 0, # 开发/内测专享
	ALPHA = 1,    # 先锋体验
	BETA = 2,     # 灰度公测
	STABLE = 3    # 全量稳定
}

var version_string: String = "1.0.0"          # 语义化版本号 (SemVer: Major.Minor.Patch)
var version_code: int = 10000                 # 递增整型版本码 (用于快速比对: 1.8.2 -> 10802)
var min_supported_version: String = "1.0.0"   # 最低强制兼容版本 (低于该版本触发强更阻断)
var patch_type: int = PatchType.FULL_RELEASE  # 补丁类型
var release_ring: int = ReleaseRing.STABLE    # 目标所属发布环
var payload_sha256: String = ""               # 补丁包文件 SHA-256 签名 (64位十六进制哈希)
var payload_size_bytes: int = 0               # 补丁包字节大小
var download_url: String = ""                 # 数据面资源获取 URI (HTTP/CDN 或 本地相对路径)
var pck_mount_priority: int = 100             # PCK 挂载叠加优先级 (越大越后挂载，覆盖底层)
var changelog_loc_key: String = ""            # 国际化更新公告词条键
var published_at_unix: int = 0                # 发布时间戳 (UTC 秒)

## 验证清单自身完整性
func is_valid() -> bool:
	return not version_string.is_empty() and version_code > 0 and (
		patch_type == PatchType.CONFIG_HOTFIX or not payload_sha256.is_empty()
	)
```

### 2. 多维灰度策略与用户分群模型 (`GrayPolicyDTO`)
* 模块路径: `res://backend/domains/version_governance/gray_policy_dto.gd`
* 职责: 承载服务器下发或配置表定义的灰度分群拓扑，支持用户 ID 散列、设备特征、渠道、地域及测试白名单等多维正交判定。

```gdscript
class_name GrayPolicyDTO
extends RefCounted

var policy_id: String = ""                    # 策略唯一 ID (如 "POL_20260908_V180_BETA")
var target_version: String = "1.8.0"          # 目标升级版本
var target_version_code: int = 10800          # 目标版本整型码
var rollout_percentage: int = 0               # 灰度放量百分比 [0, 100]
var allowed_rings: Array[int] = []            # 允许的发布环 (ReleaseRing)
var target_channels: Array[String] = []       # 允许的渠道 (如 ["official", "steam", "test"])
var target_regions: Array[String] = []        # 允许的地域标识 (如 ["CN_EAST", "GLOBAL"])
var target_device_tiers: Array[String] = []   # 允许的设备等级 (如 ["LOW", "MID", "HIGH"])
var explicit_user_whitelist: Array[String] = [] # 强行白名单用户 ID (100% 命中)
var explicit_user_blacklist: Array[String] = [] # 强行黑名单用户 ID (100% 拒绝)
var is_active: bool = true                    # 策略启用状态 (支持秒级关闭)
var rollback_version: String = ""             # 熔断时的应急回退基线版本

## 检查是否命中强制名单
func is_explicitly_whitelisted(user_id: String) -> bool:
	return explicit_user_whitelist.has(user_id)

func is_explicitly_blacklisted(user_id: String) -> bool:
	return explicit_user_blacklist.has(user_id)
```

### 3. 版本激活授权令牌模型 (`ActivationTokenDTO`)
* 模块路径: `res://backend/domains/version_governance/activation_token_dto.gd`
* 职责: 作为客户端已获得目标版本合法运行资格的“入场券”，彻底解决“**本地已有文件却未获授权**”的安全隐患。

```gdscript
class_name ActivationTokenDTO
extends RefCounted

var token_id: String = ""                     # 令牌 UUID / 唯一次序码
var user_id: String = ""                      # 绑定的目标用户账号
var authorized_version: String = ""           # 被授权运行的精确版本号
var authorized_version_code: int = 0          # 被授权运行的版本整型码
var issued_at_unix: int = 0                   # 签发时间戳
var expires_at_unix: int = 0                  # 过期时间戳 (0 为永久)
var signature_hmac: String = ""               # 授权校验数字签名 (防篡改)
var is_revoked: bool = false                  # 是否已被中心紧急撤销

## 检查令牌有效期与合法性
func is_eligible_at(now_unix: int) -> bool:
	if is_revoked:
		return false
	if expires_at_unix > 0 and now_unix > expires_at_unix:
		return false
	return not authorized_version.is_empty() and authorized_version_code > 0
```

### 4. P72 推送信道扩展拓扑 (`EventChannelDefinition`)
* 模块扩展: `res://backend/infrastructure/event_bus/event_channel_definition.gd`
* 职责: 严格继承 P72 整型信道架构，追加 `0x0500 ~ 0x05FF` 版本治理与灰度信令信道。

```gdscript
# ==============================================================================
# 5. 版本治理与灰度控制信道专区 (0x0500 ~ 0x05FF)
# ==============================================================================

## 5.1 控制面：版本发布与元数据公告广播 (广播新版本元数据摘要，< 1KB)
const VERSION_ANNOUNCED         : int = 0x0501

## 5.2 控制面：下发更新授权与运行令牌 (下发 ActivationTokenDTO 与目标版本决策)
const UPDATE_AUTHORIZED         : int = 0x0502

## 5.3 数据面状态回传：补丁下载与校验进度回报 (向服务端/遥测汇报百分比与哈希校验结果)
const UPDATE_PROGRESS_REPORT    : int = 0x0503

## 5.4 生命周期通知：新版本激活挂载生效确认 (客户端已成功挂载 PCK 并通过门禁)
const VERSION_ACTIVATED         : int = 0x0504

## 5.5 控制面：紧急版本回滚阻断指令 (下达熔断信号，强制客户端回退到安全基线)
const VERSION_ROLLBACK_ISSUED   : int = 0x0505

## 5.6 控制面：版本授权失效撤回 (注销特定用户的版本令牌，阻断后续运行)
const VERSION_REVOKED           : int = 0x0506
```
