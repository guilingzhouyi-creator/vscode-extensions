## 一、 核心数据模型与代码契约 (Data Structures & Contracts)

### 1.1 全域结构化日志记录模型 (`StructuredLogRecord`)

```gdscript
# 模块路径: res://backend/infrastructure/structured_log_record.gd
class_name StructuredLogRecord extends RefCounted:
    # ---- P66 LogRecordDTO 超集字段（前六项与其对齐，消费方零改动） ----
    var sequence: int = 0                 # 全局单调序号（与 P66 导出器同源）
    var timestamp_utc: int = 0            # 事件绝对时刻（秒）
    var level: String = "INFO"            # 级别键（debug/info/warn/error）
    var channel: String = ""              # 来源域/模块标识（如 "combat_round_coordinator"）
    var error_code: String = ""           # 英文错误码（P66 ErrorCodeRegistry 登记）
    var message: String = ""              # 人读消息（i18n 可本地化）
    # ---- P67 全域结构化扩展字段 ----
    var trace_id: String = ""             # 链路追踪 ID（Inv-LS-3：跨域调用链串联）
    var parent_span_id: String = ""       # 父链路节点 ID（嵌套调用场景）
    var event_category: String = ""       # 事件分类键（event_categories.json，与叙事分类共用）
    var duration_ms: int = 0              # 事件耗时（毫秒；非耗时事件为 0）
    var source_file: String = ""          # 产生源文件路径（定位用，不含机器绝对路径）
    var source_line: int = 0              # 产生源行号
    var context: Dictionary = {}          # 结构化上下文（深拷贝入档；敏感键已按脱敏规则掩码）
    var redacted_keys: Array[String] = [] # 已被掩码的敏感键清单（审计留痕）

    func to_dto() -> Dictionary:
        return {
            "sequence": sequence,
            "timestamp_utc": timestamp_utc,
            "level": level,
            "channel": channel,
            "error_code": error_code,
            "message": message,
            "trace_id": trace_id,
            "parent_span_id": parent_span_id,
            "event_category": event_category,
            "duration_ms": duration_ms,
            "source_file": source_file,
            "source_line": source_line,
            "context": context.duplicate(true),
            "redacted_keys": redacted_keys.duplicate(),
        }
```

**设计要点**：
- **超集兼容**：前六字段与 P66 `LogRecordDTO` 完全对齐，P66 `LogFileExporter`/前端消费方零改动即可消费扩展记录；
- **链路追踪**（Inv-LS-3）：`trace_id` 由统一底座在业务入口签发（战斗回合/交易流水/停机管线），子日志沿调用传递；`parent_span_id` 支持嵌套跨度；
- **耗时指标**：`duration_ms` 支撑性能分析（遥测分位的基础），非耗时事件恒 0。

### 1.2 敏感数据脱敏规则模型 (`RedactionRule`)

```gdscript
# 模块路径: res://backend/infrastructure/redaction_rule.gd
class_name RedactionRule extends RefCounted:

    class RuleEntry extends RefCounted:
        var field_pattern: String = ""    # 键名匹配（正则，如 "token|fingerprint|password|secret"）
        var mask_mode: String = "mask"    # mask=掩码 / drop=整键丢弃 / hash=保留哈希指纹
        var mask_prefix_len: int = 4      # 保留明文前缀长度（mask 模式）
        var mask_suffix_len: int = 4      # 保留明文后缀长度（mask 模式）
        var replace_with: String = "****" # 掩码填充串（mask 模式）

    static var _rules: Array[RuleEntry] = []
    static var _config_version: int = -1

    ## 规则新鲜度守卫：log.json redaction 段装载，热重载版本推进自动重建
    static func _ensure_loaded() -> void:
        pass

    ## 对 context 字典执行脱敏：命中规则的键按模式处理，返回掩码后副本 + 被掩码键清单
    static func apply(dict: Dictionary) -> Dictionary:
        pass
```

**设计要点**：
- **构造期脱敏**（Inv-LS-2）：`StructuredLogRecord` 构造时经 `RedactionRule.apply(context)` 掩码，落盘/检索路径只见掩码值；
- **三模式**：`mask`（保留首尾 N 位 + 中间填充，如 `TOK_****_abcd`）、`drop`（整键丢弃）、`hash`（保留 SHA-256 指纹用于一致性比对，不还原）；
- **审计留痕**：`redacted_keys` 记录被掩码键名，支撑安全审计（哪些字段被保护过）。

### 1.3 遥测聚合模型 (`TelemetryAggregate`)

```gdscript
# 模块路径: res://backend/infrastructure/telemetry_aggregate.gd
class_name TelemetryAggregate extends RefCounted:

    class SlotMetric extends RefCounted:
        var domain: String = ""           # 聚合域（combat/inventory/trading/lifecycle）
        var event_category: String = ""   # 事件分类
        var count: int = 0                # 事件计数
        var total_duration_ms: int = 0    # 累计耗时
        var p50_ms: int = 0               # 耗时中位数
        var p95_ms: int = 0               # 耗时 p95（热路径承压观测）
        var last_timestamp_utc: int = 0   # 最近一次事件时刻

    static var _slots: Dictionary = {}    # "domain|category" -> SlotMetric
    static var _window_start_utc: int = 0 # 聚合窗口起点（窗口滑动重置）

    ## 消费一条结构化日志：按 domain|category 聚合计数与耗时（单向只读，Inv-LS-4）
    static func consume(record: StructuredLogRecord) -> void:
        pass

    ## 快照当前窗口指标（只读导出，供运维/审计/测试断言）
    static func snapshot() -> Dictionary:
        pass

    ## 窗口滑动：超过配置窗口（log.json telemetry/window_seconds）时重置槽位
    static func _maybe_roll_window(now_utc: int) -> void:
        pass
```

**设计要点**：
- **单向消费**（Inv-LS-4）：`consume` 只读日志流，不改日志级别/内容——遥测是日志的派生视图；
- **分位耗时**：`p50/p95` 支撑无头后端承压观测（配合 P64 性能基准），热路径（战斗回合）耗时分布可视；
- **窗口滑动**：聚合窗口配置驱动（默认 60s），窗口满自动重置，内存有界。

### 1.4 日志检索契约模型 (`LogQueryCriteria` / `LogQueryResult`)

```gdscript
# 模块路径: res://backend/infrastructure/log_query_dto.gd
class_name LogQueryDTO extends RefCounted:

    class Criteria extends RefCounted:
        var from_utc: int = 0             # 起始时刻（含）
        var to_utc: int = 0               # 结束时刻（含；0=至今）
        var levels: Array[String] = []    # 级别过滤（空=全部）
        var channels: Array[String] = []  # 域/通道过滤（空=全部）
        var trace_id: String = ""         # 链路追踪过滤（精确匹配）
        var error_code: String = ""       # 错误码过滤（精确匹配）
        var keyword: String = ""          # 关键字模糊匹配（message 字段）
        var page: int = 1                 # 页码（>=1）
        var page_size: int = 100          # 页大小（1~500，越界钳制）

    class Result extends RefCounted:
        var total: int = 0                # 命中总数（分页统计）
        var page: int = 1
        var records: Array[Dictionary] = []   # 命中记录（to_dto 形态，只读）
        var truncated: bool = false       # 命中超出检索上限（默认 5000）截断标记

        func to_dto() -> Dictionary:
            return {
                "total": total,
                "page": page,
                "records": records.duplicate(true),
                "truncated": truncated,
            }
```

**设计要点**：
- **只读检索**（Inv-LS-5）：检索接口仅读结构化日志流（导出文件 + 内存环形缓冲），零写操作；
- **多维度过滤**：时间/级别/通道/链路 ID/错误码/关键字六维组合，支撑故障定位（按 `trace_id` 拉全链路）；
- **分页与截断**：`page_size` 钳制 [1,500]，命中超上限（5000）置 `truncated` 标记，防巨量返回拖垮调用方。

### 1.5 数据流总览（目标态）

```
业务入口（战斗回合/交易流水/停机管线）
  │  TraceContext 签发 trace_id（统一底座，Inv-LS-3）
  ▼
各域日志点 → EventBus.emit_log_record(StructuredLogRecord)
  │  ① 构造期：RedactionRule.apply(context) 掩码敏感键（Inv-LS-2）
  │  ② 字段补全：trace_id/event_category/duration_ms/source_file/line
  ▼
EventBus 统一底座
  ├─ log_record_emitted 信号 → 前端战报渲染（现状保留，P66 已兼容）
  ├─ 环形缓冲（内存最近 N 条，供实时检索/运维终端）
  ├─ 遥测聚合 TelemetryAggregate.consume()（单向消费，Inv-LS-4）
  └─ 落盘：LogFileExporter（P66 交付，NDJSON 行式结构化输出，Inv-LS-1）
        │
        ▼
日志检索 LogQueryService（只读：文件索引 + 环形缓冲，Inv-LS-5）
  └─ 六维过滤（时间/级别/通道/链路/错误码/关键字）+ 分页
```
