* **精准上游规范指针**：
  - `backend/infrastructure/event_bus.gd:L139-L140`：`emit_log` 唯一官方日志出口，仅信号广播、无落盘；

  - `backend/domains/account/entitlement_service.gd:L76`、`backend/domains/admin_sandbox/gm_audit_service.gd:L42`：`push_warning` 中文告警散落，双通道并行；

  - `config/domains/account.json auth/errors`：现有英文错误码配置段（`ERR_ACCOUNT_NOT_FOUND` 等）为单域示范，未泛化为全域统一注册表。

* **核心不变量约束断言**：
  - `Inv-LG-1`（日志单通道不变量）：所有运行时日志与错误必须经 `EventBus.emit_log` 统一通道（或显式登记的错误上报通道）广播，禁止 `push_error`/`push_warning` 绕过统一底座直发——存量迁移后全库零双通道散落；
  - `Inv-LG-2`（错误码英文底座不变量）：所有 `error_code` 一律英文大写协议常量（机器可读唯一判据），人读 `message` 经 i18n 可本地化；逻辑判断严禁依赖 `message` 文本，名称键本体一律英文；
  - `Inv-LG-3`（日志导出完整性不变量）：启用导出后，每条日志记录必须原子落盘（先写临时文件再重命名），导出记录数与广播记录数严格一致，轮转/截断不得丢行；
  - `Inv-LG-4`（导出配置收敛不变量）：导出路径、轮转阈值、级别过滤、文件名模板全部由 `log.json export` 段驱动，代码零硬编码，热重载版本推进自动重建导出器配置。

* **防漂移最高指示**：
  - 严格保持与既有 `EventBus.emit_log` 接口兼容（信号签名不变），新增导出为旁路消费，杜绝破坏既有 83 套测试套件；
  - 严格遵循零硬编码规范，导出配置与错误码注册表收敛于 `config/infrastructure/log.json` 与 `config/infrastructure/errors_catalog.json`；
  - 存量 `push_error`/`push_warning` 收敛为增量改造（逐文件登记迁移清单），严禁一次大改破坏配置装载失败路径的失败关闭语义。

## 一、 核心数据模型与代码契约 (Data Structures & Contracts)

### 1.1 统一日志记录模型 (`LogRecordDTO`)

```gdscript
# 模块路径: res://backend/infrastructure/log_record_dto.gd
class_name LogRecordDTO extends RefCounted:
    var sequence: int = 0                 # 全局单调序号（跨通道唯一，供导出排序/对账）
    var timestamp_utc: int = 0            # 事件发生绝对时刻（秒）
    var level: String = "INFO"            # 级别键（debug/info/warn/error，log.json levels 归一）
    var channel: String = ""              # 来源域/模块标识（如 "contract_registry_index"）
    var error_code: String = ""           # 英文错误码（可选；无错误时为空串）
    var message: String = ""              # 人读消息（经 i18n 可本地化；逻辑不依赖）
    var context: Dictionary = {}          # 结构化上下文（域/关键参数，深拷贝入档）

    func to_dto() -> Dictionary:
        return {
            "sequence": sequence,
            "timestamp_utc": timestamp_utc,
            "level": level,
            "channel": channel,
            "error_code": error_code,
            "message": message,
            "context": context.duplicate(true),
        }
```

**设计要点**：
- `sequence` 全局单调序号由统一底座签发（复用 `EventBus` 内部计数器），使导出文件行序与广播序严格一致（支撑 Inv-LG-3 对账）；
- `error_code` 与 `message` 分离：`error_code` 为英文协议常量（Inv-LG-2 逻辑判据），`message` 为展示文本；
- 兼容现有 `emit_log(level_key, msg)` 签名——新增 `emit_log_record(record)` 为重载入口，旧签名内部构造 `LogRecordDTO` 委托，零破坏。

### 1.2 日志导出配置模型 (`LogExportConfigDTO`)

```gdscript
# 模块路径: res://backend/infrastructure/log_export_config_dto.gd
class_name LogExportConfigDTO extends RefCounted:
    var enabled: bool = false             # 总开关（log.json export/enabled）
    var directory: String = ""            # 导出目录（log.json export/directory，禁止盘符/绝对路径硬编码）

    var min_level: String = "info"        # 最低落盘级别（debug/info/warn/error 过滤）
    var include_channels: Array[String] = []   # 通道白名单（空=全部）

    static func from_config() -> LogExportConfigDTO:  # 读 log.json export 段，缺省安全回退
        pass
```

**设计要点**：
- 全字段配置驱动（Inv-LG-4），`from_config()` 读 `log.json export` 段，热重载版本推进时由导出器比对重建（复用 Phase 64 `config_reload_version()` 模式）；
- `min_level`/`include_channels` 支持级别与通道双维过滤，测试可用低级别直写验证。

```gdscript
    static func missing_codes(used_codes: Array) -> Array:

```

**设计要点**：
- 错误码注册表装载 `config/infrastructure/errors_catalog.json`（Inv-LG-2 配置驱动），存量单域 `auth/errors` 段迁移并入；
- `message_key` 指向 `narratives.errors` 表对应 error_code 条目，实现 message 可本地化（未登记回退 code 本体，不抛错）；
- `missing_codes()` 提供登记断言——新错误码必须先在配置表登记，杜绝散落字面量（支撑阶段 4 门禁）。

### 1.4 数据流总览（目标态）

```
产生点（各域）
  ├─ 业务结果错误：return { "error_code": "...", "message": "..." }
  ├─ 运行时异常/告警：EventBus.emit_log("warn"|"error", msg)     ← 统一通道（唯一入口）
  └─ 配置装载失败：EventBus.emit_log("error", msg, {error_code})  ← 存量 push_error 收敛目标
        │
        ▼
EventBus（统一底座）
  ├─ log_message_posted 信号 → 前端 main_dashboard 战报渲染（现状保留）
  ├─ emit_log_record 构造 LogRecordDTO（签发全局单调 sequence）
  └─ LogFileExporter（旁路消费，log.json export 配置驱动）
        ├─ 级别/通道过滤 → 追加写临时文件 → 原子重命名 → 轮转/截断
        └─ 导出行与广播行对账（Inv-LG-3）
        │
        ▼
ErrorCodeRegistry（英文错误码注册表，errors_catalog.json 驱动）
  └─ lookup/missing_codes → 门禁校验 + i18n message 解析（narratives.errors 表）
```
