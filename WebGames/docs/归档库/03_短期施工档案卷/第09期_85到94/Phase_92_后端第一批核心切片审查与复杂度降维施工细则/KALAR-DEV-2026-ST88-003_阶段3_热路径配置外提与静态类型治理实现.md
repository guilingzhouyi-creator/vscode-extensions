## 一、 核心重构方案

### 1. `equipment_modifier_evaluator.gd` 循环配置外提与嵌套解构
* **外提配置查询**：在 `evaluate_total_modifiers(loadout)` 入口循环前单次获取 `var rune_table: Dictionary = GameConfig.get_dict("domains.equipment", "rune_modifiers", {})`。
* **解构 3 层循环（`PRF-ALG-001`）**：提取 `_accumulate_item_modifiers(item: EquipmentItem, rune_table: Dictionary, result: Dictionary) -> void` 与 `_add_modifier_map(source: Dictionary, result: Dictionary) -> void`，将主函数与子函数的循环深度均限制在 $\le 2$ 层，圈复杂度降至 $\le 5$。
* **补齐静态类型**：将 `get_modifier_value` 中的 `var mods = ...` 改为 `var mods: Dictionary = evaluate_total_modifiers(loadout)`。

### 2. `contract_parser.gd` 与 `contract_registry_entry.gd` 拆解与强类型化
* **`contract_parser.gd`**：将 `_apply_transform`（CC=12）拆分为 `_apply_string_transform(s: String, rule: String) -> Variant` 与 `_apply_numeric_transform(val: Variant, rule: String) -> Variant`；补全 `raw_val: Variant`、`transformed_val: Variant`、`cur: Variant`、`target_entry: ContractRegistryEntry` 显式类型。
* **`contract_registry_entry.gd`**：提取 `_extract_string_array(raw: Variant) -> Array[String]` 统一解析 `required_fields` 与 `optional_fields`，使 `from_dto` 圈复杂度从 12 降至 $\le 5$，并显式标注 `var entry := ContractRegistryEntry.new()`。

### 3. `quest_reward_dispatch.gd` 与 `save_assembler.gd` 降维
* **`quest_reward_dispatch.gd`**：提取 `_allocate_single_reward(item_id: String, total_qty: int, max_stack: int) -> Array[Dictionary]`，将 `dispatch_item_rewards` 圈复杂度从 13 降至 $\le 6$，补齐 `var proto: Variant` 类型并清理历史批次注释。
* **`save_assembler.gd`**：提取 `_record_uid_if_present(dict_node: Dictionary, seen: Dictionary, duplicates: Array[String]) -> void`，将 `_scan_uid_node` 控制流嵌套从 5 层降至 **2 层**。
