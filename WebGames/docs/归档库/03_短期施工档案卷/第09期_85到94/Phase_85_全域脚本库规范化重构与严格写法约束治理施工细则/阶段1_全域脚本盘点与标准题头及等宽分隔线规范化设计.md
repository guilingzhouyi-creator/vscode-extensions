### 1.3 脚本库标准题头六字段契约 (对齐 Phase 84 后端规范)

后端 GDScript 题头规范（Phase 84 确立）为：`模块归属`、`文件路径`、`架构定位`、`跨域依赖`、`职责说明`、`设计依据`。
脚本库（Tooling & Audit Infrastructure）全面对齐该标准，结构如下：

```text
# ==============================================================================
# 模块归属: 工程效能与质量门禁 (Tooling · 静态审计体系)
# 文件路径: WebGames/scripts/py/audit_gd.py
# 架构定位: 静态分析引擎 (Static Audit Engine)
# 依赖与触发: 触发方: audit_runner / 本地 CLI | 上游: 无 | 下游: 门禁报告 | 运行时: Python 3.10+
# 职责说明: 递归静态扫描全域 .gd 源码，断言无行内禁用模式、无瞬态分配与防御契约
# 退出语义与设计依据: 退出码: 0=合规, 1=阻断, 2=用法错误 | 设计依据: ADV-PRF-002 性能护栏
# ==============================================================================
```

#### 题头六字段严格契约定义：
1. **模块归属**：明确标注所属工程体系（如 `工程效能与质量门禁 (Tooling · 静态审计体系)`、`跨平台构建工具链 (Build · 本地与CI同构流水线)`、`全宗档案治理系统 (Archive · 周期归档引擎)`）；
2. **文件路径**：自仓库根起的相对 Posix 路径，严禁盘符与绝对路径；
3. **架构定位**：准确标注角色（`静态分析引擎` / `CLI 入口 Runner` / `共享底座 Common Base` / `流水线包装 Pipeline Wrapper` / `离线校验器 Offline Validator`）；
4. **依赖与触发**：标明调用方（`CI / audit-all / 本地 CLI`）、上游依赖模块、下游消费方及运行时版本要求；
5. **职责说明**：解释核心职责、关键输入输出与副作用，严禁代码直译复述；
6. **退出语义与设计依据**：显式声明退出码契约（`0=通过, 1=阻断, 2=用法错误`）及设计依据。

### 1.4 等宽集中分隔结构契约 (78 字符等宽线)

- 分隔线格式统一为：`# ==============================================================================`（`#` + 空格 + 76 个 `=`，整行恰好 78 字符）；
- 废除 79、80 字符漂移线；
- PowerShell 统一废除 `<# ... #>` 割裂写法，全仓 Python、Bash、PowerShell 统一采用顶格 78 字符等宽集中分隔注块。
