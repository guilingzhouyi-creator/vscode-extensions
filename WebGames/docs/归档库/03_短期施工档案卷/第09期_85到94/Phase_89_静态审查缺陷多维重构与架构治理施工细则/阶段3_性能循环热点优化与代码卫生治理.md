## 一、 实施细则方案

### 1.1 角色创建属性校验循环降阶优化（`character_creation_service.gd`）
- **性能隐患定位**：
  在属性与特性约束校验时，内部对属性键数组与允许标签数组进行两层嵌套迭代（`for attr in attributes: for tag in tags: ...`），数据规模增加时循环次数按乘积递增。
- **优化方案**：
  1. 在进入循环前，使用 `Dictionary` 将标签或规则键建立键值索引集合（`var valid_tag_set: Dictionary = {}`，利用字典键哈希索引实现 $O(1)$ `has()` 检索）；
  2. 外层循环单层遍历属性字典，直接通过哈希查表判定标签合法性；
  3. 消除内层嵌套循环，将时间复杂度从 $O(N \times M)$ 优化至 $O(N + M)$。

### 1.2 历史批次黑话标记清退（`HYG-STB-002` / `GOV-SAN-001`）
- **违规清单**：
  - `backend/domains/account/account_profile.gd:7`：含有 `# 设计依据: ... / Phase 02 施工细则规范`
  - `backend/domains/account/account_slot_binding_solver.gd:7`：含有 `# 设计依据: ... / Phase 02 施工细则规范`
  - `backend/domains/account/auth_service.gd:7`：含有 `# 设计依据: ... / Phase 02 施工细则规范`
- **改造方式**：
  将设计依据统一替换为标准中立领域契约：
  `# 设计依据: 业务领域第一性原理 / 账号与槽位生命周期契约`

### 1.3 重复字面量常量化提炼（`constants`）
- **违规清单**：
  - `account_profile.gd` 中字面量 `"domains.account"` 重复使用 5 次以上。
  - `account_slot_binding_solver.gd` 中字面量 `"domains.account"` 重复使用 3 次，错误码 `"success"` 与 `"error_code"` 分散手写。
- **改造方式**：
  在各文件顶部统一声明：
  ```gdscript
  const DOMAIN_ACCOUNT_CONFIG := "domains.account"
  ```
  将所有散落的 `GameConfig.get_*( "domains.account", ...)` 统一替换为常量引用，消除潜在拼写漂移。
