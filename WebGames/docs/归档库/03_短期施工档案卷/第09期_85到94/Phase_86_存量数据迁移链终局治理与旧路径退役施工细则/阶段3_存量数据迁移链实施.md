## 一、 存量数据迁移链实施方案

### 1.1 R-03：combat coordinator timeline_engine 必填化
- **落点文件**：`backend/domains/physics_thermodynamics/combat_round_coordinator.gd` 与测试夹具
- **空转引擎安全性**：`TertiaryTimelineEngine` 无参构造安全（`scheduled_events` 默认空，无 `_init` 强依赖）——空引擎 = 零调度事件 = 原 null 语义完全等价。
- **实施措施**：① 成员变量默认初始化改为 `= TertiaryTimelineEngine.new()`；② 展平时间推进卫语句（`fired_events = timeline_engine.advance_time(delta_ms)`）；③ 注释规范化；④ 展平快照段三元表达式；⑤ 测试夹具改用 `initialize(TertiaryTimelineEngineClass.new(), …)`。
- **验收结果**：`initialize(null` 全仓匹配恒为 0；测试断言（`test_combat_dual_random_and_timeline_pipeline.gd` 中 `_test_idle_engine_null_equivalence`）通过；战斗管线测试全绿。

### 1.2 R-02：口令加盐重铸链（login-time，不强制重置）
- **落点文件**：`backend/domains/account/account_profile.gd` 与 `backend/domains/account/auth_service.gd`
- **实施修正**：`config/domains/account.json auth.salt` 已非空（`KALAR_REALM_2026_SALT`）——业务语义明确收敛为「空盐历史档 login-time 重哈希迁移」。
- **实施措施**：① `account_profile.gd` 新增 `salt_version` 字段（新档默认 1 / 旧档缺省 0）及序列化往返；② `auth_service.authenticate_local` 双态校验：`salt_version==0` 先按空盐比对（`pass_plain.sha256_text()`），通过即重哈希落盘、升 `salt_version=1`、返回值携 `rehashed: true`；③ 注释对齐规范。
- **判定器标准**：全账号档 `salt_version==1` 占比 100% 即迁移完成（测试三态断言为行为证据）。
- **验收结果**：测试断言（`test_account.gd` 中 `test_salt_rehash_migration` 三态：重铸/新盐校验/错口令双态拒绝）全绿通过。

### 1.3 R-01：UID 单轨迁移判定器（五点退役路径本卷保留）
- **落点文件**：`backend/domains/persistence_protocol/save_assembler.gd`
- **防漂移红线**：五点兼容路径（generator LGC_ 放行 / entity migrate_legacy_uid / factory item_id_prefix / clawback item_id 回退 / matter_disposal legacy socket）为迁移期读路径，判定器证据落地前严禁删除。
- **实施措施**：`save_assembler.gd` 增 `audit_legacy_uid(payload_data)` 只读递归扫描判定器（LGC_ 前缀计数/实例总量/样本截取/`migration_complete` 判定）+ `_scan_uid_node` 递归体；完成契约 = 连续 2 个存档版本计数恒 0 → 后续批次退役五点并注销 W-01/W-03。
- **验收结果**：测试断言（`test_save_migration_engine.gd` 中 `test_legacy_uid_audit_detector`）全绿通过；五点文件 grep 计数与施工前基线一致（严格未提前删除）。
