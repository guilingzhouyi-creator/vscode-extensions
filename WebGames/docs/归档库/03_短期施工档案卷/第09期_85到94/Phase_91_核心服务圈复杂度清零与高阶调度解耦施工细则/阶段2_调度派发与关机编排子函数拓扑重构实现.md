## 一、 架构拓扑与解构设计

### 1. `event_bus_core.gd` 之 `dispatch_now` 解构拓扑

原函数 90 行，交织参数校验、缓冲复用初始化、专属频道收集、通配公共频道扫描、订阅者去重与安全遍历回调。重构为原子方法协作：

* **`_prepare_dispatch_scratch() -> void`**：
  * 集中复用并清理 `_target_scratch` 和 `_seen_scratch` 数组缓冲；
  * 确保派发热路径上的零瞬态分配与高承压稳定性。
* **`_collect_channel_subscribers(channel: String) -> void`**：
  * 负责安全收集指定频道下的有效订阅者；
  * 自动跳过失效 Callable 并维护 `_seen_scratch` 去重集合。

### 2. `game_lifecycle_service.gd` 之 `execute_graceful_shutdown` 解构拓扑

原函数 80 行，混合状态机合法性守卫、截止时间计算、存盘阶段执行、拆卸注销阶段执行与事件广播。重构为清晰的三阶段流水线：

* **`_guard_shutdown_entry() -> Dictionary`**：
  * 集中校验当前状态是否处于允许关机的生命周期阶段；
  * 若不允许则返回包含明确状态机错误码的拒绝字典。
* **`_execute_shutdown_save_stage(deadline_msec: int) -> Dictionary`**：
  * 依次调度存档服务持久化；
  * 校验是否超出 deadline，若超时则受控标记降级分支。
* **`_execute_shutdown_teardown_stage(deadline_msec: int) -> Dictionary`**：
  * 依次调度各领域服务注销与资源释放；
  * 校验注销结果并在超时时进入强制停机保护。
