# 03 跨平台门禁与脚本库架构 (`scripts/`)

> 本册映射 [WebGames/scripts/](../../../scripts/) 共 **101 个工程文件**（15 对同构 `ps1/` + `sh/` 脚本、65 个 `py/` 审计与工具脚本、3 个 `js/` Mermaid 校验器文件与 3 份 `config/` 声明式规则 JSON），构成项目本地与 CI 的自动审查中枢。

---

## 一、规则真源配置 (`scripts/config/`，3 份)

| 规则文件 | Schema / 驱动目标 | 管控范围 |
| :--- | :--- | :--- |
| [code_governance_rules.json](../../../scripts/config/code_governance_rules.json) | `audit_gd.py`（及 `gd/` 三规则包） | GDScript 4 命名风格、高级架构规范与简化防过度工程规则 |
| [docs_governance_rules.json](../../../scripts/config/docs_governance_rules.json) | `audit_docs.py`（及 `docs_audit/` 包） | 四域文档目录边界、文件名/目录名正则、四段式结构与档案头规范 |
| [value_domain_rules.json](../../../scripts/config/value_domain_rules.json) | `audit_config.py` | 声明式配置值域上下界、枚举白名单与非空约束 |

## 二、同构跨平台 Runner (`scripts/ps1/` & `scripts/sh/`，各 15 个)

Windows PowerShell 7+ 与 Linux/macOS Bash 保持 **1:1 职能镜像**（受 `audit_pair_parity.py` 强制校验参数面与退出码等价；详细规范见 [scripts/README.md](../../../scripts/README.md)）：

| 职能域 | 脚本对 | 核心作用 |
| :--- | :--- | :--- |
| 全量门禁 | `audit-all.{ps1,sh}` | 调用 `audit_runner.py` 异步并行调度静态门禁矩阵 |
| 定向审计 | `audit-arch` · `audit-docs` · `audit-perf` · `audit-refactor-metrics` | 分别驱动无头架构护栏、`audit_docs.py`、热点与性能门禁、auto-refactor 静态度量 |
| 测试与基准 | `test-run` · `bench-run` · `bench-sweep` | 运行无头单元测试与性能基准并聚合 JSON 报告 |
| 前置校验 | `check-env` · `check-gdscript` · `check-mermaid` | 校验工具链环境、单进程 Godot 语法批检查、调用 `scripts/js/validate-mermaid.mjs` 真解析 Mermaid |
| 归档打包与钩子 | `archive-volume` · `package-webgames` · `install-hooks` · `timestamp` | 路线图周期归档、导出 `.pck` + SHA-256、安装 Git 钩子、落施工时间戳 |

## 三、`audit_runner.py` 26 项注册任务矩阵 (`scripts/py/`)

总控门面 [audit_runner.py](../../../scripts/py/audit_runner.py) 支持 `--diff`（Git 增量域过滤）、`--slice`（定向切片）、`--task`、`-j`/`--serial` 并行度控制及 JSON/SARIF 输出：

### 3.1 `audit` 默认门禁组（23 项）

| `task_id` | 脚本 | 审查核心内容 |
| :--- | :--- | :--- |
| `config` | `audit_config.py` | JSON 格式（UTF-8 无 BOM/LF/2 空格）与 `value_domain_rules.json` 值域约束 |
| `gd` | `audit_gd.py` | 集成 `gd/{style,advanced,simplification}_rules.py` 全面扫描 `.gd` 质量 |
| `hardcode` | `audit_hardcode.py` | 魔法数字、调试 `print` 与非配置硬编码扫描（引号感知注释剥离） |
| `perf` | `audit_perf_hotspots.py` | 循环内分配、高频字符串拼接等性能热点扫描 |
| `coverage` | `audit_test_coverage.py` | 47 业务域与核心模块测试覆盖率基线检查 |
| `config_unused` | `audit_config_unused.py` | `config/` 死配置与未被源码引用的冗余键扫描 |
| `item_keys` | `audit_item_keys.py` | 物品 `canonical_id` / `english_name` / `loc_name_key` 标准三元组唯一性与规范核对 |
| `secrets` | `audit_secrets.py` | 硬编码密钥、口令、私钥与敏感凭证泄露扫描 |
| `bounds` | `audit_bounds.py` | 数值上下界钳制与物理量守恒防溢出校验 |
| `name_keys` | `audit_name_keys.py` | `LocalizationRegistryCatalog` 全局名称键跨表唯一性检查 |
| `copywriting` | `audit_copywriting.py` | `CopywritingResolver` 键格式、`{param}` 一致性与模板结构检查 |
| `magic_dimensions` | `audit_magic_dimensions.py` | 魔法属性（五行+风雷）与阶次双维度体系一致性 |
| `event_probability` | `audit_event_probability.py` | `event_probability` 事件流概率加权规则合法性 |
| `cdc` | `audit_cdc.py` | 配置驱动收口（Configuration-Driven Convergence）与单一真源审查 |
| `event_channels` | `audit_event_channels.py` | `EventBusCore` 信道注册声明与叙事发射一致性 |
| `refactor_metrics` | `audit_refactor_metrics.py` | 桥接 `auto-refactor` 静态圈复杂度、十维质量分审查（默认 `--strict`） |
| `arch` | `audit_arch_static.py` | 不依赖 Godot 可执行文件的纯 Python 静态架构依赖与领域清单自洽校验 |
| `docs` | `audit_docs.py` | 校验全文档库命名、布局、链接与 Mermaid 合法性，受 `benchmarks/reports/docs_baseline.json` 棘轮守卫 |
| `pair_parity` | `audit_pair_parity.py` | `scripts/ps1/` 与 `scripts/sh/` 15 对脚本参数面与退出码等价检查 |
| `script_comment` | `audit_script_comment.py` | 三语言（`.ps1`/`.sh`/`.py`）头注释七字段、严格模式守卫与无待办标记审计 |
| `sdk_sync` | `audit_sdk_sync.py` | `mod_sdk/` 与后端枚举/协议动作清单零漂移校验 |
| `code_clones` | `audit_code_clones.py` | 跨文件代码块克隆与重复逻辑域静态检测 |
| `script_adversarial` | `selftest_adversarial_guards.py` | 在隔离临时沙盒构建对抗绕过样本（注释伪装、引号遮蔽、`!=` 绕过、`push_error` 等）对本脚本库自身实施反证自检 |

### 3.2 `bench` 与 `archive` 专用组（3 项）

- `report_aggregate`（`report_aggregate.py`）：性能基准聚合、基线晋升（`--promote`）与门禁比对（`--gate`）。
- `report_sweep`（`report_sweep.py`）：多期 sweep 历史基线趋势合并扫描。
- `archive_volume`（`archive_volume.py`，依赖 `archive/` 九模块包，标记 `exclusive=True`）：短期施工区案卷周期检测（`--detect`）、满 10 卷归档（`--cycle`）与关键词重提取（`--reindex-keywords`）。
