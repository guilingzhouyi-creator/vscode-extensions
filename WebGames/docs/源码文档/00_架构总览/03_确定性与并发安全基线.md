# 确定性与并发安全基线

> 作为无头确定性推演引擎，WebGames 对随机数生成、热路径内存分配、事务幂等性、崩溃安全落盘以及敏感数据加密脱敏均设有硬性工程护栏。

---

## 一、确定性伪随机契约

引擎全域业务逻辑禁止调用 Godot 全局 `randf()`、`randf_range()`、`randi()`、`randi_range()` 或 `randomize()`（受 `TC-ARCH-04` 与 `audit_hardcode.py` 双重静态拦截），唯一合法随机数生成器为 [deterministic_rng.gd](../../../backend/infrastructure/deterministic_rng.gd)：

1. **配置驱动 LCG**：`DeterministicRNG` 采用线性同余算法，其默认乘数、增量、掩码与全局默认种子配置自 `domains.deterministic.core`。
2. **实例参数快照锁定**：在调用 `set_seed()` 或首次推进时将 LCG 参数固化到实例成员（`_lcg_multiplier_snap` 等），确保运行期配置热重载不会中途破坏已开始牌局的回放确定性；种子 `0` 自动归一为 `1` 防止退化为常数序列。
3. **统一签名约定**：业务求解器接受可选参数 `rng: DeterministicRNG = null`，内部经 `DeterministicRNG.resolve(rng_or_seed)` 归一（传入实例原样复用以保证十连等批量序列表现连续，正整数构造独立种子实例，空值回退共享 `DeterministicRNG.global()`）。

## 二、热路径零堆分配与池化架构

遵循性能边界约定（对应审查规则 `ADV-PRF-002`）：

| 机制 | 核心源码 | 设计意图与工作机制 |
| :--- | :--- | :--- |
| **事件对象池与环形队列** | [event_pool.gd](../../../backend/infrastructure/event_bus/event_pool.gd)、[ping_pong_ring_buffer.gd](../../../backend/infrastructure/event_bus/ping_pong_ring_buffer.gd) | 异步帧批处理复用固定容量 `EventPacket` 与双缓冲切换，避免帧循环高频 `.new()` |
| **递归深度暂存池** | [event_bus_core.gd](../../../backend/infrastructure/event_bus/event_bus_core.gd) | 同步嵌套广播按 `_dispatch_depth` 索引复用 `_target_scratch`、`_seen_scratch` 与 `_dead_tokens_scratch` |
| **中央对象池注册表** | [object_pool_manager.gd](../../../backend/infrastructure/object_pool_manager.gd)、[object_pool.gd](../../../backend/infrastructure/object_pool.gd) | 按 `infrastructure.object_pool` 配置预分配池容量与溢出警告阈值，支持 `teardown()` 对称清理 |
| **SoA 实体连续缓冲** | [soa_entity_buffer.gd](../../../backend/infrastructure/soa_entity_buffer.gd) | 将实体标量字段拆分为连续结构体数组（Structure of Arrays），减少批量计算缓存失效 |
| **资源生命周期追踪** | [resource_lifecycle_manager.gd](../../../backend/infrastructure/resource_governance/resource_lifecycle_manager.gd) | 显式追踪非 `RefCounted` 节点状态跃迁（`INITIALIZED -> IN_USE -> IDLE -> RELEASED -> DISPOSED`），防止双重释放与悬挂节点 |

## 三、崩溃安全落盘与幂等控制

1. **三阶段原子写原语**（[atomic_file_writer.gd](../../../backend/infrastructure/atomic_file_writer.gd)）：
   - 写入唯一临时后缀 `.tmp` 并校验底层写盘错误码；
   - 按 `retention` 参数执行历史备份轮转（`.bak` -> `.bak.1` ...）；
   - 执行原子 `rename` 替换目标正档，并在启动入口调用 `cleanup_orphan_tmp_files()` 回收中断遗留临时文件。
2. **存档单字段哈希防篡改**（[save_manager.gd](../../../backend/infrastructure/save_manager.gd)）：
   - 存档信封仅存唯一载荷字符串 `data_json`，禁止保留平行可写的 `data` 对象；
   - 写入计算 `data_json` 的 SHA-256 存入 `signature_sha256`，读盘时先验摘要再反序列化，拒收缺失签名的历史信封（`INVALID_ENVELOPE`）；同时拦截路径分隔符与 `..` 目录穿越。
3. **事务滑动窗口去重**（[idempotency_controller.gd](../../../backend/infrastructure/robustness/idempotency_controller.gd)）：
   - 对并发双发或重试请求的 `operation_token` 使用有序字典执行 $O(1)$ 均摊 FIFO 淘汰，保证高危状态修改仅生效一次。

## 四、密码学域库与日志脱敏审计

1. **纯计算密码学域库**（[crypto_integrity_lib.gd](../../../backend/infrastructure/pure/crypto_integrity_lib.gd)）：
   - 统一封装 SHA-256、加盐域隔离摘要 `salted_hash_hex`、HMAC-SHA256、常量时间字符串比对 `constant_time_equals`（防时序侧信道）、PKCS7 填充及 AES-256-CBC Encrypt-then-MAC 算子；
   - 主密钥经上下文标签派生出独立的加密子密钥与认证子密钥（`derive_subkey_32`）；密封密钥仅经受控环境变量解析，禁止硬编码在代码或明文 JSON 中。
2. **双阶段日志脱敏与防篡改链**（[redaction_rule.gd](../../../backend/infrastructure/redaction_rule.gd)、[log_file_exporter.gd](../../../backend/infrastructure/log_file_exporter.gd)、[statistics_math_lib.gd](../../../backend/infrastructure/pure/statistics_math_lib.gd)）：
   - 构造期由 `RedactionRule` 按 `infrastructure.log` 的规则匹配上下文键值并执行 `mask` / `drop` / `hash` / `salted_hash`；
   - 二次内联洗净 `StatisticsMathLib.scrub_inline_secrets()` 在落盘/输出前清除消息文本中偶发的 `password=`、`Bearer`、邮箱与本机用户目录名；
   - 导出文件通过互斥锁 `_io_mutex` 串行追加并串联哈希链，可选启用 AES-256-CBC + HMAC 日志审计信封保护。
3. **客户端内存凭据混淆**（[client_secret_vault.gd](../../../backend/infrastructure/client_secret_vault.gd)）：
   - 在客户端内存中对活跃会话令牌执行对称 LCG 流掩码保护与 FNV-1a 上下文种子推导，由 `GameBootstrap` 经依赖倒置回调注入 `WorldSessionRuntimeService`。
