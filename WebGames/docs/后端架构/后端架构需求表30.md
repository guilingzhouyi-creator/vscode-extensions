# 后端架构需求表30（第三十卷：空间邻近感知、地缘商铺集市与动态货架交易系统）

> [!IMPORTANT]
> **【系统定性与第一性原理】**：
> 本卷定义卡拉尔高魔世界引擎的**物理地缘邻近触发 (Spatial Proximity Trigger)、实体商铺实体 (Physical Merchant Shop Entity)、动态有限库存与时效神秘游荡商人中枢**。系统必须满足：
> 1. **拒绝全知全能隔空商城 (No Ubiquitous Floating Shop)**：
>    - 严禁任何玩家随时随地凭借空打开商城购买万物的非真实机制；
>    - 玩家必须肉身位于商铺、集市摊位、或者游荡商人的有效交互辐射半径内（如 $R \le 3.0\text{m}$ 或处于同一城镇建筑子图节点），方可建立交易会话；
> 2. **三类商铺形态与地缘货架 (Shop Category Topology)**：
>    - **定居点常驻官方店铺 (Fixed Town Stores)**：铁匠铺、炼金药房、杂货铺、魔法公会物资部；
>    - **黑市流动摊贩 (Underground Black Market)**：深夜出现在暗巷或下水道，贩卖违禁手稿、淬毒武器与无名赃物；
>    - **地脉游荡神秘商人 (Roaming Leyline Peddler)**：在大地图七大洲巡游，随机停靠在定居点，贩卖限量传奇图纸与魔单晶异宝，停留时限耗尽即自发拔营转移；
> 3. **有限库存与局部供需动态价格 (Finite Stock & Elastic Pricing)**：
>    - 商铺库存由实体仓储驱动，买一件少一件；货架依据《第十一卷》集市供需价格弹性自发涨跌；
> 4. **空间断开自动阻断事务 (Proximity Guard & Transaction Safe)**：
>    - 交易过程中若玩家移动超出交互半径，或遭遇战斗被击退，系统自发安全中断交易会话，杜绝挂机卡交易漏洞。

## 二、 空间邻近检定与货架购买求解器 (`ShopProximityTransactionSolver`)

```gdscript
# 脚本路径: res://core/domain/shop/shop_proximity_transaction_solver.gd
class_name ShopProximityTransactionSolver
extends RefCounted

# 检定空间邻近性
static func is_player_in_shop_range(
    player_town_id: String,
    player_pos: Vector2,
    shop: MerchantShopAggregate
) -> bool:
    if player_town_id != shop.location_town_id:
        return false
    var dist = player_pos.distance_to(shop.local_position)
    return dist <= shop.interaction_radius_meters

# 执行购买交易
static func execute_purchase(
    player_town_id: String,
    player_pos: Vector2,
    shop: MerchantShopAggregate,
    shelf_index: int,
    buy_count: int,
    player_wallet: Dictionary,
    player_inventory: RefCounted
) -> Dictionary:
    # 1. 空间距离强制断言
    if not is_player_in_shop_range(player_town_id, player_pos, shop):
        return { "success": false, "code": "ERR_OUT_OF_RANGE", "msg": "冒险者已远离商铺柜台，无法完成选购" }

    if shelf_index < 0 or shelf_index >= shop.shelf_inventory.size():
        return { "success": false, "code": "ERR_INVALID_SHELF", "msg": "货架货物不存在" }

    var shelf_item = shop.shelf_inventory[shelf_index]
    if shelf_item["stock_count"] < buy_count:
        return { "success": false, "code": "ERR_OUT_OF_STOCK", "msg": "该货品库存不足" }

    var total_cost = shelf_item["base_price"] * buy_count
    var currency = shelf_item.get("currency", "SILVER")

    if player_wallet.get(currency, 0) < total_cost:
        return { "success": false, "code": "ERR_INSUFFICIENT_FUNDS", "msg": "随身货币不足以支付该货品" }

    # 原子扣款与出货
    player_wallet[currency] -= total_cost
    shelf_item["stock_count"] -= buy_count

    return {
        "success": true,
        "item_template_id": shelf_item["item_template_id"],
        "purchased_count": buy_count,
        "total_cost": total_cost,
        "remaining_stock": shelf_item["stock_count"]
    }
```

## 三、 邻近交易求解器与游商生命周期 (`ShopProximityTransactionSolver`)

1. **肉身邻近检定**：以 `interaction_radius_meters` 圆形半径强制空间邻近，超出即 OUT_OF_PROXIMITY_RANGE——拒绝隔空商城；
2. **货架库存守卫**：超额购买拦截 INSUFFICIENT_STOCK；成交即时扣减 `stock_count` 与买家钱包，账实同步；
3. **游商生命周期**：`RoamingMerchantFSM.spawn_roaming_peddler` 按时效生成临时摊位，`is_peddler_active` 依撤摊时间戳判定存续，超时自动收摊。

**归档细则**：阶段 3 施工细则 `KALAR-DEV-2026-RM30-003`（见归档库档案卷）。
