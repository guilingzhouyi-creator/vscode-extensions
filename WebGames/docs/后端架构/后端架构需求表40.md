# 后端架构需求表40（第四十卷：全域通知弹窗、系统跑马灯与有向红点树状态机）

> [!IMPORTANT]
> **【系统定性与第一性原理】**：
> 本卷定义卡拉尔高魔世界引擎的**全域通知调度 (Notification Dispatcher)、阻塞弹窗数据契约、全服跑马灯 (Banner Marquee) 与有向无环红点树 (Red-Dot Hierarchy DAG) 状态机**。系统必须满足：
> 1. **通知四级拓扑分类 (Four-Tier Notification Topology)**：
>    - `TOAST` (轻量浮动气泡): 简短提示（如“背包已满”、“获得100金币”），3秒自动淡出；
>    - `MODAL_DIALOG` (阻塞式二次确认弹窗): 带有确认/取消动作回调契约（如“确认分解史诗武器？”）；
>    - `BANNER_MARQUEE` (全服跑马灯公告): 顶部滚动世界大事件或GM广播（如“玩家获得了圣杯！”）；
>    - `SYSTEM_TRAY` (系统角标/右下角抽屉): 邮件到达、好友申请常驻提示；
> 2. **有向红点树自发冒泡算法 (Red-Dot DAG Bubble-Up Algorithm)**：
>    - 红点系统采用父子树状拓扑（如 `root -> character -> equipment -> slot_chest`）；
>    - 叶子节点发生变动时（新装备、可领邮件、新称号），红点计数自发向上递归汇总；父节点计数等于所有子节点之和；子节点清空父节点自发消失；
> 3. **前端渲染完全解耦与数据推流 (Renderer Agnostic & Event Push)**：
>    - 后端仅维护纯数据状态机与 DTO 流，前端图形 UI 或文本终端仅需监听 `NotificationEventStream` 即可即时呈现。

## 一、 红点树节点与通知实体 (`RedDotTreeNode` & `NotificationDTO`)

```gdscript
# 脚本路径: res://core/domain/notification/red_dot_tree_node.gd
class_name RedDotTreeNode
extends RefCounted

var node_path: String                       # 如 "menu.mail.unread"
var parent_path: String = ""                # 如 "menu.mail"
var direct_count: int = 0                   # 本身直接计数
var total_aggregated_count: int = 0         # 包含全部子节点的聚合计数
var children_paths: Array[String] = []

class NotificationDTO extends RefCounted:
    enum NoticeType { TOAST, MODAL_DIALOG, BANNER_MARQUEE, SYSTEM_TRAY }
    var notice_id: String
    var type: NoticeType = NoticeType.TOAST
    var title_loc_key: String = ""
    var content_loc_key: String = ""
    var params: Dictionary = {}
    var auto_dismiss_seconds: float = 3.0
    var actions_payload: Array[Dictionary] = [] # 弹窗按钮集 [{"label": "confirm", "action": "DO_BUY"}]
```

## 二、 红点树递归汇总求解器 (`RedDotTreeSolver`)

```gdscript
# 脚本路径: res://core/domain/notification/red_dot_tree_solver.gd
class_name RedDotTreeSolver
extends RefCounted

# 递归重算节点与其父级链总红点数
static func recalculate_node_upwards(registry: Dictionary, start_node_path: String) -> void:
    if not registry.has(start_node_path):
        return

    var node: RedDotTreeNode = registry[start_node_path]
    var sub_sum = node.direct_count
    for c_path in node.children_paths:
        if registry.has(c_path):
            var child: RedDotTreeNode = registry[c_path]
            sub_sum += child.total_aggregated_count

    node.total_aggregated_count = sub_sum

    # 向上冒泡通知父节点
    if node.parent_path != "" and registry.has(node.parent_path):
        recalculate_node_upwards(registry, node.parent_path)
```

## 三、 红点树递归汇总求解器与通知管线 (`RedDotTreeSolver`)

1. **叶子冒泡聚合**：`set_node_direct_count` 变动叶子直接计数后沿父链递归汇总 `total_aggregated_count`，红点自发向上冒泡；
2. **消除自适应同步**：`recalculate_node_upwards` 在子节点清零后父级数量即时扣减，全树数量恒自洽；
3. **四级通知拓扑**：`NotificationPipeline.push_notification` 以纯数据 DTO（TOAST / MODAL_DIALOG / BANNER / SYSTEM_TRAY）推流入列，前端图形或文字终端解耦渲染。

**归档细则**：阶段 3 施工细则 `KALAR-DEV-2026-RM40-003`（见归档库档案卷）。
