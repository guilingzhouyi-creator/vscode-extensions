# 后端架构需求表28（第二十八卷：组织委托悬赏派发、冒险者阶位资质与佣金抽成结算求解器）

> [!IMPORTANT]
> **【系统定性与第一性原理】**：
> 本卷定义卡拉尔高魔世界引擎依托《第二十七卷》各大组织的**委托布告栏系统 (Commission Board)、冒险者阶位评级 (Adventurer Tiers)、悬赏质押与佣金分成结算中枢**。系统必须满足：
> 1. **双源委托生成流 (Dual-Source Commission Dispatch)**：
>    - **世界生态自发委托 (System Emergent Bounties)**：城镇因魔素浓度畸变、魔兽袭村、商队护送自发涌现的委托；
>    - **玩家/NPC 匿名悬赏 (Player/NPC Private Bounties)**：玩家出资悬赏仇敌项上人头、委托收集特定稀有草药或护卫自建商队；
> 2. **冒险者阶位与准入门槛约束 (Adventurer Tier Gating)**：
>    - 冒险者公会评级体系（木牌 $\rightarrow$ 铁牌 $\rightarrow$ 铜牌 $\rightarrow$ 银牌 $\rightarrow$ 金牌 $\rightarrow$ 秘银 $\rightarrow$ 秘钻级）；
>    - 委托阶位严格挂钩接取人评级，防止越级自杀式滥领；
> 3. **佣金质押与组织抽成结算方程 (Commission Tax & Staking Solver)**：
>    - 发布委托需全额质押赏金 + 缴纳发布税费；
>    - 交付验收后，组织自发抽取管理手续费（如 5%~10%）注入《第二十七卷》组织金库，余款打入完成者钱包；
> 4. **履约保证金与信誉黑名单惩罚状态机 (Breach of Contract & Default Penalties)**：
>    - 放弃委托或超时未完成，扣除承接押金，降低公会信誉积分；严重者列入全大陆冒险者公会失信通缉黑名单。

## 一、 冒险委托领域聚合实体 (`CommissionAggregate`)

```gdscript
# 脚本路径: res://core/domain/commission/commission_aggregate.gd
class_name CommissionAggregate
extends RefCounted

enum CommissionTier {
    WOOD = 1,       # 木牌 (见习)
    IRON = 2,       # 铁牌 (初阶)
    BRONZE = 3,     # 铜牌 (中阶)
    SILVER = 4,     # 银牌 (高阶)
    GOLD = 5,       # 金牌 (大师)
    MYTHRIL = 6,    # 秘银 (英雄)
    ADAMANTITE = 7  # 秘钻 (传说天灾级)
}

enum CommissionStatus {
    POSTED_AVAILABLE,   # 挂板可接取
    ACCEPTED_IN_PROGRESS,# 已接取进行中
    COMPLETED_PENDING,  # 目标达成待结算
    SETTLED_SUCCESS,    # 已验收结算完毕
    FAILED_DEFAULTED    # 超时/放弃/违约已失效
}

var commission_id: String                   # 委托全局唯一 ID
var issuing_org_id: String                  # 发行承办组织 ID (如 "ORG_ADVENTURER_GUILD_CENTRAL")
var publisher_account_id: String            # 雇主 ID (NPC_ID 或 玩家 Account_ID)
var title_key: String                       # 委托标题
var required_tier: CommissionTier = CommissionTier.WOOD

# 经济与赏金
var reward_gold: int = 100
var reward_mana_crystals: int = 0
var org_tax_rate: float = 0.05              # 组织抽成比例 (默认 5%)
var security_deposit_required: int = 10     # 接取人需押付的履约保证金

# 状态与时效
var status: CommissionStatus = CommissionStatus.POSTED_AVAILABLE
var assignee_account_id: String = ""        # 承接者账户 ID
var time_limit_seconds: float = 3600.0      # 倒计时时限
var elapsed_seconds: float = 0.0
```

## 二、 委托交付与佣金分成求解器 (`CommissionSettlementSolver`)

```gdscript
# 脚本路径: res://core/domain/commission/commission_settlement_solver.gd
class_name CommissionSettlementSolver
extends RefCounted

# 结算成功完成的委托
static func settle_successful_commission(
    commission: CommissionAggregate,
    org: OrganizationAggregate,
    contractor_wallet: Dictionary
) -> Dictionary:
    if commission.status != CommissionAggregate.CommissionStatus.ACCEPTED_IN_PROGRESS:
        return { "success": false, "code": "ERR_INVALID_STATUS", "msg": "委托未处于可交付状态" }

    var gross_gold = commission.reward_gold
    var gross_crystals = commission.reward_mana_crystals

    # 1. 计算公会管理抽成
    var org_cut_gold = int(float(gross_gold) * commission.org_tax_rate)
    var org_cut_crystals = int(float(gross_crystals) * commission.org_tax_rate)

    var net_gold = gross_gold - org_cut_gold + commission.security_deposit_required # 退还押金
    var net_crystals = gross_crystals - org_cut_crystals

    # 2. 注入组织金库
    org.treasury_gold_coins += org_cut_gold
    org.treasury_mana_crystals += org_cut_crystals

    # 3. 注入冒险者钱包
    contractor_wallet["gold"] = contractor_wallet.get("gold", 0) + net_gold
    contractor_wallet["mana_monocrystals"] = contractor_wallet.get("mana_monocrystals", 0) + net_crystals

    commission.status = CommissionAggregate.CommissionStatus.SETTLED_SUCCESS

    return {
        "success": true,
        "net_gold_received": net_gold,
        "net_crystals_received": net_crystals,
        "org_cut_gold": org_cut_gold,
        "status": "SETTLED"
    }
```

## 三、 委托全生命周期状态机 (`CommissionFSM`)

1. **接取守卫链**：状态必须为 POSTED_AVAILABLE → `check_qualification` 阶位门槛（不足返回 TIER_TOO_LOW）→ 保证金足额检定（不足 INSUFFICIENT_DEPOSIT），全过才扣质押金并进入 ACCEPTED_IN_PROGRESS；
2. **验收结算**：`settle_successful_commission` 按 (1 − 组织抽成) 发放赏金、全额退还保证金，税费自动划扣入公会金库，状态迁移 SETTLED_SUCCESS；
3. **违约处置**：`handle_commission_breach` 没收履约保证金全额转入公会金库，状态迁移 FAILED_DEFAULTED 并计入失信记录。

**归档细则**：阶段 3 施工细则 `KALAR-DEV-2026-RM28-003`（见归档库档案卷）。
