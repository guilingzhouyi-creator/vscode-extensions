# 后端架构需求表43（第四十三卷：账号 UID 物品 ID 库统计系统——递归挂载聚合与物品生命周期事件）

> [!IMPORTANT]
> **【系统定性与第一性原理】**：
> 本卷定义卡拉尔高魔世界引擎的**账号物品统计中枢**。系统必须满足：
> 1. **UID 下挂载物品 ID 库（递归树）**：每个账号 UID 为根，物品按注册表分类递归挂载为
>    `category_major → category_minor → canonical_id` 叶节点；分类节点沿路径递归聚合子树统计；
> 2. **物品全生命周期事件契约**：获得/消耗/销毁/交易/锻造/追缴六类事件经 `ItemStatisticsSolver`
>    落账并旁路遥测（复用《第四十二卷》环形缓冲底座），事件名约定 `"<域>.<事件>"`；
> 3. **账号隔离与 RBAC 门禁**：查询一律按账号 UID 隔离（各自操作自己的库）；跨账号全局聚合需
>    `LEVEL_GAME_MASTER` 权限门槛（配置 `global_query_min_level`，默认 2）；
> 4. **减量下限 0**：消耗/销毁/追缴触底钳制，当前持有不可为负；累计量永久保留。

---

## 一、 账号物品 ID 库聚合根（递归挂载树） (`AccountItemLibraryAggregate`)

树结构：**根(account_id) → category_major → category_minor → canonical_id 叶节点**。

| 递归操作 | 语义 |
| :--- | :--- |
| `mount_item(canonical_id, major, minor)` | 递归建路径（幂等），缺省分类 UNCATEGORIZED / UNSPECIFIED |
| `apply_item_delta(canonical_id, stat_key, quantity)` | 递归定位叶节点落账，减量下限 0，自底向上递归重算分类聚合 |
| `query_subtree(major, minor)` | 递归聚合分类子树（缺省 = 全树） |
| `query_all_items()` | 递归收集叶节点（账号全量物品清单） |

叶节点七维统计：`current_quantity / total_gained / total_consumed / total_destroyed / total_traded / total_forged / total_clawed_back`。

---

## 二、 物品生命周期事件契约 (`ItemStatisticsSolver`)

| 事件 | 语义 | 库统计键（对当前持有） |
| :--- | :--- | :--- |
| `item.granted` | 发放（GM give / gacha 掉落 / CDKey 兑换 / 礼包直发 / 邮件附件 / 商店购买） | total_gained（+） |
| `item.consumed` | 消耗 | total_consumed（−） |
| `item.destroyed` | 销毁 / 装备分解 | total_destroyed（−） |
| `item.traded` | 交易流出 | total_traded（−） |
| `item.forged` | 锻造 / 分解产出（炉渣、魔素尘埃） | total_forged（+） |
| `item.clawed_back` | 追缴（`ClawbackService` 回扣） | total_clawed_back（−） |

事件接入经 `record_item_event(library, event, canonical_id, quantity, catalog, telemetry)`：
按注册表分类递归挂载 + 落账 + 旁路遥测落点（环形缓冲，事件带账号 UID 维度）。

---

## 三、 查询与隔离门禁

- **账号内查询**（UID 天然隔离，仅操作该账号自己的库）：
  `query_account_item_stats` / `query_account_subtree` / `query_account_all`；
- **跨账号全局聚合**：`query_global_item_stats(libraries, canonical_id, admin_level)`——
  `admin_level < global_query_min_level` 时返回 `STATS_GLOBAL_FORBIDDEN`，聚合返回
  `current_quantity`、六类累计量与该物品涉及账号数 `account_count`。

---

## 四、 接入链路

- **发放**：GM give / gacha 掉落 / CDKey 兑换 / 礼包直发 / 邮件附件 → `item.granted`；追缴 → `item.clawed_back`；
- **消耗**：商店购买（商品进包 → granted）、销毁管线（原物品 → destroyed + 渣/尘产出 → forged）、装备分解（→ destroyed）；
- **强化/重铸为原地修改**（无物品进出背包），不产生物品流转事件。

---
