# 后端架构需求表36（第三十六卷：全域物品统一命名空间、ID 注册表与分类学元数据注册系统）

> [!IMPORTANT]
> **【系统定性与第一性原理】**：
>
> 本卷定义卡拉尔高魔世界引擎的**全局物品分类学命名空间 (Item Taxonomy Namespace)、不可变标准 ID 注册表 (Canonical Item Registry)、多语言本地化键与动态别名索引中枢**。系统必须满足：
> 1. **分级命名空间与 ID 编码规范 (Hierarchical Namespace & ID Standard)**：
>    - 物品 ID 严禁混乱无序命名，统一采用分级命名空间格式：
>      `[DOMAIN]:[CATEGORY]:[SUBCATEGORY]:[ITEM_TAG]` (如 `KALAR:EQUIP:WEAPON_BLADE:MITHRIL_LONGSWORD`)；
>    - **底层名称三元组规范**：**ID**（canonical_id / numeric_id，后端逻辑判定）+ **统一英文名**（`english_name`，如 `mithril_longsword`，底层规范化标准，GM 命令唯一合法输入）+ **i18n**（`loc_name_key` 本地化键，前端按区域呈现）；
>    - 内部全局映射至压缩整型 `ItemID (int)` 与字符串标准键双向无损转换，保障内存极致紧凑与高效查找；
> 2. **不可变注册表与元数据字典 (Immutable Item Registry & Metadata Catalog)**：
>    - 启动时自动从 `config/items/*.json` 加载全量物品原型模板 (`ItemPrototypeTemplate`)；
>    - 声明核心固有物理参数（质量、体积、基础硬度、基础槽位数、物品大类）；
> 3. **多语言与通俗别名反向模糊检索 (I18N Keys & Alias Inverted Index)**：
>    - 每件物品绑定唯一 `loc_key`（如 `item.mithril_longsword.name`）；
>    - 支持别名与民间俗称注册（如“秘银剑”、“蓝晶长刃”），支持聊天框/GM指令/集市交易的极速模糊查表；
> 4. **动态 MOD 扩展与防冲突撞库校验器 (Dynamic Extension & Collision Guard)**：
>    - 支持未来 DLC 或 MOD 注册动态扩展物品，注册前执行强类型校验与 ID 冲突断言，杜绝覆盖覆写灾难；
> 5. **数字 ID 自动递增与删除回收 (Auto-increment & Recycle)**：
>    - 未显式指定数字 ID 的物品由注册表自动递增分配（回收的空闲 ID 优先复用）；
>    - 配置删除物品后自动注销并回收其数字 ID 与名称键，防止 ID 空洞与名称键残留。

## 一、 物品元数据注册表领域实体 (`ItemRegistryCatalog`)

```gdscript
# 脚本路径: res://backend/domains/item_namespace_registry/item_registry_catalog.gd
class_name ItemRegistryCatalog
extends RefCounted

class ItemPrototypeTemplate extends RefCounted:
    var canonical_id: String               # 如 "KALAR:EQUIP:WEAPON_BLADE:MITHRIL_LONGSWORD"
    var english_name: String = ""          # 统一英文名（底层规范，如 "mithril_longsword"；必填，注册时小写归一，仅允许 [a-z0-9_]）
    var numeric_id: int = 0                # 压缩数字 ID (1~N)
    var loc_name_key: String               # "item.mithril_longsword.name"
    var loc_desc_key: String               # "item.mithril_longsword.desc"
    var category_major: String             # "EQUIPMENT" / "CONSUMABLE" / "MATERIAL" / "QUEST"
    var category_minor: String             # "WEAPON_BLADE" / "POTION" / "ORE"
    var tier_rank: int = 1                 # 品阶 (1:普通, 2:精良, 3:稀有, 4:史诗, 5:传说, 6:神圣)
    var default_mass_kg: float = 1.5
    var default_volume_slots: int = 2
    var base_market_value: int = 100
    var search_aliases: Array[String] = [] # 别名列表

# 字符串键 -> ItemPrototypeTemplate
var _canonical_registry: Dictionary = {}
# 压缩数字 ID -> Canonical String ID
var _numeric_to_canonical: Dictionary = {}
# 本地化展示名键 -> Canonical String ID（名称键唯一性校验索引）
var _loc_key_to_canonical: Dictionary = {}
# 统一英文名（小写）-> Canonical String ID（GM 命令/底层规范化解析索引）
var _english_name_to_canonical: Dictionary = {}
# 别名/名称倒排索引 (lowercase_term -> Array[canonical_id])
var _alias_inverted_index: Dictionary = {}
# 数字 ID 分配高水位（单调递增，仅记录已分配过的最大 ID）
var _highest_numeric_id: int = 0
# 已释放数字 ID 空闲池（升序，分配时优先复用，实现「删除回收」）
var _freed_numeric_ids: Array[int] = []

func allocate_numeric_id() -> int: ...    # 优先复用空闲池最小 ID，否则高水位 +1（自动递增占用）
func occupy_numeric_id(num_id: int) -> void: ...  # 显式 ID 从空闲池移除并刷新高水位
func release_numeric_id(num_id: int) -> void: ... # 注销后数字 ID 释放回空闲池
```

## 二、 命名规范校验与模糊查表求解器 (`ItemRegistrySolver`)

```gdscript
# 脚本路径: res://backend/domains/item_namespace_registry/item_registry_solver.gd
class_name ItemRegistrySolver
extends RefCounted

# 校验 ID 命名空间是否合法
static func validate_canonical_id_format(canonical_id: String) -> bool:
    var parts = canonical_id.split(":")
    if parts.size() < 4:
        return false
    if parts[0] != "KALAR":
        return false
    return true

# 注册物品原型模板（数字 ID <= 0 时自动递增分配）
static func register_prototype(catalog: ItemRegistryCatalog, proto: ItemRegistryCatalog.ItemPrototypeTemplate) -> Dictionary:
    if not validate_canonical_id_format(proto.canonical_id):
        return { "success": false, "code": "ERR_INVALID_ID_FORMAT", "msg": "物品 ID 未遵循 KALAR:[MAJOR]:[MINOR]:[TAG] 命名空间规范" }

    if catalog._canonical_registry.has(proto.canonical_id):
        return { "success": false, "code": "ERR_ID_COLLISION", "msg": "物品 ID 冲突: %s 已存在" % proto.canonical_id }

    if proto.english_name.is_empty():
        return { "success": false, "code": "ERR_ENGLISH_NAME_MISSING", "msg": "缺少统一英文名: %s" % proto.canonical_id }

    if not proto.loc_name_key.is_empty() and catalog._loc_key_to_canonical.has(proto.loc_name_key):
        return { "success": false, "code": "ERR_NAME_KEY_COLLISION", "msg": "展示名键冲突: %s 已被占用" % proto.loc_name_key }

    if not proto.english_name.is_empty() and catalog._english_name_to_canonical.has(proto.english_name):
        return { "success": false, "code": "ERR_ENGLISH_NAME_COLLISION", "msg": "统一英文名冲突: %s 已被占用" % proto.english_name }

    if proto.numeric_id <= 0:
        proto.numeric_id = catalog.allocate_numeric_id()
    elif catalog._numeric_to_canonical.has(proto.numeric_id):
        return { "success": false, "code": "ERR_NUMERIC_COLLISION", "msg": "数字 ID 冲突: %d 已被占用" % proto.numeric_id }

    catalog._canonical_registry[proto.canonical_id] = proto
    catalog._numeric_to_canonical[proto.numeric_id] = proto.canonical_id
    catalog.occupy_numeric_id(proto.numeric_id)
    if not proto.loc_name_key.is_empty():
        catalog._loc_key_to_canonical[proto.loc_name_key] = proto.canonical_id
    if not proto.english_name.is_empty():
        catalog._english_name_to_canonical[proto.english_name] = proto.canonical_id

    # 别名倒排索引去重（空别名与同物品重复别名忽略）
    for alias in proto.search_aliases:
        var key = alias.to_lower().strip_edges()
        if key.is_empty():
            continue
        if not catalog._alias_inverted_index.has(key):
            catalog._alias_inverted_index[key] = []
        if proto.canonical_id not in catalog._alias_inverted_index[key]:
            catalog._alias_inverted_index[key].append(proto.canonical_id)

    return { "success": true, "canonical_id": proto.canonical_id, "numeric_id": proto.numeric_id }

# 注销物品原型（配置删除后的回收入口）：清理四表并将数字 ID 释放回空闲池
static func unregister_prototype(catalog: ItemRegistryCatalog, canonical_id: String) -> Dictionary:
    var proto = catalog._canonical_registry.get(canonical_id)
    if proto == null:
        return { "success": false, "code": "ERR_NOT_FOUND", "msg": "物品不存在: %s" % canonical_id }
    # 倒排索引回退 / 数字映射 / 名称键 / 主表清理 + release_numeric_id(proto.numeric_id)
    ...
    return { "success": true, "canonical_id": canonical_id, "numeric_id": proto.numeric_id }
```

## 三、 注册表目录与防撞求解器 (`ItemRegistrySolver`)

1. **Canonical ID 格式校验**：`validate_canonical_id_format` 强制 `KALAR:[MAJOR]:[MINOR]:[TAG]` 四段结构与 KALAR 全宗前缀（空段即拒），非法命名空间即拒；
2. **数字 ID 自动递增分配**：`numeric_id <= 0` 的条目由 `allocate_numeric_id` 自动分配（回收的空闲 ID 优先复用），显式重复数字 ID 返回 `ERR_NUMERIC_COLLISION`，杜绝静默覆盖；
3. **ID 防撞库**：`register_prototype` 对重复 canonical_id 返回 ERR_ID_COLLISION、展示名键重复返回 ERR_NAME_KEY_COLLISION，注册表不可变元数据一经登记不可覆盖；
4. **别名倒排检索与去重**：多语言通俗别名建倒排索引（同物品重复别名与空别名忽略），`resolve_search_term` 支持中英文模糊命中 canonical_id；
5. **删除回收**：`unregister_prototype` 清理主表/数字映射/名称键/倒排索引并将数字 ID 释放回空闲池；`ItemLoaderPipeline.reload_from_config` 按配置差异自动注销已删除物品、增量注册新增物品；
6. **配置批量装载与装配**：`ItemLoaderPipeline.build_catalog_from_config` 自动发现 `config/items/*.json`（表名 `items.<name>`，MOD 新增文件即收录）并批量实例化原型模板；
7. **统一英文名严格解析**：`resolve_by_english_name` 仅按英文规范化名称（大小写不敏感）解析——中文别名、数字 ID、canonical_id 一律拒绝，是 GM `/give` 的唯一合法入口；重复英文名返回 ERR_ENGLISH_NAME_COLLISION。

**归档细则**：阶段 3 施工细则 `KALAR-DEV-2026-RM36-003`（见归档库档案卷）。
