# 后端架构需求表25（第二十五卷：全域邮件信箱、系统公告附件与仓储生命周期系统）

> [!IMPORTANT]
> **【系统定性与第一性原理】**：
> 本卷定义卡拉尔高魔世界引擎的**全域异步邮件传输、系统维护补偿、活动奖励附件暂存与信箱仓储生命周期中枢**。系统必须满足：
> 1. **全域异步解耦投递 (Universal Asynchronous Delivery)**：
>    - 玩家离线时，来自《第二十四卷》兑换码、《第二十三卷》世界 BOSS 结算、《第二十卷》GM 补偿的奖励均可安全投递入信箱；
> 2. **三类邮件形态与优先流转 (Mail Category Topology)**：
>    - **系统重要邮件 (System Critical)**：带重要魔单晶/装备附件或官方停服公告，附带过期倒计时，严防被误清理；
>    - **公会/社交信件 (Social Mail)**：NPC 故人书信、阵营通告与玩家间信件；
>    - **日常战报与拍卖行结算邮件 (Transaction Receipts)**：高频交易通知，支持自动归档；
> 3. **附件原子提取与防背包溢出 (Atomic Attachment Claiming)**：
>    - 支持“一键领取所有附件”，领取前执行背包容量检定；
>    - 若随身背包空间不足，支持部分提取并精准提示已存满部位，未领取的附件仍安全留存在邮件中；
> 4. **仓储上限与自动化垃圾回收 (Mailbox Capacity & Garbage Collection)**：
>    - 单信箱上限 100 封，达到上限时自动清理“已读且无未领附件”的最早旧邮件。

## 二、 信箱仓储管理器与一键提取求解器 (`MailboxManager`)

```gdscript
# 脚本路径: res://core/domain/mail/mailbox_manager.gd
class_name MailboxManager
extends RefCounted

const MAX_MAILBOX_CAPACITY: int = 100

var stored_mails: Array[MailItemAggregate] = []

# 投递新邮件进信箱
func receive_mail(new_mail: MailItemAggregate) -> bool:
    if stored_mails.size() >= MAX_MAILBOX_CAPACITY:
        _purge_old_read_mails()
    stored_mails.push_front(new_mail)
    return true

# 一键提取所有可用附件
func claim_all_attachments(wallet: Dictionary, inventory: Dictionary) -> Dictionary:
    var total_crystals = 0
    var total_gold = 0
    var claimed_mail_count = 0
    var claimed_items: Array[Dictionary] = []

    for mail in stored_mails:
        if mail.has_attachment and (mail.status == MailItemAggregate.MailStatus.UNREAD or mail.status == MailItemAggregate.MailStatus.READ_UNCLAIMED):
            # 提取货币
            total_crystals += mail.attachment_crystals
            total_gold += mail.attachment_gold
            mail.attachment_crystals = 0
            mail.attachment_gold = 0

            # 提取物品
            for item_dict in mail.attachment_items:
                claimed_items.append(item_dict)
            mail.attachment_items.clear()

            mail.has_attachment = false
            mail.status = MailItemAggregate.MailStatus.READ_CLAIMED
            claimed_mail_count += 1

    # 注入钱包
    wallet["mana_monocrystals"] = wallet.get("mana_monocrystals", 0) + total_crystals
    wallet["gold"] = wallet.get("gold", 0) + total_gold

    return {
        "claimed_mail_count": claimed_mail_count,
        "gained_crystals": total_crystals,
        "gained_gold": total_gold,
        "gained_items": claimed_items
    }

func _purge_old_read_mails() -> void:
    for i in range(stored_mails.size() - 1, -1, -1):
        var m = stored_mails[i]
        if m.status == MailItemAggregate.MailStatus.READ_CLAIMED and not m.is_pinned:
            stored_mails.remove_at(i)
            break
```

## 三、 附件投递管线与信箱生命周期 (`MailDeliveryPipeline`)

1. **一键提取**：`claim_single_mail` 将附件货币经 `apply_delta` 原子入账并即时清零邮件附件字段，杜绝重复提取；
2. **满仓安全保护**：附件物品逐件按《第三十六卷》注册表三元组实例化入包（`template_id` 必填为已登记 canonical_id，质量/体积取原型值），容积不足的剩余部分以 `remaining_items_count` 安全留存于邮件，未登记附件同样安全留存不可提取，状态回退 READ_UNCLAIMD 语义（可再次提取）；
3. **信箱容量与 GC**：`MailboxManager` 100 封硬上限，超出时按最旧已读已领邮件自动回收，新邮件永远可入；
4. **时效生命周期**：`update_expiry` 按 UTC 时间戳将过期邮件标记 EXPIRED，未到期信件保持 UNREAD。

**归档细则**：阶段 3 施工细则 `KALAR-DEV-2026-RM25-003`（见归档库档案卷）。
