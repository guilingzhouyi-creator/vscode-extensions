## 一、 算法降阶与性能重构设计

### 1. `contract_completeness_guard.gd` 之 $O(N^2) \to O(N)$ 降阶

* **缺陷背景**：在 `forward_orphans` 审计逻辑中，外层遍历所有领域 `domains_seen`，内层线性扫描所有契约条目 `all_entries` 判定 `e.domain_name == d and not e.view_name.is_empty()`。当领域数和条目数增长时产生二次方阶计算放大。
* **重构方案**：采用「单次哈希集合预索引」设计模式：
  ```gdscript
  # 预置已绑定视图的领域集合（单次线性扫描 O(E)）
  var domains_with_view: Dictionary = {}
  for e in all_entries:
      if not e.view_name.is_empty():
          domains_with_view[e.domain_name] = true

  # 线性遍历判定（O(D) 伴随 O(1) 哈希判定）
  var forward_orphans: Array[Dictionary] = []
  for d in domains_seen:
      if not domains_with_view.has(d):
          forward_orphans.append({
              "domain_name": d,
              "reason": "backend domain has no view mapping"
          })
  ```
* **性能收益**：算法时间复杂度由 $O(D \times E)$ 严格收敛至 $O(D + E)$，杜绝大规模资产扫描时的 CPU 尖刺。

### 2. `contract_parser.gd` 之事件过滤守卫函数抽取

* **重构方案**：将双重循环内部的字典键遍历 `for k in e.event_filter.keys():` 抽离为私有纯断言函数：
  ```gdscript
  static func _matches_event_filter(filter: Dictionary, payload: Dictionary) -> bool:
      for k in filter.keys():
          if payload.get(k) != filter[k]:
              return false
      return true
  ```
* **架构收益**：消除主分发循环的嵌套深度，使过滤逻辑具备独立测试性与防腐边界。

### 3. `contract_registry_entry.gd` 之消除循环内 `.duplicate(true)`

* **缺陷背景**：在 `to_dto()` 序列化方法中，循环执行 `clean_field_mapping.append(fm.duplicate(true))`，触发递归深拷贝堆分配，违反 `AGENTS.md` 绝对红线。
* **重构方案**：字段映射字典均为纯标量配置项，使用 `fm.duplicate(false)` 浅拷贝即满足不可变隔离需求，彻底消除深层递归遍历开销。

### 4. 零黑话彻底清退与账号聚合防腐

* **清退 `P39`**：[entitlement_service.gd](../../../../backend/domains/account/entitlement_service.gd) 注释由 `# P39 清单 6：...` 改写为标准架构描述 `# 密钥安全策略：仅接受受控环境密钥提供器...`。
* **清退 `Phase 08`**：[save_slot_dto.gd](../../../../backend/domains/account/save_slot_dto.gd) 注释由 `（Phase 08 隔离域：...）` 改写为 `（角色生命周期隔离域：...）`。
* **防腐增强**：[account_profile.gd](../../../../backend/domains/account/account_profile.gd) `is_slot_occupied` 增加 `if slot_id.is_empty(): return false` 前置校验，消除无意义薄包装。
