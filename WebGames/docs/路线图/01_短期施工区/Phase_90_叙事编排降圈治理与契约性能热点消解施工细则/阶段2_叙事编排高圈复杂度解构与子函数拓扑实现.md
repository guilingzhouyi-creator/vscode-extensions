## 一、 架构拓扑与解构设计

### 1. `narrative_dag_execution_engine.gd` 之 `execute_node_action` 解构拓扑

原函数 90 行，交织状态机守卫、前置汇聚、活跃迁移、上下文合并、终态判定、边权重仲裁与事件广播。重构为四大私有辅助方法：

* **`_verify_node_executable(node_id: String) -> Dictionary`**：
  * 集中处理 `is_terminated`、`active_node_ids.has`、`graph.nodes.has` 守卫；
  * 执行 `required_prerequisites` 汇聚哈希校验；
  * 返回 `{"ok": true}` 或包含标准 `error_code` 的失败字典。
* **`_commit_node_completion(node_id: String, current_node: NarrativeDAGNode, action_payload: Dictionary) -> void`**：
  * 活跃节点移出、已完成列表记录与哈希集合标记；
  * 合并动作载荷至 `runtime_context`；
  * 发出 `narrative.dag.node_completed` 领域事件。
* **`_try_handle_terminal(node_id: String, current_node: NarrativeDAGNode) -> Dictionary`**：
  * 检测当前节点是否为终态出口（`terminal_node_id` 或 `TERMINAL_EXIT`）；
  * 若是，置 `is_terminated = true`、清空活跃列表、广播 `narrative.dag.completed` 并返回标准终止响应字典；否则返回空字典。
* **`_derive_downstream_activations(node_id: String, current_node: NarrativeDAGNode) -> Array[String]`**：
  * 提取并过滤满足分支条件的出边；
  * 若为 `BRANCH_CHOICE` 且匹配边多于 1 条，执行优先级权重最大化仲裁；
  * 遍历候选边，满足前置依赖者加入活跃列表并广播 `narrative.dag.node_activated`，返回新增激活节点列表。

### 2. `causality_dag_validator.gd` 之 `validate_graph` 解构拓扑

原函数 80 行，将整套 Kahn 算法、邻接图与拓扑校验硬塞于一个静态函数中。重构为三阶段流水线：

* **`_validate_graph_topology_integrity(graph: NarrativeDAGGraphDTO) -> Dictionary`**：
  * 校验图元判空、节点字典非空；
  * 校验入口节点 `entry_node_id` 存在性；
  * 校验非空终态节点 `terminal_node_id` 存在性；
  * 返回 `{"is_valid": false, ...}` 或 `{"is_valid": true}`。
* **`_build_degrees_and_edges(graph: NarrativeDAGGraphDTO, in_degree: Dictionary, adj_list: Dictionary) -> Dictionary`**：
  * 初始化入度与邻接表；
  * 遍历边集合，若存在悬挂边（`from` 或 `to` 不在节点集）立即返回 `DANGLING_EDGE` 错误；
  * 遍历节点前置集合，若依赖不存在节点立即返回 `MISSING_PREREQUISITE` 错误。
* **`_detect_cycle_kahn(graph: NarrativeDAGGraphDTO, in_degree: Dictionary, adj_list: Dictionary) -> Dictionary`**：
  * 初始化零入度队列；
  * 循环出队并递减后继节点入度；
  * 若最终出队访问数小于总节点数，返回 `CYCLE_DETECTED` 错误。
