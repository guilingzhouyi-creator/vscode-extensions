# 短期施工区准入、审批、两轮施工周期与序号治理规范 (Short-Term Sprint Zone Norms)

> [!IMPORTANT]
> **【默认归属与先批后建铁律】**：
> 1. **默认短期归属**：依据卡拉尔工程化治理总规，**在没有项目负责人/用户明确授权 (Explicit Authorization) 的情况下，任何新增的业务施工细则、近期迭代冲刺与重构计划，一律默认归入此「01_短期施工区」**。
> 2. **先细则获批，后编码施工（硬性红线）**：**每次改动和修改必须先落成分阶段硬性要求的施工细则文件，按四阶段标准模板写清楚、理清楚，获得项目负责人/用户明确批准后才可依据路线图实施代码编写，否则严禁编写代码，严格按照项目规范手册活动**。

---

## 🎯 一、 职能定位与标准两轮施工周期 (Two-Round Sprint Cycle)

每一项任务的推进，严格由**两轮 Agent 执行构成一个完整施工周期**。Agent 不得仅依赖自身上下文记忆，**施工区与路线图的显式状态才是任务顺序的唯一权威依据**：

```
                             ┌────────────────────────────────────────────────────────┐
                             │       收到新提示词 (Prompt Triggered)                  │
                             └───────────────────────────┬────────────────────────────┘
                                                         │
                                                         ▼
                             ┌────────────────────────────────────────────────────────┐
                             │ 【第 1 轮：开工前置检查 ➔ 编写施工细节与实现】          │
                             │  1. 强制检查短期施工区：核对已有序号、状态、完成位置   │
                             │     与未完成事项，校验连续/唯一/无跳号/无重复/无越序   │
                             │  2. 实施本轮细则编写与代码实现                         │
                             │  3. ⚠️ 严禁擅自提前修改尚未获批的最终路线图状态        │
                             └───────────────────────────┬────────────────────────────┘
                                                         │
                                                         ▼
                                          [ 获得项目负责人/用户明确批准 ]
                                                         │
                                                         ▼
                             ┌────────────────────────────────────────────────────────┐
                             │ 【第 2 轮：复查施工区 ➔ 细则收敛 ➔ 验收 ➔ 路线图闭环】│
                             │  1. 再次核对施工区序号与状态自洽性                     │
                             │  2. 完成细则收敛、最终补充与修正                       │
                             │  3. 执行全域单元测试与 20 项静态门禁验收               │
                             │  4. 正式将路线图状态更新标记为完成（周期闭环）         │
                             └───────────────────────────┬────────────────────────────┘
                                                         │
                                                         ▼
                             ┌────────────────────────────────────────────────────────┐
                             │  【周期闭环完成】方可开启下一项合法序号任务            │
                             └────────────────────────────────────────────────────────┘
```

## 🔒 二、 强制序号门禁与开工前置检查

1. **每轮开工前置检查**：
   - 每次收到新的提示词后，**第一步必须先检查短期施工区**，确认当前施工区已有任务序号、执行状态、上轮完成位置及未完成事项；
   - 验证序号是否**连续、唯一、无跳号、无重复及无越序**。若发现异常，必须先识别并纠正状态关系，禁止直接进入施工。
2. **强制序号继承**：
   - 每一轮开始前及每一周期结束后，必须重新核对施工区序号；
   - 新任务只能使用**当前序列中的下一个合法序号**（如当前已有 Phase 25~34，则下一个合法序号必为 Phase 35），禁止自行复用、跳过、覆盖或创造冲突序号；
   - **路线图、施工区、实际代码状态三者必须保持绝对一致**。

## 📦 三、 10 案卷归档周期机制 (10-Volume Archive Cycle)

> [!NOTE]
> 短期施工区遵循**批次归档机制**以保持活跃看板的高内聚与整洁度：
> * **归档周期阈值**：**每积累完成 10 个大的施工细节文件夹（即 10 卷共 40 阶段细则）为一个完整归档周期**（如第 01 期收录 Phase 05~14，第 02 期收录 15~24，第 03 期收录 25~34，短期流始于 Phase 05；当前第 08 期在途 2/10，下一新卷 Phase 77）；
> * **特化校验门禁**：执行 `archive_volume.py` 时，系统将自动校验 4 阶段内容的独特性与特化闭环，存在样板化复制粘贴即阻断归档；
> * **标准档号生成**：自动迁移至 `docs/归档库/03_短期施工档案卷/第XX期_01到10/`，编制标准档号 `KALAR-DEV-2026-ST{NN}-{PPP}`（如 `KALAR-DEV-2026-ST01-001`），自动注入 14 项标准 YAML 头块并同步更新全宗元数据库与总索引。
