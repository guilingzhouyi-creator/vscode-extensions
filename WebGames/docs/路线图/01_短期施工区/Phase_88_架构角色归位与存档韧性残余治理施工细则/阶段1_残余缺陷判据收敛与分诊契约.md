  * `WebGames/docs/模板/GD老练风格硬性规范标准.md`（性能热点循环治理 `ADV-PRF-002` 的适用范围为**热路径循环**）；
  * 仓库根 `AGENTS.md` §四（禁止无实测优化的臆测改动、禁止局部最小 MVP 敷衍）。
* **核心不变量约束断言**：
  * `Inv-P88-1 (判据先于改动)`：任何一项残余缺陷进入实施前，必须给出「真实/不成立」的复核结论与证据；**经复核为「不成立」或「无热路径证据」的项，以证据结案而非机械改码**。
  * `Inv-P88-2 (角色归位可判定)`：`solver` 违规判据为「文件内存在 `-> void` 且**改写外部入参状态**（入参聚合 / 入参字典 / 注入 registry）」；无外部入参的私有缓存方法（`_ensure_*` / `_prune_*` / `init_or_rebuild_*`）不构成违规。
  * `Inv-P88-3 (归位零调用点风险)`：角色重分类优先采用「文件与 `class_name` 重命名 + 题头架构定位更正」；引用面必须实测穷尽并同步更新，改后全域断言数不得减少。
  * `Inv-P88-4 (韧性配置驱动)`：存档自愈能力（自动恢复开关、孤儿临时文件清理）必须由 `config/infrastructure/persistence.json` 声明，代码仅保留兜底默认值。
  * `Inv-P88-5 (回滚深度有界)`：自动恢复必须具备硬性深度上限（不得因 `.bak` 亦损坏而产生无界递归），且失败时回退原始错误结果，不美化失败语义。
  * `Inv-P88-6 (编号唯一)`：新增测试用例编号必须实测全域占用后顺延，禁止跨文件重号。
* **防漂移最高指示**：本卷以「判据 → 修法 → 证据」为唯一推进链路；**严禁**为追求「六项全改」而对无热路径证据的项做臆测性改动，**严禁**在未穷尽引用面的情况下重命名。
