## 三、 世界 MOD 锁摘要固化、篡改阻断与网关状态机清污实现

### 3.1 世界锁真实元数据与 SHA-256 固化

- **新建后端辅助类 `res://backend/domains/narrative_orchestration/world_mod_lock_metadata_helper.gd`**:
  - 将包列表规范化与哈希补全从过长的协调器/管理器中剥离，保持低圈复杂度与可复用性。
  - 方法 `resolve_lock_pack_entries(raw_packs: Array, custom_roots: Array = []) -> Array[Dictionary]`：
    1. 扫盘索引当前已安装激活包（`ModPackageDiscoverySolver.scan_installed_packs(custom_roots)`）。
    2. 对输入条目（无论 `String` 还是缺失摘要的 `Dictionary`/`Object`）：优先保留已携带的非空 `version` 与 `content_sha256`；若缺失则按 `pack_id` 从已安装索引读取 `version`、`content_sha256`、`priority`、`pack_profile`、`is_official`；若清单自身 `content_sha256` 仍为空且存在有效目录 `root_path`，立即调用 `ModPackageDiscoverySolver.compute_package_content_sha256(root_path)` 计算真实内容摘要。
- **[world_character_creation_orchestrator.gd](../../../../backend/domains/character_creation/world_character_creation_orchestrator.gd)** `_anchor_world_continuity`:
  - 优先从 `gateway_fsm.adapted_mod_manifest.get("applied_packs", [])`、已安装激活包与 `gateway_fsm.get_active_mods()` 聚合，并经 `WorldModLockMetadataHelper.resolve_lock_pack_entries(...)` 生成完整包元数据字典后再调用 `WorldModAffinityManager.new().save_world_mod_lock(world_id, resolved_packs)`。

### 3.2 `digest_drifts` 无条件 Fail-Closed 阻断与自动发现覆盖修复

| 目标文件 | 精确改造点 | 安全守卫逻辑 |
| :--- | :--- | :--- |
| [world_mod_affinity_manager.gd](../../../../backend/domains/narrative_orchestration/world_mod_affinity_manager.gd) | `verify_and_bind_world_mods` | 若 `not digest_drifts.is_empty()`，无视 `should_allow_safe_degrade`，强制 `success = false`，返回 `error = "MOD_ERR_REALM_DIGEST_MISMATCH"` 与 `digest_drifts` 诊断；仅当 `digest_drifts.is_empty()` 且仅有可选扩展位于 `missing_packs` 时，`should_allow_safe_degrade == true` 方可触发 `DEGRADED` + `MOD_DETACHED` |
| [save_load_routing_solver.gd](../../../../backend/domains/world_gateway/save_load_routing_solver.gd) | `_restore_world_mod_context` | 若世界存在锁定文件，`diagnose_world_mods` / `verify_and_bind_world_mods` 返回 `not digest_drifts.is_empty()` 或 `not missing_packs.is_empty()`（未授权降级）时强制阻断读档，禁止忽略 `digest_drifts` 放行 |
| [world_gateway_realm_lock_helper.gd](../../../../backend/domains/world_gateway/world_gateway_realm_lock_helper.gd) | `ensure_single_player_world_mods_ready` | 当 `has_lock == true` 时，不再因 `not gateway_fsm.adapted_mod_manifest.is_empty()` 而提前跳过校验；对比当前已挂载 `pack_id` 与 SHA-256 列表是否与 `locked_pack_ids` / 锁摘要完全一致，不匹配则按 `locked_pack_ids` 重新校验并重挂载或 Fail-Closed 拦截 |
| [mod_package_discovery_solver.gd](../../../../backend/domains/narrative_orchestration/mod_package_discovery_solver.gd) | `_parse_manifest_at_path` | 目录型包若声明了非空 `content_sha256` 则保留比对基础（或按已声明与 `compute_package_content_sha256` 校验目录完整性策略暴露显式一致性检查函数供锁与联机验签调用，确保不误伤无自报摘要的合成测试夹具） |

### 3.3 `WorldGatewayFSM` 模式切换、退出清污与联机验签回滚

1. **`switch_gateway_mode` ([world_gateway_fsm.gd](../../../../backend/domains/world_gateway/world_gateway_fsm.gd))**:
   - 若当前处于 `GatewayPhase.IN_WORLD` 或 `WorldSessionRuntimeService.has_active_world()`，仍优先阻断返错（保护 `TC-PROTO-09`）。
   - 若 `target_mode == GameMode.MULTIPLAYER`：若参数明确传入了 `custom_mods` 且其中含非官方包，立即返回 `SECURITY_ERR_MULTIPLAYER_MOD_POISONING`；否则先执行 `purge_and_fallback_to_vanilla()`，同步清空 `_selected_mod_pack_ids`、`_has_explicit_mod_selection` 与 `_realm_manifest` 并重建合规联机洁净上下文。
2. **`select_mode` (`world_gateway_fsm.gd`)**:
   - 保持对预先 `set_active_mods(poison_mods)` 的直接拦截（保护 `TC-MSS-02` 安全基线）。
3. **`exit_to_gateway()` 与 `verify_and_reconcile_realm_manifest()` (`world_gateway_fsm.gd`)**:
   - `exit_to_gateway()` 补全 `_selected_mod_pack_ids.clear()`、`_has_explicit_mod_selection = false`、`_realm_manifest.clear()`，与 `logout()` 保持对称清污。
   - `verify_and_reconcile_realm_manifest()` 在 `!allowed` 时除清空 `Tier3ContentOverrideLoader` 与 `GameConfig` 外，同步调用 `WorldGatewayModHelper.clear_fsm_mod_overlays(self)`，清除残留 `active_mods` 与 `adapted_mod_manifest`。
