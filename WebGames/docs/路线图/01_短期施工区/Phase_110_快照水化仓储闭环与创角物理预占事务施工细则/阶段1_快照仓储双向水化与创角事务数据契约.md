# 施工细则：快照水化仓储闭环与创角物理预占事务施工细则 —— 阶段1：快照仓储双向水化与创角事务数据契约

> [!NOTE]
> **【施工目标】**：定义快照测试工程模式（Dev Harness · Snapshot Mode）与账号物理仓储（`AccountRepository`）之间的双向水化交互数据契约，并规范角色创建阶段的槽位物理预占事务与配置策略驱动模型。明确从快照 DTO（`TestSnapshotBundleDTO`）到账号聚合（`AccountProfileAggregate`）的字段映射与注册语义，确立创角落盘配置 `domains.account.storage.save_on_character_creation` 与预占策略，消除快照态下账号仓储缺失导致的鉴权/槽位断层。
> **施工开始日期**：2026-10-11

* **防漂移最高指示**：严禁快照跳过仓储而仅在内存孤岛水化；严禁创角事务未经槽位预占直接分发下游。

## 一、 核心数据契约与拓扑映射模型 (Core Data Contracts & Topology Mapping)

### 1. 快照至账号聚合实体映射契约 (Snapshot to Account Aggregate Mapping)

当快照注入器（`SnapshotInjectionSolver`）执行状态水化时，将 `TestSnapshotBundleDTO` 中关于身份与槽位维度的字段无损映射为 `AccountProfileAggregate`：

| 快照 DTO 字段 (`TestSnapshotBundleDTO`) | 账号聚合实体字段 (`AccountProfileAggregate`) | 缺省回退值 (Fallback) | 语义说明 |
| :--- | :--- | :--- | :--- |
| `snapshot.account_id` | `acc.account_id` | `"ACC_DEV_INJECTED"` | 账号全局唯一物理识别码 |
| `snapshot.username` | `acc.username` | `"DevAdventurer"` | 账号登录名（大小写不敏感索引键） |
| `snapshot.slot_id` | `acc.active_slot_id` | `"SLOT_01"` | 当前选定激活的存档槽位 ID |
| `snapshot.world_id` | `acc.world_state_ref` | `"WORLD_DEFAULT_SP_01"` | 当前绑定的物理世界标识符 |
| `snapshot.world_id` + `snapshot.slot_id` | `acc.world_slots[world_id]` | `world_slots["WORLD_DEFAULT_SP_01"] = "SLOT_01"` | 世界与槽位映射绑定条目 |
| 系统当前 UTC 时间戳 | `acc.created_timestamp_utc` | `int(Time.get_unix_time_from_system())` | 账号创建物理时间戳 |
| 系统当前 UTC 时间戳 | `acc.last_login_timestamp_utc` | `int(Time.get_unix_time_from_system())` | 账号最近登录时间戳 |

水化构建出的 `AccountProfileAggregate` 实体立即经由 `AccountRepository.get_instance().save_account(acc)` 注册进主缓存表与反向用户名索引表，使下游鉴权服务（`AuthService`）与槽位求解器（`AccountSlotBindingSolver`）能以 $O(1)$ 常数时间检索命中。

### 2. 创角槽位物理预占事务信封规范 (Character Creation Slot Pre-allocation)

创角流程第一步必须在持久层物理锁定对应槽位。槽位绑定求解器执行角色创建与槽位预占事务时，遵循以下信封数据契约：

```json
{
  "success": true,
  "slot_id": "SLOT_01",
  "account_id": "ACC_NOVICE_01",
  "character_name": "NoviceRunner",
  "persisted": true,
  "error_code": ""
}
```

失败场景下必须返回确定性错误码，严禁静默吞没异常：

```json
{
  "success": false,
  "slot_id": "SLOT_01",
  "account_id": "ACC_NOVICE_01",
  "character_name": "",
  "persisted": false,
  "error_code": "ERR_SLOT_ALREADY_OCCUPIED"
}
```

### 3. 配置驱动策略契约 (Configuration Driven Strategy)

在 `config/domains/account/core.json` 的 `storage` 与 `save_slot` 节点中规范如下键值契约：

```json
{
  "storage": {
    "registry_file": "user://accounts/account_registry.json",
    "accounts_dir": "user://accounts/",
    "atomic_write": true,
    "save_on_character_creation": true,
    "backup_retention": 3,
    "format_version": "1.0.0"
  },
  "save_slot": {
    "max_slots": 3,
    "id_prefix": "SLOT_",
    "default_slot_id": "SLOT_01",
    "preallocate_on_creation": true
  }
}
```

- `storage/save_on_character_creation`: 布尔值，指示创角槽位绑定时是否立即将账号聚合物理落盘至 `user://accounts/`；
- `save_slot/preallocate_on_creation`: 布尔值，指示是否在角色进入游戏序章前完成物理槽位占位符锁定。
