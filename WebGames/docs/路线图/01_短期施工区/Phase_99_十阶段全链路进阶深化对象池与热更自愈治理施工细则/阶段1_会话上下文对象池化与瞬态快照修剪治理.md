## 一、 数据结构设计与代码契约

### 1.1 会话状态面

`SessionFlowContextDTO` 保留会话、账号、槽位、角色、世界、模式、阶段、菜单状态、领域快照、阶段结果和未接线槽位字段。`reset_state()` 清空会话数据与所有可变容器，将 `is_active` 恢复为初始值并清除借用标记。

### 1.2 池化接口

| 接口 | 语义 | 失败/边界行为 |
| :--- | :--- | :--- |
| `acquire()` | 从空闲池取出或创建 DTO，标记借用并增加借用计数 | 空池允许创建池外实例 |
| `release(context)` | 仅接受当前借出对象；先完整复位，再按配置决定是否保留 | 空对象或重复归还返回 `false`；空闲池满时复位后不入池 |
| `clear_pool()` | 清除空闲对象并返回清除数量 | 不重置仍借出的对象 |
| `max_free` | `infrastructure.lifecycle` 下 `session_context_pool/max_free` | `0` 表示不保留空闲实例；读取使用 `GameConfig.get_int` |

### 1.3 快照和修剪

- `to_dto(false)` / `from_dto(data, false)` 是浅传输，嵌套字典和数组共享引用，不是只读快照。
- `deep_copy = true` 对领域字典、数组和 `unwired_slots` 做独立复制；跨所有者或 DTO 复用周期保存时使用深复制。
- `prune_intermediate_snapshots()` 仅在 `current_stage_index >= 6` 时清理 `opening_event_snapshot` 与 `physiology_snapshot`；账号、槽位、钱包、HUD、停机、阶段结果和未接线数据不在该方法中清除。
- 不将 `EventPool` 用作会话 DTO 池；两者类型、所有权和容量策略不同。
