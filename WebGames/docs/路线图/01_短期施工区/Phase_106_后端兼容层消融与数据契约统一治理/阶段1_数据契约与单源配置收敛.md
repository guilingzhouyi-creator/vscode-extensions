  - `Inv-BC1-1 (全域 UID 格式合规性)`：全域生成的物品 UID 必须严格符合 `ItemUIDGenerator` 的前缀白名单与 2 位十六进制 SHA-256 校验尾规范，通过 `validate_uid()` 100% 校验；

  - `Inv-BC1-4 (模式配置单一语义)`：管理员运行/同步模式配置收敛为明确的 `sync/mode`，杜绝双轨字段语义冲突。

## 一、 数据结构设计与代码契约 (Data Structures & Code Contracts)

### 1. 物品 UID 权威签发契约对齐
在 `wearable_inventory.gd` 中，严禁使用裸 `UniqueIdGenerator.next_id("INV_")`。当入包物品 `item_uid` 为空时，统一调用领域标准生成器并使用系统权威白名单前缀 `SRV_`：

```gdscript
# 模块路径: res://backend/domains/inventory/wearable_inventory.gd
const ItemUIDGenerator = preload("res://backend/domains/item_namespace_registry/item_uid_generator.gd")

func add_item(item: ItemEntity, race_bonus: float = 0.0) -> bool:
	if not can_add_item(item, race_bonus):
		return false
	if item.item_uid.is_empty():
		item.item_uid = ItemUIDGenerator.generate_uid("SRV_")
	# ... 后续入包逻辑 ...
```

### 2. 契约索引单源物理路径收敛
消融 `contract_registry_index.gd` 中的 `CONTRACT_CONFIG_PATH_FALLBACK` 后备探测分支，固化单一权威路径：

```gdscript
# 模块路径: res://backend/domains/contract_registry/contract_registry_index.gd
const CONTRACT_CONFIG_PATH_PRIMARY: String = "res://config/infrastructure/contracts.json"
```

### 3. 持久化与存储配置参数去重
在 `storage.json` 中保留实质的 `primary.minimal_state.max_restore_budget_ms`，移除重复的路径与未生效加盐镜像：

```json
{
  "deterministic": { "force_sync_in_tests": true },
  "primary": {
    "minimal_state": { "max_restore_budget_ms": 10.0 }
  }
}
```
