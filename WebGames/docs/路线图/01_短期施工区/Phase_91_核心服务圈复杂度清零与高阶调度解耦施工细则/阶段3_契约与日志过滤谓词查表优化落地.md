## 一、 架构拓扑与解构设计

### 1. `contract_registry_index.gd` 之 `_load_from_config` 解构拓扑

原函数 65 行，将文件读取、JSON 解析与注册表解包深度混合。重构为三大纯辅助函数：

* **`_read_config_file_text() -> String`**：负责主备配置路径探测与原始文件文本读取；
* **`_parse_json_dict(json_text: String) -> Dictionary`**：负责安全的 JSON 解析与顶层字典校验；
* **`_unpack_registry_sections(dict: Dictionary) -> void`**：负责校验各分段有效性并填充索引条目。
* 主函数 `_load_from_config` 圈复杂度从 16 降至 3。

### 2. `log_query_service.gd` 之 `_matches_criteria` 解构拓扑

原函数 55 行，将六个维度的过滤条件挤入同一个分支判断中。重构为三个正交的独立谓词：

* **`_matches_time_window(dto, criteria) -> bool`**：判定起始时间戳与结束时间戳区间；
* **`_matches_level_and_channel(dto, criteria) -> bool`**：判定最低日志级别与特定通道名；
* **`_matches_identifiers_and_keyword(dto, criteria) -> bool`**：判定 trace_id、error_code 与关键词子串匹配。
* 主函数 `_matches_criteria` 圈复杂度从 17 降至 3。

### 3. `visual_adapter.gd` 之 `adapt_label` 解构拓扑

原函数 50 行，交织控件类型判断、可用宽度探测、阶梯字号匹配与溢出裁剪应用。重构为四大纯辅助函数：

* **`_get_label_current_font_size(label: Node) -> int`**：自适应提取 Label/RichTextLabel 初始字号；
* **`_resolve_label_available_width(label: Node, container_width: float) -> float`**：安全探测容器可用宽度；
* **`_resolve_fitted_font_size(...) -> int`**：逐级递减字号直至文本不发生溢出；
* **`_apply_label_visual_style(...) -> void`**：应用字号覆盖与溢出省略号。
* 主函数 `adapt_label` 圈复杂度从 15 降至 4。

### 4. `test_architecture_guard.gd` 之 `_strip_by_mode` 与黑话清退

* 提取 `_skip_string_escape` 与 `_blank_char_if_needed`，消除了单字节状态机内部深层嵌套分支，圈复杂度从 17 降至 9。
* `clawback_service.gd` 清除残留的 `# P4：` 与 `P39 清单 5` 批次代号，完全对齐 `AGENTS.md` 零黑话契约。
