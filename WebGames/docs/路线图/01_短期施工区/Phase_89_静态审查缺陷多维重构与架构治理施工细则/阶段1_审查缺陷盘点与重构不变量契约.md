  * `WebGames/README.md` §领域与基础设施边界：业务领域层（`backend/domains/`）严禁向外反向依赖基础设施层（`backend/infrastructure/`）与展示层（`frontend/`）；
  * `WebGames/docs/模板/GD老练风格硬性规范标准.md` §四：圈复杂度门禁硬顶（告警阈值 15，失败阈值 25，目标收敛至 $\le 10$）；
  * `WebGames/docs/模板/GD老练风格硬性规范标准.md` §五：性能热点循环治理（`ADV-PRF-002` 循环内零瞬态堆分配，嵌套循环降阶）；
  * 仓库根 `AGENTS.md` §二 关键架构约定与工程契约（严禁循环内 `.new()` / `.duplicate(true)`；全域严禁施工批次黑话）；
  * 仓库根 `AGENTS.md` §四 交付违规绝对禁止清单（禁止局部最小 MVP 敷衍实现；改动必先立分阶段施工细则）。
* **核心不变量约束断言**：
  * `Inv-P89-1 (行为完全等价)`：所有优化重构必须保证各模块外部 API 签名、参数字典、返回结构与副作用完全向后兼容；全域既有 770 项测试断言 100% 保持全绿。
  * `Inv-P89-2 (领域层依赖单向性)`：`backend/domains/` 领域模型与离散求解器严禁反向依赖外部 `backend/infrastructure/`；`account_slot_binding_solver.gd` 中的 `GameLoopStateStack` 违规依赖彻底清退。
  * `Inv-P89-3 (圈复杂度有界收敛)`：重构的目标函数（`_validate_invariants`、`_validate`、`dispatch_ui_command`、`apply_transaction`）圈复杂度一律拆解至 $\le 10$。
  * `Inv-P89-4 (循环性能降阶与零瞬态分配)`：循环内严禁瞬态 `.new()`；多层属性匹配循环通过字典/集合预索引优化至 $O(N)$。
  * `Inv-P89-5 (零黑话与字面量常量化)`：彻底清理目标业务脚本中的 `Phase 02` 等历史施工批次黑话；高频配置路径（如 `domains.account`）提取为命名常量。
  * `Inv-P89-6 (用例编号全域唯一)`：新增测试用例编号必须全局搜索验重后顺延，严禁跨文件重号。
* **防漂移最高指示**：本卷以「架构解耦 → 复杂度降阶 → 性能热点消除 → 代码卫生清退」为唯一改造范围；**严禁**借重构名义随意重构未被审查标记的健康模块，**严禁**修改已封存历史需求表与归档库。
