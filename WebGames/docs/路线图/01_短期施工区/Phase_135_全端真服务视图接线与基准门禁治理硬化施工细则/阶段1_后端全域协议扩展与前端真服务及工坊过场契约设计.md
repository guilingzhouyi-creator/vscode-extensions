## 一、 核心架构与契约设计

1. **后端全协议域扩展与真会话快照契约 (`protocol_and_snapshot_contract`)**:
   - `UnifiedProtocolDispatcher` 保持向后兼容 7 个核心域直连，并通过模块化领域协议处理器支持 `combat`、`economy`、`gacha`、`quest`、`mail`、`guild`、`world_navigation`、`crafting`、`grimoire`、`misc_edge`、`system_save`、`gm_command` 等域分发。
   - `RealSnapshotDataService` 从 `WorldSessionRuntimeService.build_live_hud_context()` 的扁平键（`character_id`、`character_name`、`wallet_gold`、`wallet_mana_monocrystals`、`attribute_values` 等）与各后端服务构造权威嵌套快照，并将 `domains.world#mod_world_topology`（`nodes`/`edges`）及 `MapAndEcologySolver` 输出映射到 `world_map` 快照。
   - `RealWorldService` 覆写 `plan_routes` 与 `upgrade_territory` 调用 `MapAndEcologySolver` 与后端领地状态，并在 `set_mod_selection_async`/`precheck_mod_stack_async` 透传 `custom_roots`。
2. **真领域服务与字段契约对齐 (`real_services_schema_alignment`)**:
   - 对齐 `RealQuestService`（`"ACTIVE"` 与 DAG 状态同步）、`RealGachaService`（`get_rules()` 与 `GachaWishView` 键对齐 + 扣费与保底计数同步）、`RealGrimoireService`（3 种版税模式对齐与编纂/领取持久化）、`RealMailService`（`"attachment_keys"` 对齐与收发/草稿/领取联动）、`RealEconomyService`/`RealCraftingService`/`RealGuildService`/`RealMiscEdgeService`/`RealSaveService`/`RealCombatService`/`RealChatCommandService`（真实买卖、强化锻造分解、公会治理与交易托管、异变拾取改名、档案读写与回放、技能释放与 HUD 同步、GM 指令解析执行）。
3. **MOD 工坊全流程与过场播放器接入契约 (`mod_workbench_and_cutscene_contract`)**:
   - 为 `ModWorkbenchScreen` 与 `IWorldService`/`RealWorldService`/`WorldGatewayProtocolHandler` 增加游戏内 **创建 MOD (`create_mod_pack`)**、**打包 `.kmod` (`pack_mod_kmod`)**、**安装文件夹或 `.kmod` 至 `user://mods` (`install_mod_pack`)**，同时在 Python CLI (`kalar_mod.py install`) 补齐 `install` 子命令。
   - `ModPrecheckAndAdaptationSolver` 在接收非空 `selected_pack_ids` 时尊重用户手动排列顺序，仅对依赖约束进行合法性校验而不静默重写顺序。
   - 补齐 `frontend/views/cutscene_player/cutscene_player_view.tscn`，在 `NavManager._init_default_registry()` 注册 `"cutscene_player"`，并在 `AppBootstrap` 与 `PrologueView` 完成 `CutsceneEventBridge` 挂载与播放联动。
