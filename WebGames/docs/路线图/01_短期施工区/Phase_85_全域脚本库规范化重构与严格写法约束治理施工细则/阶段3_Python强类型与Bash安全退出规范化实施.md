## 一、 Python 强类型体系与 Bash 安全防御规范 (Python & Bash Engineering)

### 1.1 Python 35 脚本强类型注解 (Strict Type Hints 100%)

全量 35 份 Python 脚本执行严格类型标注改造，达成 100% 函数级类型覆盖：

1. **函数签名强类型化**：
   - 所有函数声明必须标注全部输入参数类型与明确返回值类型（如 `def check_item(path: Path, verbose: bool = False) -> list[dict[str, str]]:`）；
   - 无返回值的操作必须显式标注 `-> None`，杜绝任何未类型化函数遗漏；
   - 重点补齐 `audit_docs.py`、`audit_config.py`、`audit_runner.py`、`archive_volume.py` 等引擎中的 12 个历史裸函数；
2. **异常捕获精准化防御**：
   - 严禁裸 `except:`；
   - 严禁无差别 `except Exception: pass`（除非在可预期的非致命探测中且附带类型注释）；
   - I/O 与 JSON 解析必须显式捕获 `(OSError, IOError, json.JSONDecodeError, UnicodeDecodeError)`；
3. **Windows UTF-8 控制台兼容与 Docstring**：
   - 独立入口脚本统一调用 `ensure_utf8_stdout()`，彻底根除 Windows GBK 终端乱码与换行异常；
   - 模块顶部统一配备 PEP 257 标准 Docstring，阐明工具职责与设计依据。

### 1.2 Bash 23 脚本安全防御与退出语义 (Bash Safe Practices)

覆盖 `WebGames/scripts/sh/` 14 份与根目录 `scripts/sh/` 9 份脚本：

1. **Shebang 标准化**：
   - 统一声明 `#!/usr/bin/env bash`；
2. **安全选项统一契约**：
   - 统一声明 `set -uo pipefail`（硬性禁用盲目 `set -e`，防止命令管道中的良性探测被意外中断，统一依托后续的显式退出码与状态校验）；
3. **变量安全双引号展开**：
   - 严格审查全量变量引用，统一采用 `"$VAR"` 双引号包裹，杜绝路径含空格或空变量时的意外解构；
4. **退出码三态语义收敛**：
   - `0`：成功 / 全部门禁通过；
   - `1`：检查不通过 / 业务执行失败（阻断 CI）；
   - `2`：命令行参数错误 / 用法不当 / 环境缺失。
