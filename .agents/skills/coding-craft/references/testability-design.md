# 可测性设计

> 可测性不是测试阶段的问题，是设计阶段的产物。测试写不出来，通常是设计有问题，而不是测试不够努力。

---

## 一、 五个前置条件

| 条件 | 判据 | 违规信号 |
| :--- | :--- | :--- |
| **时间可注入** | 无直接 `Date.now()` / `time.time()` | 测试需要 mock 全局 |
| **随机可注入** | 无直接 `Math.random()` / `random.random()` | 断言依赖运气 |
| **I/O 在边界** | 纯计算函数不读文件、不发请求 | 单测需要真实文件 |
| **无模块级单例** | 模块加载不产生连接、定时器、监听器 | 测试间互相污染 |
| **失败可构造** | 每个错误分支能稳定触发 | 需要 mock 整个框架 |

---

## 二、 时间与随机的注入形态

```ts
// 反模式：时间藏在实现里
export function isExpired(rule: Rule): boolean {
  return rule.expiresAt <= Date.now();
}

// 正模式：时间作为契约输入
export interface Clock { now(): number }

export function isExpired(rule: Rule, clock: Clock): boolean {
  return rule.expiresAt <= clock.now();
}

// 测试：钉死时钟
const frozen: Clock = { now: () => 1_700_000_000_000 };
expect(isExpired({ expiresAt: 1_699_999_999_999 } as Rule, frozen)).toBe(true);
```

随机同理：把 `random: () => number` 作为参数或构造注入，测试传入常量序列。

## 三、 I/O 边界

```text
        ┌────────────────────────────┐
        │  纯计算（无 I/O，可秒测）    │
        └─────────────▲──────────────┘
                      │ 输入数据
        ┌─────────────┴──────────────┐
        │  薄适配层（读文件/发请求）   │
        └────────────────────────────┘
```

- 适配层只做「取数据 → 交给纯函数 → 写结果」，自身不含业务判断；
- 纯函数层覆盖率应接近 100%，适配层靠集成测试覆盖；
- 判据：**能否在不创建任何临时文件的前提下测试核心逻辑**。

## 四、 单例消解

| 反模式 | 问题 | 改写 |
| :--- | :--- | :--- |
| `export const db = createConnection()` | 模块加载即连接 | `export function createDb(cfg)` + 组合根注入 |
| `let cache = new Map()` 模块级 | 测试间共享状态 | 传入 `cache` 参数或封装为类实例 |
| `setInterval(...)` 在模块顶层 | 进程不退出，测试挂起 | 显式 `start()/stop()` 生命周期 |
| 全局可变配置对象 | 测试顺序影响结果 | 每次调用传入不可变配置 |

## 五、 失败可构造

每个错误分支必须能在测试中被**稳定**触发，且触发方式不需要真实故障：

| 失败类型 | 可构造方式 |
| :--- | :--- |
| 文件不存在 | 传入临时目录中的不存在路径 |
| 解析失败 | 传入已知非法输入字符串 |
| 超时 | 注入假时钟 + 手动推进 |
| 网络错误 | 注入返回拒绝的 fetch 替身 |
| 权限拒绝 | 注入抛错的适配器实现 |

无法构造的失败分支，等于未验证的代码。

## 六、 断言质量标准

| 反模式 | 问题 | 规则 |
| :--- | :--- | :--- |
| `expect(result).toBeTruthy()` | 无法定位偏差 | `TST-TAU-001` |
| `expect(fn).not.toThrow()` | 未验证任何输出 | `TST-TAU-001` |
| 断言与实现同义反复 | 实现错则断言也错 | `TST-TAU-001` |
| 跳过用例 `it.skip` | 覆盖缺口被隐藏 | `TST-SKP-001` |
| 无归属的孤儿用例 | 无人维护 | `TST-ORC-001` |
| 依赖真实时间/随机 | 偶发失败 | `TST-DEN-001` |

---

## 七、 自检清单

- [ ] 核心逻辑能否在不碰磁盘、不发请求的前提下测试？
- [ ] 时间与随机是否全部经注入？
- [ ] 是否存在模块级可变单例？
- [ ] 每个错误分支是否有对应测试？
- [ ] 断言是否描述了具体期望值而非「为真」？
