# 面向终端用户的产品变更日志编写指南 (User-Facing Changelog Guide)

本指南规范了终端交付项目（如 VS Code 扩展 `workspace-timing`）在对外发布版本时，如何编写符合工业级交付标准、以终端用户价值为中心的版本变更日志（`CHANGELOG.md`）。

---

## 一、 核心原则：用户视角与工程黑话物理隔离

变更日志的首要受众是**安装、使用扩展的真实开发者与终端用户**，而非项目的内部维护者或自动化门禁脚本。

### 1. 绝对禁止混入的内部工程概念
以下内容属于代码库内部实现细节或演进痕迹，严禁泄露至用户端 `CHANGELOG.md`：
- **架构重构与分层解耦**：如“重构五层解耦”、“消融空包跳板”、“抽离 Domain 层”、“门面聚合治理”等；
- **代码复杂度与体积控制**：如“CC <= 15”、“ELOC 预算压减”、“1:3 动态包络”、“收敛至 900 行内”等；
- **门禁脚本与自动化守卫**：如“接入 commit-msg-gate”、“pre-commit 内存流式预审”、“audit-all 5 大支柱绿色通行”等；
- **开发过程痕迹与工期黑话**：如“批次 1~6 提交”、“W1-W9 冲刺”、“阶段二自测补全”等。

### 2. 必须突出的终端用户价值
每一项变更记录必须回答一个核心问题：“**这项变动给用户的实际使用带来了什么改善？**”
- **功能特性 (Added)**：用户可以使用什么新功能、新增了什么可视化图表、支持了什么新配置项；
- **体验优化 (Changed)**：界面响应速度提升、数据加载更流畅、国际化翻译更准确自然；
- **缺陷修复 (Fixed)**：修复了导致时间记录异常、视图偶发白屏、导出数据缺失的特定场景 Bug；
- **安全与稳定性 (Security)**：防止多窗口竞争崩溃、强化本地数据落盘防丢机制。

## 二、 Keep-a-Changelog 标准语义化分类

每个版本遵循 [Keep a Changelog](https://keepachangelog.com/) 国际规范，使用以下标准二级分类（按需呈现，无对应变更的分组省略）：

| 分类标识 | 含义与适用场景 | 面向用户的描述范例 |
| :--- | :--- | :--- |
| `### Added` | 面向用户的新增功能、新视图、新配置选项 | 新增按周/按月的编码时长热力图与柱状分布视图 |
| `### Changed` | 现有功能的行为变更、视觉优化或交互改进 | 优化状态栏计时指示器的更新机制，降低后台刷新能耗 |
| `### Deprecated` | 将在未来版本中移除的既有功能或配置预警 | 标记即将废弃的旧版 CSV 导出字段格式 |
| `### Removed` | 本次版本中正式移除的废弃功能 | 移除对已废弃的旧版本地临时缓存目录的向下兼容扫描 |
| `### Fixed` | 针对用户可见或影响数据完整性的缺陷修复 | 修复跨午夜编程时当天有效时长计算发生偏移的异常 |
| `### Security` | 漏洞修复、权限收敛或崩溃安全机制加固 | 增强本地日志双写容灾机制，防止 VS Code 异常终止导致数据丢失 |

## 三、 文案写作模板与前后对照

### 1. 典型条目对比
- ❌ **内部黑话反模式**：
  - `重构 TimeAggregator.ts 消除循环内瞬态堆分配，ELOC 降至 450 行`
  - `完成 Phase_03 四阶段方案落地，全仓 audit-all 评分提升至 99.8`
  - `修复 L3-HARDCODE 门禁报错，将中文提取至 zh-CN.ts 字典`
- ✅ **用户价值最佳实践**：
  - `显著优化长周期统计数据的加载计算性能，大型工作区秒级渲染`
  - `完善状态栏与仪表板界面的多语言本地化翻译，文案更加自然贴切`
  - `修复跨天会话未自动分割导致前一日统计图表时间偏小的偶发缺陷`

### 2. 日期与版本号格式规范
每个版本必须包含语义化版本号（SemVer）与发布日期（ISO 8601 格式 `YYYY-MM-DD`）：
```markdown
## [1.2.0] - 2026-10-10
### Added
- 新增项目级时间投入环比分析面板，清晰掌握近两周开发精力分配。
```
