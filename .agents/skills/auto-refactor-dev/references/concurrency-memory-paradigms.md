# 高并发调度、图算法降阶与 9 项内存治理工程范式

> 本指南总结了 `auto-refactor` 大型静态分析与常驻守护进程中的 9 项核心内存与算法治理范式。

---

## 一、 核心痛点与工程治理背景

静态分析器通常需要处理成千上万个源码文件、构建百万节点级的抽象语法树与依赖图。如果在循环体内产生临时对象、未解绑 Worker 监听器或递归遍历超深依赖图，极易引发 V8 堆内存溢出（OOM）或垃圾回收微卡顿。为此，系统确立了 9 项刚性范式：

---

## 二、 9 项刚性治理范式矩阵

| 序号 | 治理范式名称 | 关键规则 / 契约 | 治理手段与标准代码模式 |
| :--- | :--- | :--- | :--- |
| **1** | **Myers Trace 动态缩容** | 算法降级保护 | 按编辑距离 $D$ 动态分配 $(D + 1) \times (2D + 1)$ 矩阵；超限（$>1500$ 行或 $>2\text{M}$ 单元格）回退继承修剪前后缀。 |
| **2** | **Worker 线程池监听器解绑** | 生命周期闭包隔离 | 任务终结时通过 `w.off('message', ...)` 与 `w.off('error', ...)` 显式解绑，防止扫描结果 AST 驻留内存。 |
| **3** | **队列单指针游标推进** | 消除 $O(V^2)$ 移位 | BFS 遍历严禁使用 `queue.shift()`；统一采用单指针推进：`let head = 0; while (head < queue.length) { const cur = queue[head++]; ... }`。 |
| **4** | **显式栈三色迭代 DFS** | 免疫递归调用栈溢出 | 废除原生 JS 递归函数，基于显式 `stack` 进行 White/Gray/Black 三色迭代，保护深度环路检测调用栈。 |
| **5** | **路径倒排索引 (`nodesByFile`)** | 消除全图线性扫描 | 维护规范化文件路径索引的倒排映射，避免全图遍历过滤带来的百万级临时数组分配。 |
| **6** | **分析器行切片全局缓存** | 消除重复字符串切分 | 文件入口处单次执行 `cachedLines = content.split('\n')`，后续局部提取直接 `cachedLines.slice(start, end)`。 |
| **7** | **正则顶层不可变常量化** | `PRF-MEM-001` | 严禁在循环内动态编译 RegExp；统一提升为顶层 `const RE_XXX = /^.../`；全局正则跨次调用前重置 `lastIndex = 0`。 |
| **8** | **同步 I/O 隔离屏障与次序** | `PRF-IO-001` | 必要同步 I/O 统一经 `SyncIoBarrier` 等封装；类定义中所有同步方法物理排在 async 异步方法之前。 |
| **9** | **循环内集合预索引** | `PRF-ALG-002` | 循环外预构建 `new Set(...)` 并通过 `Set.has()` 索引；多关键词匹配统一使用预编译复合正则或 ASCII 字符码扫描。 |
