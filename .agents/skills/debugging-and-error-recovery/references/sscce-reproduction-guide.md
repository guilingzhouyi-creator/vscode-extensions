# SSCCE 最小完整可复现指南 (Short, Self-Contained, Correct Example)

## 一、 为什么必须坚持 SSCCE
在庞大的业务工程中，多重组件交互、全局状态与异步竞态会形成极大的排错噪音。直接在业务源码中盲目打补丁容易掩盖真正的病根。SSCCE 要求在修改业务源码前，先用极小的确定性脚本把 Bug 孤立出来。

## 二、 SSCCE 四要素
1. **短小 (Short)**：代码规模通常 $\le 30$ 行，剔除所有与触发缺陷无关的业务包装；
2. **自给自足 (Self-Contained)**：零外部环境依赖，利用内存桩替代真实 I/O，任何人可在任意机器秒级运行；
3. **精准暴露 (Correct Example)**：运行即确定性抛出与生产一致的异常堆栈；
4. **资产沉淀**：缺陷修复后，该复现脚本直接升级为自动化回归测试用例。
