# debugging-and-error-recovery — 故障排查与自愈恢复规范

本技能规范了排查定位缺陷、分析复杂故障并安全实施自愈修复的标准通用工作流。排查故障必须遵循科学方法，严禁无根据地盲目猜测或在生产代码中大范围乱撞修改。

---

## 一、 科学排错五步法

```text
1. 观察现象 (Observe) ──▶ 2. 提出假说 (Hypothesize) ──▶ 3. 探针隔离 (Isolate)
                                                                 │
                                                                 ▼
5. 质性证明 (Prove)   ◀── 4. 实施最小修复 (Fix) ◀────────────────┘
```

1. **观察现象**：收集精确错误堆栈、控制台报错信息、复现步骤与最小环境；
2. **提出假说**：基于架构原理推导故障的物理根因，明确写出可能原因；
3. **探针隔离**：通过最简复现用例或无侵入式断点日志确认根因，排除干扰因素；
4. **实施最小修复**：针对确诊根因实施改动行最少、侵入性最低的精准修复；
5. **质性证明**：运行原先失败的用例，证明缺陷已被修复且无伴随回归。

---

## 二、 刚性约束：两次失败即停反思法则 (Rule of Two)

当尝试修复同一个缺陷**连续 2 次未见成效**（测试依然失败或产生新报错）时：
- **必须立刻强制停下手头的一切改动**；
- 运行 `git diff` 或恢复暂存区，清除无效试错代码，防止污染代码基线；
- 重新审视初始假说：此缺陷是否并非表层代码引起？是否存在前置隐式依赖或环境配置问题？
- 整理排查进展，以根因分析单形式向人类汇报并征求思路。
