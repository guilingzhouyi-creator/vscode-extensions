# code-simplification — 通用代码精简与跳板消融规范

本技能指导在代码编写完成后进行系统性的精简与重构。精简的目标不是单纯压缩代码行数，而是在**严格保持外部可观测行为 100% 等价**的前提下，降低理解认知负荷、消除无意义的间接层、收敛圈复杂度并提升可维护性。

---

## 一、 精简五项铁律

1. **绝对保全行为等价**：精简仅改变代码表达方式，绝不可变更业务输入输出、副作用发生顺序及异常抛出条件；
2. **跳板文件坚决消融**：有效代码行小于等于 3 行且仅起单纯转发透传作用的文件必须内联消融；
3. **门面实质承载**：导出门面必须聚合 3 个以上子系统，或具备冻结防御及实质调度逻辑；
4. **控制流平铺直叙**：深层嵌套（Depth > 3）必须拆解为卫语句提前返回；
5. **保护架构契约注释**：模块顶部的架构角色与职责注释不可因代码精简而被删除。

---

## 二、 典型精简场景

### 1. 单行透传跳板的内联消除
当存在类似 `export * from './internal/impl';` 的空壳文件，且其仅对单一内部模块做简单重新导出时，直接将调用方引用重定向至目标模块，彻底移除中间跳板文件。
详见：[trampoline-and-indirection-inlining.md](references/trampoline-and-indirection-inlining.md)。

### 2. 循环内瞬态堆分配优化
高频触发逻辑中，将循环体内部反复创建的临时对象、临时闭包或数组提升至循环外复用，大幅减轻垃圾回收负担。

### 3. 过度防御与死逻辑清理
清除从未被触发的内部幽灵分支、无意义的假处理注释以及多余的重复类型断言。
