# context-engineering — 通用上下文工程与渐进式信息流治理规范

本技能确立了在 AI Agent 辅助软件研发过程中管理上下文（Context）的标准工程规范。**上下文是决定智能体生成质量的唯一关键杠杆**——信息不足会导致凭空幻觉与不合规，而信息过载则会导致注意力被稀释、核心约束被遗忘。上下文工程的核心就是：在正确的时间、以最小的体积、向 Agent 喂入最精准的结构化事实。

---

## 一、 上下文五层分级架构 (The Context Hierarchy)

上下文按照**生命周期持久度从高到低**严格划分为五层：

```text
┌─────────────────────────────────────────┐
│  第 1 层：项目顶层公理与规范 (Rules)    │ ← 全局持久，会话启动即加载
├─────────────────────────────────────────┤
│  第 2 层：架构设计与规格说明 (Specs)    │ ← 按特性加载，JIT 渐进式读取
├─────────────────────────────────────────┤
│  第 3 层：目标源码与类型契约 (Sources)  │ ← 按具体原子任务精准定向加载
├─────────────────────────────────────────┤
│  第 4 层：执行结果与错误栈 (Diagnostics)│ ← 按调试循环局部喂入，剥离噪音
├─────────────────────────────────────────┤
│  第 5 层：交互历史与工作进展 (History)   │ ← 动态累积，达到预算阈值必须压缩
└─────────────────────────────────────────┘
```

1. **第 1 层：公理与规范 (Rules)**：全局治理总规、代码风格与门禁刚性红线，必须简洁高内聚；
2. **第 2 层：规格说明 (Specs)**：当前模块的技术规格书与边界契约，仅加载与当前任务相关的章节，严禁一次性灌入上万字全量设计；
3. **第 3 层：目标源码 (Sources)**：需要修改的目标文件及其强关联测试/接口定义，修改前必须精读现有代码范式；
4. **第 4 层：错误栈与诊断 (Diagnostics)**：测试或构建报错时，仅提取关键异常原因与前 5 行堆栈，严禁全量粘贴数百行控制台流水账；
5. **第 5 层：交互历史 (History)**：多轮推理的问答记录，必须及时提取结论并清理过程废话。

## 二、 渐进式披露与定向加载 (Progressive Disclosure)

杜绝“开局倾倒全部文件”的粗暴模式，遵循按需展开原则：
1. **指针化索引 (Pointer Architecture)**：在顶层规范中仅维护模块职责与路径指针，Agent 根据任务意图检索指针后，再定向读取细节文档；
2. **切片式喂入 (Selective Slicing)**：重构或排查时，优先使用局部 AST 切片或目标函数段落，避免将整个数千行巨型文件全量载入上下文；
3. **分层摘要 (Hierarchical Summary)**：大型系统维护高内聚的模块拓扑索引，任务分派时仅下发涉及模块的接口边界。

## 三、 上下文预算与注意力防衰减治理 (Context Budget Management)

大模型上下文窗口类似于工作台面，杂物堆积会导致推理能力断崖式下降。

1. **75% 预警阈值治理**：上下文占用达到窗口容量的 75% 时，必须主动开展信息脱水与压缩，严禁等到 100% 溢出时被动截断；
2. **优先淘汰列表**：
   - 已证实无效的历史试错方案与错误日志（仅保留“根因排查结论”，删除试错过程）；
   - 冗长的工具执行输出（如长列表、大量无差异查找结果）；
   - 已被新实现完全替换的废弃代码草稿；
3. **永久保护列表**：
   - 原始任务目标与刚性验收条件；
   - 当前正在定位的关键测试断言与核心错误信息；
   - 模块必须遵守的刚性架构红线；
4. **规避“中间迷失效应” (Lost-in-the-Middle Mitigation)**：
   - 模型对位于上下文最前（Primacy）和最后（Recency）的信息注意力最集中；
   - 刚性总规置于开头，当前执行的微任务目标与核心依据置于最尾端，中间仅放置静态参考。

---

## 四、 可重入会话边界持久化 (Restartable Session Boundaries)

当任务涉及跨会话执行或需要清空重置上下文时，必须在交接边界持久化以下状态至结构化文档：
1. 已完成的任务状态与已落盘代码的变更状态；
2. 已经验证通过的关键断言与自检命令；
3. 下一个待执行的原子任务与输入契约；
4. 尚未解决的未决风险与需人类确认的决策项。
