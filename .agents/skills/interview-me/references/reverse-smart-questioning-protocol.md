# 逆向提问工程协议 (Reverse Smart Questioning Protocol)

> 本协议源自 Eric S. Raymond (ESR) 的经典著作《提问的智慧》（How To Ask Questions The Smart Way）。
> 在 AI Agent 自治体系中，将其**逆向内化**为主 Agent 的“需求澄清与上下文补全引擎”，指导主 Agent 在面对人类的自然语言输入时，敏锐识别信息盲区，优雅地反向质询以收敛需求。

---

## 一、 核心理念的逆向转化

| 《提问的智慧》原始法则 (人类向黑客提问) | 逆向内化法则 (主 Agent 面对人类指令) |
| :--- | :--- |
| **不要问 X-Y 问题**：描述目标，而非手段过程 | **X-Y 问题侦测**：当用户指定某种低效或畸形手段（Y）时，主动探寻其背后的核心系统目标（X），并给出更优架构选项。 |
| **描述问题症状，而非主观猜测** | **事实剥离与四元组补全**：引导用户剥离情绪与猜测，补全【环境、触发输入、预期行为、真实报错堆栈】四元组。 |
| **做足功课，提供最小可复现示例 (MRE)** | **最小用例诱导**：当遇到复杂边界问题时，主动提供最简代码夹具，邀请用户确认这是否即为其复现场景。 |
| **精确描述，言之有物** | **单点渐进质询**：每次只质询一个最核心的决策卡点，并提供带 `(Recommended)` 的具象候选项，降低人类表达成本。 |

---

## 二、 三大逆向侦测与引导过滤器

### 1. X-Y 问题侦测器 (The XY Problem Detector)
- **典型特征**：用户提出一个非常偏门、脆弱或违背良好架构的局部实现手段。
- **逆向响应策略**：
  1. 礼貌指出该手段可能引发的架构反模式（如破坏分层解耦、破坏并发安全）；
  2. 询问其想要解决的原始痛点（X）；
  3. 提供 2~3 个符合良好工程规范的成熟替代架构方案，并标注 `(Recommended)`。

### 2. 缺陷诊断四元组补全器 (Diagnostic Tetrad)
当用户反馈“出错了”、“没有效果”或“怎么跑不通”等极度简短的报障时，严禁盲目猜代码。必须对照四元组自查表，精准反问缺失的维度：
1. **运行环境 (Environment)**：操作系统、语言与运行时版本、依赖环境；
2. **触发输入 (Input/Trigger)**：执行了哪条命令、调用了什么方法或传递了什么参数；
3. **预期表现 (Expected)**：根据设计或常理应该发生什么；
4. **客观症状 (Actual Symptoms)**：控制台报错、日志堆栈或无声挂起（杜绝纯主观猜测）。

### 3. 边界与不变式澄清器 (Boundary Invariants Probing)
对于功能特性的模糊描述，在委派 SubAgent 或编写 Spec 前，重点澄清以下隐式假设：
- **容量与规模上限**：数据规模、处理条数、延迟预算；
- **并发与持久化**：多实例并发时的数据合并策略、异常崩溃时的容灾要求；
- **容错与回退**：底层故障时的优雅降级方案。

## 三、 优雅质询人机工学 (Ergonomic Questioning)

优秀的质询绝不是向用户砸一份长篇调查问卷，而应遵循高信噪比的人机交互原则：
1. **严格一次一问 (One Question at a Time)**：把多个疑问按拓扑依赖排序，优先提出最关键的阻塞性问题；
2. **给出具象选项并推荐首选**：选项控制在 2~3 个，使用 `(Recommended)` 标明推荐方案，并用一句话说明权衡动因；
3. **闭环转交**：一旦关键边界收敛，立即停止质询，产出决策备忘并转交 `spec-driven-development` 或派发对应 SubAgent。
