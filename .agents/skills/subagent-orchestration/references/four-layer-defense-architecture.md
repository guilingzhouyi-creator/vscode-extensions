# 四重防线立体防御机制 (Four-Layer Defense Architecture)

> **规范地位**：本文件为 `subagent-orchestration` 技能的深水区架构参考指南，详细定义多智能体在工作区执行任务时的立体防御边界。

---

## 一、 防线分层模型

在工作区中，对 SubAgent 的约束绝非散落的单次提示词，而是层层递进的四重物理与逻辑防御体系：

```text
┌────────────────────────────────────────────────────────┐
│ 防线 1: Agy 平台级工具权限物理剥夺 (Physical Tool Jail)   │
│ • review / explore 姿态：enable_write_tools = false     │
│ • 物理层面阻断文件创建、修改与终端执行，杜绝误操作污染     │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 防线 2: 领域原型 Path Jail 路径沙箱 (Zero-Intersection)  │
│ • allowedPrefixes: 独占授权文件或目录列表                │
│ • forbiddenPrefixes: 全局硬禁区，越界操作立即一票否决    │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 防线 3: 5 层系统契约自动注入 (Layer 0~4 System Contract)│
│ • Layer 0: 工作区全局刚性公理 (AGENTS.md)              │
│ • Layer 1: 物理路径沙箱约束与关联技能                   │
│ • Layer 2: 领域刚性公理与技术栈规范                     │
│ • Layer 3: 作业姿态与行为限定                           │
│ • Layer 4: 本地门禁自检契约 (姿态感知差异化)            │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│ 防线 4: 主 Agent 8 步交叉复审闭环 (Cross-Review Loop)   │
│ • 独立沙箱审计、静态编译、体积复杂度、单源规则防虚构    │
│ • 领域专属守卫、单调棘轮防反弹、全量回归、五大支柱审计  │
└────────────────────────────────────────────────────────┘
```

---

## 二、 姿态与工具权限矩阵

| 作业姿态 | 核心职责 | `enable_write_tools` | `enable_mcp_tools` | `enable_subagent_tools` |
| :--- | :--- | :---: | :---: | :---: |
| **`construct`** | 特性开发、增量编码 | `true` | `false` | `false` |
| **`review`** | 静态审查、规则断言 | `false` | `false` | `false` |
| **`refactor`** | 结构消融、复杂度平铺 | `true` | `false` | `false` |
| **`explore`** | 依赖拓扑、调用链调查 | `false` | `false` | `false` |
| **`guardian`** | 质量裁决、门禁巡检 | `true` | `false` | `false` |

---

## 三、 同构模型继承公理

所有通过 `subagent-orchestration` 装配的 SubAgent 均必须指定 `Model: "inherit"`，保持与主会话（Gemini 3.8 Flash，高思考强度 effort=High）同构一致：
1. 完整保留主会话的高强度深度推理能力；
2. 锁定 Flash 算力成本，杜绝随意切换未受控高开销模型；
3. 保证各专员对复杂架构契约与多层逻辑的理解深度一致。
