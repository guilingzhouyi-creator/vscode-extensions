# constraint-driven-development — 通用约束驱动开发规范

本技能确立了在软件开发生命周期中，将质量标准与资源预算建立为**先验刚性契约**的通用工程机制。规格说明（Spec）定义“做什么”，测试驱动（TDD）证明“逻辑正确”，而约束驱动开发（CDD）则在编写代码前确立**“何为合格的工程交付”**。

在自主研发与 Agent 辅助编码中，Agent 极易为了“让测试变绿”而悄悄放宽质量门槛（如添加忽略标记、降低覆盖率要求、跳过耗时断言或编写空桩函数）。约束驱动开发通过硬性数字与底线守卫彻底杜绝此类质量妥协。

---

## 一、 质量契约的四大物理支柱

所有质量约束必须量化为可由脚本离线机械检验的硬性指标，严禁主观叙述：

1. **结构与复杂度预算**：
   - 单函数圈复杂度（CC）、嵌套深度（Depth）、单行噪声比（Noise）；
   - 单文件有效代码行（ELOC）与物理行（LOC）双轨上限；
2. **内存与运行时预算**：
   - 关键循环体内瞬态堆分配为 0；
   - 高频对象池与不可变结构强制复用；
3. **测试防线完整性预算**：
   - 测试断言覆盖率棘轮（Ratchet）：只许提升或持平，严禁下跌；
   - 零孤儿用例、零被跳过用例（跳过标记清零）；
4. **架构契约与卫生预算**：
   - 零 0 字节物理空文件、统一换行符契约（LF/CRLF）；
   - 门面层实质承载行数与不可变冻结保障；
   - 消除单行透传跳板。

---

## 二、 底线守卫机制 (The Floor Guard)

底线守卫是运行在本地暂存区与 CI 流水线中的防逆流守卫，针对 Diff 变更严密盯防以下**五大逆流退化行为**，一旦检测到立即一票否决：

```text
┌────────────────────────────────────────────────────────┐
│             底线守卫 (The Floor Guard)                 │
├────────────────────────────────────────────────────────┤
│ 1. 阈值私自下调  ──▶ 试图修改配置文件放宽门槛 (阻断)   │
│ 2. 抑制检查消音  ──▶ 新增类型或代码检查消音标记 (阻断) │
│ 3. 测试断言弱化  ──▶ 删除测试、标记跳过或删除断言 (阻断)│
│ 4. 虚假半成品    ──▶ 遗留未决 TODO、空 catch 或空桩 (阻断)│
│ 5. 规则目录漂移  ──▶ 虚构未经单源登记的规则代码 (阻断) │
└────────────────────────────────────────────────────────┘
```

1. **严禁悄悄下调阈值**：禁止在提交中修改工具配置文件以掩盖指标超标；
2. **严禁消音检查**：严禁通过内联注释强行消除类型报错或静态检查；
3. **严禁弱化测试**：严禁删除已有测试文件、禁止添加跳过标记、严禁为通过测试而删除既有用例中的断言；
4. **严禁假实现空桩**：严禁提交空函数实现、占位符抛错或空的异常吞没块；
5. **严禁规则漂移**：检查器引用的规则代码必须在单源目录中严格登记，禁止临时自造。

## 三、 棘轮效应治理 (The Ratchet Principle)

质量标准遵循**单向单调不减（Ratchet Mechanism）**：
- 当项目当前覆盖率为 85% 时，该数值即成为新的刚性底线；后续任何提交若导致覆盖率降至 84.9%，必须被门禁无条件拦截；
- 允许在重构时提高门槛，但严禁以“先上线再补”为由向下突破底线。
