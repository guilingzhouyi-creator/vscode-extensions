## 1. 概念正名：为何称为“分形（Fractal）”？

在软件工程中，传统的组织架构多表现为**异构写死的层级树（Hierarchical Tree）**：高层、中层与底层节点的行为契约与数据结构迥然不同，缺乏递归通用性。

而在分形 Git 中，版本控制体系遵循数学意义上的**分形公理（Fractal Axioms）**：

$$\text{FractalNode} = \langle \text{BaselineRef}, \text{PreReviewZone}, \text{GateVerifier}, \text{SpawnChildren}, \text{ReclaimRule} \rangle$$

### 1.1 自相似性（Self-Similarity）
无论是系统级主干、部门级集成分支、任务卡工作树，还是最底层的子智能体探索分支，**每个节点运转着完全同一套状态转移与门禁裁决状态机**：
1. **相对性原理**：
   - 父级 Agent 私有工作树相对于它的 SubAgent 而言，是权威的**“集成主树”**；
   - 但同一个父级工作树相对于其所在的 Cell 而言，它自身又是一个**“子分支”**；
   - Cell 集成主树相对于内部所有 Agent 而言是**“主干”**，但相对于系统全局 Trunk 而言它又是一个**“子分支”**。
2. **尺度缩放与无限递归**：
   当 SubAgent 面临复杂推演时，若需继续派发 Sub-SubAgent（微观变体探针打擂），整套分形拓扑、预审区检验与物化回收规则**无须任何特殊分支代码，天然支持向下无限递归展开与向上收敛**。

### 1.2 时间尺度分形（Temporal Fractal）
分形不仅体现在空间命名空间（`refs/fractal/...`）的拓扑嵌套上，更体现在**生命周期的自相似收缩**上：
- **微观叶子节点（SubAgent）**：秒级/分钟级生存，完成打擂即被物理销毁；
- **任务中层节点（Card Worktree）**：小时级生存，绑定单张任务卡生命周期，通过 L2 门禁合入后物理卸载；
- **部门集成节点（Cell Main）**：迭代周期级生存，作为部门常驻或半常驻汇聚点；
- **全局根干节点（System Trunk）**：全生命周期永驻，系统绝对真源（SSOT）。

## 2. 核心拓扑隔离律：父级工作树 $\neq$ 部门集成主树

在多智能体协同实践中，最常犯的严重错误是将“父级工作树”与“部门集成主树”混为一谈，导致并发踩踏与越权合入。分形 Git 在数据结构与引用层确立了**绝对物理隔离铁律**：

```
┌────────────────────────────────────────────────────────────────────────┐
│   [人类第 2 道关卡·战略发布] 全局系统主树 (System Trunk / Main)        │
└───────────────────────────────────▲────────────────────────────────────┘
                                    │ (全量顶级门禁 + L3A/总架构师终审)
┌───────────────────────────────────┴────────────────────────────────────┐
│   [人类第 1 道关卡·战术集成] 部门集成主树 (Cell Integration Main)      │
└───────────────▲───────────────────────────────────────▲────────────────┘
                │ (L2 单元门禁 + 交叉审查)                │ (L2 单元门禁 + 交叉审查)
┌───────────────┴──────────────────────┐ ┌──────────────┴──────────────────────┐
│  父级 Agent-A 私有工作树 (Card-101)  │ │  平权 Agent-B 私有工作树 (Card-102)  │
└──────────────────▲───────────────────┘ └──────────────────▲───────────────────┘
                   │ (L1 局部门禁 + 父验审)                  │ (L1 局部门禁 + 父验审)
┌──────────────────┴───────────────────┐ ┌──────────────────┴───────────────────┐
│     SubAgent-A1 临时探索工作树       │ │     SubAgent-B1 临时探索工作树       │
└──────────────────────────────────────┘ └──────────────────────────────────────┘
```

### 2.1 拓扑合法性状态转移断言
在 [`src/fractal/topology.rs`](file:///c:/CODE_game-development/vscode-extensions/fractal-git/src/fractal/topology.rs) 中，以下规则作为内核级的刚性断言执行：

1. **SubAgent 归属单向封闭律**：
   $$\text{TargetRef}(SubAgent) \equiv refs/fractal/cell/\langle cellId\rangle/card/\langle parentCardId\rangle$$
   SubAgent 是父级 Agent 派发的临时触手，其变更**绝对禁止跨越父级私有工作树直接合入 Cell Main，更严禁直推 Trunk**。违者直接抛出 `FractalError::TopologyBreach` 熔断拦截。
2. **平权 Agent 私有互斥律**：
   同一 Cell 内部的平权 Agent（如 Agent-A 与 Agent-B）各自持有独立的 Card 工作树，互不可写对方的私有分支。
3. **汇入集成主树之充分必要条件**：
   父级 Agent 必须在自身私有工作树内消化、吸收并验证完所属 SubAgent 的全部产出，闭环本卡功能后，方可向 `Cell Main` 发起合入申请，接受同级其他平权 Agent 的交叉审查与 L2 拓扑门禁。

## 3. 一体两面双载荷贯穿始终

同一个版本变更在智能体与人类工程师之间存在天然的认知屏障。分形 Git 在 Git Commit 与 Diff 层全面践行**一体两面双载荷机制**：

```
                    ┌───────────────────────────────┐
                    │  一体两面双载荷分形 Git 体系   │
                    └──────────────┬────────────────┘
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         ▼                                                   ▼
┌─────────────────────────────────┐ ┌─────────────────────────────────┐
│     机器面 (Agent Face)         │ │     人类面 (Human Face)         │
│  - 纯内存无锁 Tree 结构          │ │  - 100% 兼容原生 Git 对象格式   │
│  - 精确到 AST 符号坐标的指令     │ │  - VS Code UI 双语诊断卡片    │
│  - LayerVFS CAS 块哈希指纹      │ │  - git log 可读的清晰拓扑图谱 │
│  - 纳秒级序列化，零多余排版      │ │  - 语义化高对比度状态徽章     │
└─────────────────────────────────┘ └─────────────────────────────────┘
```

### 3.1 提交载荷的一体两面
每个由系统自动生成的 Git Commit 对象，正文均包含两层结构：
- **人类可读层（Human Readability）**：
  标准的中文祈使句摘要标题，包含 `[Project: fractal-git]`、`[Why]`、`[Changed]`、`[Verification]`，与原生 Git 工具链（`git log`、VS Code GitLens）完全无缝融合；
- **机器元数据层（Machine Metadata）**：
  在 Commit 正文尾部附带结构化的 `Praxis-Agent-Meta` 标记：
  ```json
  Praxis-Agent-Meta: {"card_id":"card-101","cell_id":"cell-alpha","agent_uid":"agent-42","quality_score":100.0,"gate_status":"approved","timestamp_ms":1700000000000}
  ```
  供其他协同 Agent、回滚引擎和全息审计账本以 $O(1)$ 时间复杂度极速反序列化。

## 4. 人类管理的两道核心战略关卡

分形 Git 的设计哲学是：**微观彻底自治，宏观绝对掌控**。

1. **底层机器面（微观放手）**：
   在 SubAgent $\to$ Parent Card Worktree 阶段，属于每秒发生的高频微观算法打擂，由 Auto 门禁与系统内核全自动流转、自动物化提交、自动物理回收，**无需人类在微观细节上耗费任何精力**；
2. **人类第一道关卡（战术级·领域把关）——部门集成主树**：
   由 Cell 领域负责人掌舵，通过一体两面的人类卡片审阅部门内各任务卡的整合效果，防范领域逻辑冲突与重复造轮子；
3. **人类第二道关卡（战略级·发布准入）——全局系统主树**：
   由系统总架构师与 L3A 决策中枢掌舵，审阅全系统跨部门拓扑波及图与复合质量门禁最终大盘，批准后方可合入 Trunk，确保生产主干永驻健康。
