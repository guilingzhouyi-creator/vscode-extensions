⚙️ Storage

Crash Protection ?每 10 秒将时间片写入 .journal 文件；
VS Code 崩溃后重启时可回放恢复，
最多丢失约 10 秒数据
启用 journal 文件防止崩溃数据丢失
JSON Backup ?额外写入 .vscode/workspace-timing.json；
用户可见、可版本控制、可移植
额外写入 .vscode/workspace-timing.json
RingBuffer Capacity ?内存中缓存的时间片数量；
越大则 UI 可查询的历史越久，
但占用内存越多（推荐 1024 ≈ 17 分钟）
环形缓冲区条目数 (64~65536)
Journal Flush Interval ?内存缓存写入 journal 文件的频率；
间隔越短丢失越少，但磁盘写入越频繁
ms (1000~300000)
Full Save Interval ?将完整计时数据写入 workspaceState 和 JSON 文件的频率；
间隔越短数据越安全，但写入越频繁
ms (5000~600000)
Max Sessions ?最多保留的会话记录条数；
超出时自动删除最旧记录；
设为 0 表示不限（注意内存占用）
0 = unlimited
Efficiency Tracking ?监听编辑活动，计算实际打字时间 ÷ 计时器时长 = 工作效率；
仅在本地统计，不上传任何数据
启用编辑活跃度追踪（效率转化图表）
Daily Goal ?设定每日工作时长目标，达成后桌面通知提醒；
设为 0 关闭目标提醒
minutes (0 = disabled)

🔧 Actions

New Period：累计归零，历史保留在会话记录中
Reset All：清空所有计时数据和历史，不可撤销
