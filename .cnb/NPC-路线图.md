## 1. 维护规则（摘要）

1. 状态取值（意图）：进行中 / 冲突中·等待答复 / 待合入 / 已合入
2. 状态取值（任务）：待领 → 进行中 → 完成·待交接 → 已交接（严格顺序，不可跳变）；卡阻·已上报 为异常态
3. 每个 NPC 只更新**自己领取的 TODO 表**，不擅动他者表
4. 路线图与 Issue 评论必须同步（双写防漂移）
5. 每步完成即更新，不得攒到收尾一次性补写
6. 依赖图中出现**依赖环**（A→B→A）即违规：发现者立即上报并冻结相关任务

## 2. 分层结构（树状分叉 + 拓扑依赖）

```
总体路线图（意图 <ID>）
├── 大点 M1（路线图中的一个"大点"）
│   ├── TODO 表 TB-M1-B · 协作员·构建  ← 每个大点可拆出多个 TODO 表
│   │   ├── 任务 T1-B1（依赖：-）
│   │   ├── 任务 T1-B2（依赖：T1-B1）
│   │   └── 任务 T1-B3（依赖：T1-B2 + T1-T1 ← 跨表依赖，见依赖拓扑）
│   ├── TODO 表 TB-M1-T · 协作员·测试
│   │   ├── 任务 T1-T1（依赖：T1-B2）
│   │   └── 任务 T1-T2（依赖：T1-T1）
│   └── TODO 表 TB-M1-R · 协作员·审查（收尾把关）
│       └── 任务 T1-R1（依赖：T1-B3 + T1-T2）
├── 大点 M2
│   ├── TODO 表 TB-M2-T · 协作员·测试（与 M1 并行）
│   └── TODO 表 TB-M2-B · 协作员·构建
└── 依赖拓扑（DAG）：跨表依赖 + 关键路径 + 并行支线
```

**树的分叉**：一个大点 → 多个 TODO 表；一个 TODO 表 → 多个任务。分叉处天然并行。
**环的分叉**：
- **依赖环（禁止）**：任务依赖形成环 → 检测即冻结 + 上报（见 2 规则 6）
- **协作环（允许）**：流水线接力环（构建→测试→审查→合入）与两圈交叉审查，属正常协作循环
- **回并**：TODO 表内任务全完成后，该表标记「完成·待回并」，大点聚齐全部子表后标记「完成」
