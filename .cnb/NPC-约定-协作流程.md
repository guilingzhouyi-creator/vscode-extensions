# NPC 约定 · 分册二：协作流程

> 由 `.cnb/NPC-约定索引.md`（引导式命令规范 + 铁律 + 指针地图）索引。被触发后执行任务、交叉审查、冲突处理时加载本分册。
> 所有命令遵循索引第 0 章「引导式命令规范」：`[ ]` 打勾、`<占位符>` 填空、`→ 通过标准` 判定。
> 与索引铁律冲突时，以索引为准。
> **读取范围**：必读区 §2 工作流程 + §3 交叉审查；选读区 §1 触发 / §4 两圈 / §5 冲突 / §6 输出（需要时）。禁止通读全文。

---

## 1. 触发

仓库管理员在 Issue 描述或评论中 `@` 提及对应 NPC 并下发意图，即触发该 NPC 执行。

---

## 2. 工作流程（每个协作 NPC 接到意图后 · 打勾检查单）

```
☐ [ ] 步骤 1：阅读约定索引（铁律）与当前路线图 → 通过标准：可复述 <本轮意图> 与 <铁律要点>
☐ [ ] 步骤 2：cd workspace-timing && npm install → 通过标准：exit 0
☐ [ ] 步骤 3：按并行拓扑分册第 1 章完成分工，以主责切入 → 通过标准：评论已声明【承接领域 + 计划产出】
☐ [ ] 步骤 4：完成任务域工作（构建：编译产物 / 测试：用例+Lint / 审查：Diff 分析）
          → 通过标准：产物存在且可验证
☐ [ ] 步骤 5：动用其余两种职能自查（按门禁治理分册第 1 章门禁顺序）
          → 通过标准：install → compile → lint → diff 全绿
☐ [ ] 步骤 6：按门禁治理分册第 7 章即时更新路线图 → 通过标准：版本号+1、变更日志追加
☐ [ ] 步骤 7：按索引「完成即唤醒」协议 @ 下一个平权 NPC → 通过标准：评论含【唤醒】@<NPC>
☐ [ ] 步骤 8：按第 6 节输出格式报告 → 通过标准：含 职责/结果/改动/审查/唤醒 五要素
```

**规则**：全部 `[x]` 才算完成；任何一步未过标准 → 停止并报告，不得跳到下一步。

---

## 3. 交叉审查与定点 Diff 改造

**交叉审查顺序（按序，不得跳序）：**

| 执行者 | 审查对象 |
|--------|---------|
| 协作员·构建 | 协作员·测试 的改动 |
| 协作员·测试 | 协作员·构建 的改动 |
| 协作员·审查 | 协作员·构建 + 协作员·测试 的改动（收尾把关） |

**交叉审查检查单：**

```
☐ [ ] 步骤 1：git diff 审查 <他者改动> → 通过标准：列出 <文件清单 + 问题清单>
☐ [ ] 步骤 2：判断缺陷类型 → 通过标准：L1 缺陷级 / L2 方案级（见门禁治理分册第 4 章）
☐ [ ] 步骤 3：L1 → 定点修复（补丁级最小改动）→ 通过标准：未重写他者主责逻辑
☐ [ ] 步骤 4：L2 → 按冲突上报（第 5 节）→ 通过标准：评论含【冲突方/冲突点/建议方案】
☐ [ ] 步骤 5：修复后重跑门禁（compile → lint → diff）→ 通过标准：全绿
☐ [ ] 步骤 6：主动 @ 下一个应审查者 → 通过标准：评论含【唤醒】@<NPC>
```

**定点 Diff 改造规则（约束）：**

1. 仅修复**他者引入**的缺陷（补丁级最小改动）。
2. 不重写他者主责逻辑、不改变其实现意图。
3. 修复后必须重新通过门禁，并说明修复原因。

## 4. 两圈机制

**两圈收敛检查单：**

```
☐ [ ] 第一圈：按第 3 节顺序各交叉审查一轮，修复发现的问题 → 通过标准：问题清单已清零
☐ [ ] 第二圈：按同一顺序再收敛一轮 → 通过标准：无新增问题
☐ [ ] 两圈后强制终止，输出最终结论 → 通过标准：评论含【最终结论】
☐ [ ] @ 规划者声明「两圈收敛完成，待合入」→ 通过标准：评论含【唤醒】@路线图规划者
```

**规则**：
- 两圈后**强制终止**，不无限循环。
- 若第二圈仍无法收敛（双方反复互相引入问题）→ 触发第 5 节冲突上报。

---

## 5. 冲突上报协议（重大问题反馈）

**触发条件**：改动互相矛盾、无法自行收敛、他者改动影响自己主责领域且无法定点化解，或发生构建方案分歧。

**上报命令（占位格式，冲突方可不只一个）：**

```
【冲突上报】
【冲突方】<NPC1> 与 <NPC2>
【冲突点】<文件路径 / 行号 / 矛盾原因>
【建议方案】<候选解决方向>
【状态】<等待提出者回答>
```

**规则（打勾检查单）：**

```
☐ [ ] 上报后立即停止改动 → 通过标准：相关文件冻结
☐ [ ] 收到答复后按答复继续 → 通过标准：评论引用 <提出者答复>
☐ [ ] 未获答复前不强行覆盖 → 通过标准：他者改动未被修改
☐ [ ] 更新路线图状态为「冲突中·等待答复」→ 通过标准：状态字段已改
```

---

## 6. 输出格式（命令回显）

每次完成任务后，评论须**逐项回显**（遵循索引 0.4）：

```
【执行清单】
☐ [x] 本轮职责：<主责领域 + 实际动用职能>
☐ [x] 执行结果：<install/compile/lint/diff 结果>
☐ [x] 改动清单：<文件与改动摘要>
☐ [x] 交叉审查结论：<审查了谁的改动 / 修复了什么>
☐ [x] 唤醒/交接：<@了谁 / 交接了什么>
☐ [x] 冲突/遗留：<有则按第 5 节上报 / 无则填"无">
```

**未回显视为未执行**；同侪可要求补正（完成即唤醒协议）。
