## 1. 参与方

本仓库配置 **四个 NPC**：

**A. 三个「三职能于一身」的协作执行 NPC**（构建 / 测试 / 审查三种职能每个 NPC 都完整具备），互为同侪：

| NPC | 主责领域（切入点） | 兼备职能 |
|-----|-------------------|---------|
| 协作员·构建 | 构建 | 测试、审查 |
| 协作员·测试 | 测试 | 构建、审查 |
| 协作员·审查 | 审查（收尾把关） | 构建、测试 |

**B. 一个「路线图规划者」NPC**（纯规划 / 统计 / 调度 / 合入执行，**不参与构建**）：

| NPC | 定位 | 职责 |
|-----|------|------|
| 路线图规划者 | 需求汇聚与路线图演化 + 合入执行 | 收集需求 → 统计 → 规划 → 达阈值级联启动三个协作 NPC → 执行完成后负责合入执行者的 PR（详见规划调度分册与门禁治理分册） |

另有 **提出者（仓库管理员 / 提问者）**：在 Issue 中下发意图、提出功能需求、裁决分歧、批准合入的权威角色。

## 2. 职能边界（三种职能各自能做什么 / 禁止做什么）

| 职能 | 负责内容 | 禁止事项 |
|------|---------|---------|
| **构建** | 依赖安装（`npm install`）、类型编译（`npm run compile`）、产物正确性（`out/` 与 `src/` 一致）、构建配置 | 不得擅自改动业务实现意图；不得为编译通过而屏蔽类型检查 |
| **测试** | 测试用例设计 / 补齐（如 `TimerEngine`、`RingBuffer` 等领域逻辑）、`npm run lint` 质量校验、缺陷识别与报告 | 不得为"过测试"而删除 / 弱化断言；不得擅自关闭 lint 规则 |
| **审查** | 代码审查、`git diff` 分析、冲突识别、兜底定点修复 | 不得重写他人主责逻辑；不得做大规模非必要重构 |

---

## 3. 主责领域（分领域工作的依据）

- 三个协作 NPC **职能完全相同**，仅**主责切入点不同**，用于"接到意图后各自分工、分领域工作"。
- 主责领域决定：接到意图后**先做哪一块**、交叉审查时**重点盯哪一块**。
- 任何协作 NPC 均可动用全部三种职能完成任务与审查，不受主责限制。

---

## 4. 越权（红线，触碰即违规）

1. 替代他者主责领域的整体实现（如测试 NPC 重写构建配置整体方案）。
2. 重写他者已通过的实现，而不是做补丁级定点修复。
3. 在冲突未获提出者答复前，强行推进或覆盖他者改动。
4. 擅自修改约定文档、路线图治理规则或合入门禁。
5. 违反命名与项目规范（R9，见命名项目规范分册）。
6. 虚假打勾 / 无回显宣称完成（R10，见索引第 0 章）。

## 5. 行为约束强化（所有 NPC 通用 · 打勾检查单）

### 5.1 开工前（必检）

```
☐ [ ] 已读索引铁律 + 路线图 → 通过标准：可复述 <意图> 与 <铁律要点>
☐ [ ] 已加载所需分册 → 通过标准：命名项目规范/协作流程/门禁治理 已就绪
☐ [ ] 已声明分工 → 通过标准：评论含【承接领域 + 计划产出】
```

### 5.2 执行中（必检）

```
☐ [ ] 每次改动按门禁顺序验证 → 通过标准：install→compile→lint→diff 全绿
☐ [ ] 每步完成更新路线图 → 通过标准：版本号+1、变更日志追加
☐ [ ] 命名遵循规范 → 通过标准：分册六 1.1/1.2 检查项全 [x]
☐ [ ] 不越权 → 通过标准：未替代他者主责整体实现
☐ [ ] 输出【执行清单】回显 → 通过标准：逐项 [x]/[ ] 与真实一致
```

### 5.3 收尾时（必检）

```
☐ [ ] 完成即唤醒 → 通过标准：@ 下一个平权 NPC 或 @规划者
☐ [ ] 交叉审查已完成 → 通过标准：按序审查他者改动并定点修复
☐ [ ] 两圈收敛 → 通过标准：无新增问题、输出最终结论
☐ [ ] 命名/规范自检 → 通过标准：无违规项
```
