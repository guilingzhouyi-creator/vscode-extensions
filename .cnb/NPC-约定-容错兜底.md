## 1. 竞态仲裁（领取/更新顺序 · 补并行拓扑 2.3 / 3.6）

### 1.1 领取顺序仲裁（无依赖任务同时可领时）

```
☐ [ ] 同一大点下多个无依赖 TODO 表 → 按 构建→测试→审查 固定顺序优先领取
      → 通过标准：构建先领，测试次之，审查最后
☐ [ ] 同轮次禁止重复领取同一表 → 通过标准：任务矩阵「负责」列无重复 NPC
☐ [ ] 同时声明（并发）→ 以路线图更新锁 + 时间戳裁决 → 通过标准：先占锁者先得
```

**规则**：竞态裁决不改变主责归属，只解决"谁先动"；被仲裁让出的 NPC 等待下一轮认领。

### 1.2 更新竞态（两人同时写路线图）

```
☐ [ ] 写前必须占更新锁（7.3 硬约束 2）→ 通过标准：锁字段 = 自己
☐ [ ] 锁冲突（他人持有）→ 等待释放，不覆盖 → 通过标准：他者写毕后再写
☐ [ ] 锁超 15 分钟 → 可接管 + 变更日志记录 → 通过标准：接管记录
```

## 2. 回滚协议（撤销错误改动 · 防"改错了没法退"）

### 2.1 触发条件

```
☐ [ ] 定点修复引入新问题 → 回滚本次修复
☐ [ ] 自动裁决（4.6）被管理员推翻 → 回滚自动裁决的改动
☐ [ ] 某提交破坏了门禁 → 回滚到最近绿点
☐ [ ] 他者要求回滚且有依据 → 走 2.2 流程
```

### 2.2 回滚流程（打勾检查单）

```
☐ [ ] ① 发起：评论发【回滚】<目标版本/提交> + <原因> → 通过标准：含依据
☐ [ ] ② 定位：从变更日志找目标版本 → 通过标准：版本号/提交号明确
☐ [ ] ③ 裁决：L1 低风险（可定点逆转）→ 发起者直接回滚；
          L2 高风险（大范围/影响他者）→ 平权表决或管理员批准 → 通过标准：裁决记录
☐ [ ] ④ 执行：git revert 到目标版本 → 通过标准：不丢失无关改动
☐ [ ] ⑤ 验证：回滚后重跑门禁 → 通过标准：compile→lint→diff 全绿
☐ [ ] ⑥ 留痕：更新路线图 + 变更日志 → 通过标准：版本号+1
```

**规则**：
- 回滚只针对**错误引入的改动**，不牵连无关变更（用 `git revert` 而非 `reset`）。
- 回滚后相关任务状态重置为「待领」，重新进入领取。

## 3. 超时兜底（无人响应 / 卡死 · 防流程停摆）

### 3.1 超时阈值矩阵

| 环节 | 等待对象 | 默认超时 | 超时处理 |
|------|---------|---------|---------|
| 缺席裁决 | 管理员 | 24h | 按 4.6 风险分级自动裁决 |
| 执行体响应 | 被唤醒的执行体 | 4h | 升级：审查员介入 → 规划者介入 → 标注「卡阻·已上报」 |
| 交接验收 | 下游执行体 | 4h | 通知上游 + 规划者协调 |
| 交叉审查接力 | 下一审查者 | 4h | 跳过序位（构建→测试→审查 中缺失者由审查员补位） |
| 心跳停滞 | 领取者 | 3 步 | 按并行拓扑 10.7 让表机制 |
| 文档巡检 | 规划者 | 收官时 | 由审查员代行 DRI 巡检 |

### 3.2 超时升级链（逐级上移，不无限等待）

```
执行体 → 审查员（协调）→ 规划者（调度）→ 管理员（裁决）
```

```
☐ [ ] 超时发生时先 @ 提醒 → 通过标准：评论含【超时提醒】@<对象>
☐ [ ] 提醒后 1 心跳仍未响应 → 升级上一级 → 通过标准：升级记录
☐ [ ] 升级到顶（管理员也超时）→ 按 4.6 缺席裁决 → 通过标准：风险分级
```

## 4. 幂等保护（重复触发 / 重复执行 · 防重复劳动）

### 4.1 触发即查重（开工前）

```
☐ [ ] 开工前查路线图是否已有同任务 → 通过标准：按 意图#ID + 大点 + 任务ID 匹配
☐ [ ] 已存在且未完成 → 更新进度继续，不新建 → 通过标准：无重复任务条目
☐ [ ] 已存在且已完成 → 报告状态，不重做 → 通过标准：评论含【已完成，状态：<...>】
```

### 4.2 事件幂等

```
☐ [ ] 同一评论多次 @ / 事件重复触发 → 只执行一次 → 通过标准：以路线图任务状态为准
☐ [ ] 重复收到同一唤醒 → 比对进度，已完成的直接确认 → 通过标准：不重复建 PR/修复
☐ [ ] 对同一需求重复收集 → 需求池去重（规划调度分册 3.2）→ 通过标准：R#ID 唯一
```

**规则**：**路线图是唯一事实源**——任何触发都以路线图任务状态判断是否需要执行，避免重复。

## 5. 资源纪律（Token / 上下文节制 · 免费也要省）

### 5.1 加载纪律

```
☐ [ ] 指针式加载：只读所需分册 → 通过标准：不一次通读全部文档
☐ [ ] 单轮内避免重复读同一文档 → 通过标准：缓存已读内容到本轮记忆
☐ [ ] 输出精简：【执行清单】只回显关键项 → 通过标准：不粘贴大段原文
```

### 5.2 调用纪律

```
☐ [ ] 无意义轮询禁止 → 通过标准：不在无变化时重复触发
☐ [ ] 批量操作合并 → 通过标准：同主题评论合并，不逐条刷屏
☐ [ ] 空闲即停 → 通过标准：无任务时不主动循环触发
```

### 5.3 效率优先

```
☐ [ ] 大意图优先批量处理（第 9 章平权并行）→ 通过标准：少轮次、高并行
☐ [ ] 交接物一次给全（契约+产物）→ 通过标准：下游不需二次索取
```

## 6. 审计追踪（出了问题查得清 · 可追溯）

### 6.1 审计记录要求

```
☐ [ ] 每轮意图结束生成审计摘要 → 通过标准：写入路线图「审计区」
☐ [ ] 审计摘要含决策时间线 → 通过标准：唤醒/领取/修复/裁决/合入 各决策点
☐ [ ] 所有决策留痕 → 通过标准：评论 + 变更日志 + 路线图 三处一致
```

### 6.2 审计摘要格式（路线图追加）

```
#### 审计摘要 · 意图 <ID>
| 时间 | 决策 | 发起者 | 结果 |
|------|------|--------|------|
| <时间> | 唤醒 @构建 | 规划者 | 已响应 |
| <时间> | 领取 TB-M1-B | 构建 | 完成 |
| <时间> | 缺席裁决 L2低 | 规划者 | 自动裁决·可回滚 |
| <时间> | 合入 PR | 规划者 | 已合入 |
```

### 6.3 审计查询

- 管理员可随时从路线图审计区回看任意一轮决策链。
- NPC 间争议 → 以审计区记录为事实依据仲裁。
